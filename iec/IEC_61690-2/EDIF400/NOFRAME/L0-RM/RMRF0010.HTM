instanceWidth

instanceWidth ::= '(' 'instanceWidth'
	integerToken
	')'

Used by:

<instance

Similar Keywords:

instanceWidthDisplay width

Constraints:

1. The following constraint applies to this context: All contexts
When instanceWidth is used the product of the instance width and the port or portBundle width divided by the width of the connecting net or bus should be equal to the instance width or one.

2. The following constraint applies to this context: All contexts
The integerToken used in instanceWidth must have a value greater than zero.

3. The following constraint applies to this context: All contexts
When a portInstanceRef is used in a schematicBusJoined or connectivityBusJoined the size of the flattened signalGroup associated with the interconnect should equal either the size of the port or flattened portBundle, or the product of this size and the instanceWidth.
(See also similar constraint in: connectivityBusJoined, schematicBusJoined)

4. This construct is illegal in this context: pcbMcmView

Description:

InstanceWidth defines the width of an instance. The default width is one.

The integerToken must be greater than zero.

Example:

(instance INST1 ...
   (instanceWidth 4) ...)

In this example, the instance INST1 has width 4.

integerToken

[ '-' | '+' ] 
digit
{ digit }

Used by:

Similar Keywords:

integer

Description:

IntegerToken is a basic EDIF token, expressed in normal decimal notation. Its absolute value must be less than 231. IntegerTokens are terminated by whiteSpace, quotation marks, a left or right parenthesis or percent character within encodedCharacter. WhiteSpace must not occur within the token nor after the optional sign.

An integerToken will typically be recognized by a lexical scanner.

Example:

0
123
-456
789
2147483647

This example illustrates five integer tokens. The last one is the maximum-allowed value for an integerToken.

interconnectAttachedText

interconnectAttachedText ::= '(' 'interconnectAttachedText'
	attachmentPoint
	{ annotate | <criticalityDisplay> | interconnectDelayDisplay | 
	<interconnectNameDisplay> | interconnectPropertyDisplay } 
	')'

Used by:

*schematicInterconnectAttributeDisplay

Description:

InterconnectAttachedText is used to attach some text to a point on the graphics of the net or bus. The text may be simple annotation or the display of a property or attribute. The attachment point must be a specified point within the graphics of the net or bus, though not necessarily at the same level in the nested hierarchy of a net, subnet, bus, subbus or bus slice.

The display positions are relative to (0, 0) and not relative to the attachment point.

Example:

(interconnectAttachedText (pt 200 300)
   (annotate "See note 3" (display ...))
   (interconnectPropertyDisplay route_width 
      (display ...)))

The annotation and the property displayed are both attached to the point (pt 200 300) in this example. The display positions are given separately and are typically different from the attachment point.

interconnectDelay

interconnectDelay ::= '(' 'interconnectDelay'
	interconnectDelayNameDef
	derivation
	delay
	{ becomes | transition } 
	')'

Used by:

*interconnectAnnotate *interconnectHeader *schematicInterconnectHeader *schematicSubInterconnectHeader

Similar Keywords:

interconnectDelayDisplay interconnectDelayNameRef

Constraints:

1. The following constraint applies to this context: All contexts
The timeDelay associated with an interconnectDelay should not be negative.

Description:

InterconnectDelay is an attribute of an interconnect which is used to specify a delay for the given set of transitions. If no transition or becomes is specified, then the default is relevant for any transition.

Such a delay is effective between any two ports connected to the interconnect, and acts in addition to any specified port delays.

Example:

(connectivityNet N1 (signalRef SIG1) 
   (interconnectHeader 
      (interconnectDelay
         delay1
         (calculated)
         (delay (e 3 1))
         (transition HS LR)))
   (connectivityNetJoined ...))

The above example specifies a calculated delay of 30 time units when a transition from HS to LR occurs on net N1.

interface

interface ::= '(' 'interface'
	interfaceUnits
	{ <designator> | interfaceJoined | mustJoin | permutable | port | portBundle 
	| timing | weakJoined } 
	')'

Used by:

!cluster

Description:

The interface defines objects which can be seen, and defines relationships which are true for all views and symbols in the cluster.

Objects include the ports themselves, and the properties and attributes defined in the interface and in the ports. Relationships define which ports of the cell are shorted together (interfaceJoined) and which ports can be interchanged (permutable).

The ports defined in the interface are referred to as master ports in this manual.

Example:

(cell CZ ...
   (cluster CZ
      (interface (interfaceUnits)
         (port A (inputPort))
         (port B (inputPort))
         (port O (outputPort))
         (designator "000")
         (interfaceJoined (portRef A) (portRef B)))
      (clusterHeader (property basic (string "XXX")))
      (connectivityView CZNet ...)
      ...))

The above example specifies the interface of the cluster named CZ of cell CZ. The objects defined include the ports A, B and O, and the designator attribute. The relationship that port A is joined to port B is also specified. The property basic belongs to the cluster.

interfaceJoined

interfaceJoined ::= '(' 'interfaceJoined'
	{ portRef } 
	')'

Used by:

*interface *mustJoin *weakJoined

Constraints:

1. The following constraint applies to this context: All contexts
A port can be referenced at most once by any interfaceJoined, mustJoin or weakJoined constructs in an interface.
(See also similar constraint in: mustJoin, weakJoined)

Description:

InterfaceJoined is used to specify that certain ports are shorted together.

InterfaceJoined may refer only to master ports, i.e. ports defined in the interface. The interfaceJoined may be nested with mustJoin and weakJoined to specify complex relationships between master ports. This relationship forms a tree structure. Within the interface a port may be referenced no more than once in interfaceJoined, mustJoin and weakJoined.

The portRef may refer to ports and not to portBundles.

InterfaceJoined has no influence on how interface ports are joined together when the cluster is instantiated. Thus, two ports that are interfaceJoined may or may not be in the same signal when the cluster is instantiated.

Example:

(interfaceJoined (portRef A) (portRef B))

The first example states that the master ports A and B are connected.

iso8859

iso8859 ::= '(' 'iso8859'
	iso8859Part
	')'

Used by:

!characterEncoding

Description:

Iso8859 is used to indicate that characters within % delimiters in strings are encoded using the ISO 8859 standard.

The ISO 8859 standard has 8 parts. Each one is a complete description of an 8-bit word, with graphical representations for the 256 codes possible. All the ISO 8859 standards are built around ANSI X3.4-1986. In other words, the ISO 8859 character sets build on the ASCII codes. In all cases, the ISO character sets define a set of characters whose most-significant bit is set, and relegate the ASCII characters to their values with the 8th, i.e. most-significant bit, set to zero.

Example:

(characterEncoding (iso8859 5))

Specifies that the codes in quoted strings represent characters in the ISO 8859-5 character set (Part 5: Latin/Cyrillic alphabet).

iso8859Part

iso8859Part ::= integerToken

Used by:

!iso8859

Constraints:

1. Numeric constraints:
Minimum value: 1 Maximum value: 8

Description:

Iso8859Part is an integer with minimum value 1 and maximum value 8. The numeric value represents the part of ISO 8859. These are listed below:

Part 1: Latin Alphabet No. 1 - Applicable to many countries

Part 2: Latin Alphabet No. 2 - Characters for Albanian, Czech, English, German, Hungarian, Polish, Rumanian, Serbocroatian, Slovak, and Slovene.

Part 3: Latin Alphabet No. 3 - Afrikaans, Catalan, Dutch, English, Esperanto, German, Italian, Maltese, Spanish, and Turkish.

Part 4: Latin Alphabet No. 4 - Danish, English, Estonian, Finnish, German, Greenlandic, Lappish, Latvian, Lithuanian, Swedish, and Norwegian.

Part 5: Latin/Cyrillic Alphabet

Part 6: Latin/Arabic Alphabet

Part 7: Latin/Greek Alphabet

Part 8: Latin/Hebrew Alphabet

isolated

isolated ::= '(' 'isolated'
	')'

Used by:

<logicValue

Description:

Isolated is an attribute of a logic value and is used to indicate the logic value which is used for isolated or undriven interconnects, i.e. those without any source. There may be only one logicValue which contains isolated in a logicDefinitions construct.

Example:

(logicDefinitions ...
   (logicValue T)
   (logicValue F)
   (logicValue Z (isolated)))

This defines a logic value Z and declares that it is the isolated value.
