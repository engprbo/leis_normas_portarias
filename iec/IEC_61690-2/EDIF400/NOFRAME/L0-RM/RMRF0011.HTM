jisx0201

jisx0201 ::= '(' 'jisx0201'
	')'

Used by:

!characterEncoding

Description:

The JIS (Japanese Industrial Standard) includes JIS X 0201, JIS X 0208 and others. Jisx0201 is used to indicate the standard JIS X 0201.

JIS X 0201 presents an 8-bit standard that encodes the normal ASCII printing characters in their normal positions, with the 8th and most-significant bit set to zero. There are two exceptions: \ (backslash) is replaced by the Yen sign, and ~ (tilde) is replaced by an overbar, much like the _ (underscore) character, but made to go at the top of the character. The part of the code with the most-significant bit set to one describes an analog of the ASCII set with 33 codes left undefined, analogs of the control characters and space of ASCII, and the Katakana characters following.

Using JIS X 201 does not preclude embedding 16-bit JIS X 0208 characters in the strings. Readers understanding JIS X 0201 characters may wish to observe the escape sequences that would embed JIS X 0208 characters in the string.

jisx0208

jisx0208 ::= '(' 'jisx0208'
	')'

Used by:

!characterEncoding

Description:

The JIS (Japanese Industrial Standard) includes JIS X 0201, JIS X 0208, and others. Jisx0208 is used to indicate the standard JIS X 0208.

JIS X 0208 is a 16-bit character set. Within it, are defined a set of graphics characters, mathematical-notation characters, the Latin character set capitalized and small, the numbers 0-8, a Katakana set, a Hiragana set, a (big) Kanji set with Greek (upper and lower case), and Cyrillic (upper and lower case).

joinedAsSignal

joinedAsSignal ::= '(' 'joinedAsSignal'
	')'

Used by:

!connectivityNetJoined !schematicNetJoined

Similar Keywords:

signal signalJoined

Description:

JoinedAsSignal is used as a shorthand in schematicNetJoined or connectivityNetJoined to indicate that exactly the same set of ports are referenced as in the corresponding signal.

Example:

(schematicNet A (signalRef SIGA)
   (schematicInterconnectHeader ...)
   (schematicNetJoined
      (joinedAsSignal)
      ...)
   ...)

In this example, schematicNet A joins exactly the same ports as signal SIGA.

Used by:

Similar Keywords:

k1KeywordNameRef

Description:

A k1KeywordNameDef must be a simple identifier and must not have been previously defined as a keyword name. It must not match any native EDIF keywords of the same edifVersion.

The scope of a defined keyword is from the end of the enclosing k1KeywordAlias, k2KeywordDefine or k3KeywordDefine to the end of the entire edif construct.

k2Actual

k2Actual ::= '(' 'k2Actual'
	k2FormalNameRef
	')'

Used by:

*k2Build *k2Generate !k2Optional *k3Build *k3ForEach *k3Generate

Description:

K2Actual generates the actual token or form that corresponds in position within the use of the keyword being defined, to the formal parameter definition within the k2KeywordDefine or k3KeywordDefine form. If the k2Formal parameter is bound to several forms, the k2Actual expands to several forms, unless it is used within a k3ForEach statement which references the same formal parameter.

Example:

 (k2KeywordDefine EG
    (k2KeywordParameters
       (k2Formal layer (k2Required))
       ...)
    (k2Generate
       (k2Build figure
          (k2Actual layer)
          ...) ) )

k2Build

k2Build ::= '(' 'k2Build'
	k1KeywordNameRef
	{ comment | k2Actual | k2Build | k2Literal } 
	')'

Used by:

*k2Build *k2Generate !k2Optional *k3Generate

Description:

K2Build is used within the context of a k2KeywordDefine to generate non- primitive output. It contains a k1KeywordNameRef, which is the name of an existing or previously-defined keyword. K2Build expands into a form with k1KeywordNameRef as its keyword, and each component of the k2Build replaced by the result of generating the enclosed constructs in the order specified. The enclosed comments generate nothing, but provide documentation about the purpose or use of the new keyword definition.

K2Build may nest to create nested output forms.

Example:

(k2KeywordDefine REV
   (k2KeywordParameters
      (k2Formal A (k2Required)) 
      (k2Formal B (k2Required)))
   (k2Generate
      (k2Build PT
         (k2Actual B) (k2Actual A))))

k2Formal

k2Formal ::= '(' 'k2Formal'
	k2FormalNameDef
	( k2Optional | k2Required )
	')'

Used by:

*k2KeywordParameters

Similar Keywords:

k2FormalNameRef

Description:

This construct is used to specify a formal parameter for use with the k2KeywordParameters section of a k2KeywordDefine form. These formal parameters will be substituted for positionally, by actual parameter values, in subsequent invocation of the defined keyword. The k2Optional form allows the use of formal parameters; these need not be included in every use of the new keyword. Any k2Formal parameter following a k2Optional parameter must also be a k2Optional.

Example:

(k2KeywordDefine wait
   (k2KeywordParameters
      (k2Formal load_time (k2Optional (k2Literal 5)))
      (k2Formal load_capacitance
         (k2Optional (k2Literal 1))))
   (k2Generate
      (k2Build loadDelay
         (k2Actual load_time)
         (k2Actual load_capacitance))))

This keyword definition creates a loadDelay construct. If the load value is not specified, the default value of 5 is used. A later use such as (wait 10) or (wait 15 20) would be legal in any context in which loadDelay is legal. These are equivalent to (loadDelay 5 1) and (loadDelay 20 1) respectively.

k2Generate

k2Generate ::= '(' 'k2Generate'
	{ comment | k2Actual | k2Build | k2Literal } 
	')'

Used by:

!k2KeywordDefine

Description:

K2Generate is used to specify the expansion of a form which references a defined keyword at keyword level k2 or higher. Since this construct contains an arbitrary number of builders, the use of a k2KeywordDefine can generate more than one form. In such cases it should not be used as a positional item within the enclosing construct.

Example:

(k2KeywordDefine polyFigure
   (k2KeywordParameters (k2Formal figure (k2Required)))
   (k2Generate
      (k2Build figure
         (k2Literal POLY)
         (k2Actual figure))))

k2KeywordDefine

k2KeywordDefine ::= '(' 'k2KeywordDefine'
	k1KeywordNameDef
	k2KeywordParameters
	k2Generate
	')'

Used by:

*k2KeywordLevel

Description:

The k2KeywordDefine construct provides the capability in EDIF of defining new keywords in terms of existing ones. It is intended to act as a reasonably powerful method of abbreviating EDIF descriptions using a general method which could be resolved in a pre-processing input step. Keywords have to be defined within keywordMap at the top level of the EDIF data, i.e. they cannot be defined inside a design or library, or anywhere other than a keywordMap.

In the above syntax, k1KeywordNameDef is an identifier which is being defined to be a keyword, k2KeywordParameters is a construct that defines all arguments to be passed to the k2KeywordDefine, and k2Generate is a construct that specifies what the k2KeywordDefine form will generate when processed. The defined keyword is not available for use until after the end of the k2KeywordDefine statement. Existing keyword names may not be redefined with this construct.

Example:

(k2KeywordDefine rev
   (k2KeywordParameters
      (k2Formal a (k2Required)) 
      (k2Formal b (k2Required)))
   (k2Generate
      (k2Build pt
         (k2Actual b) (k2Actual a))))

This example defines a new keyword rev in terms of the native keyword pt. A subsequent use such as (rev 1 2) should be interpreted in the same way as its expansion (pt 2 1).

k2KeywordParameters

k2KeywordParameters ::= '(' 'k2KeywordParameters'
	{ k2Formal } 
	')'

Used by:

!k2KeywordDefine

Description:

K2KeywordParameters contains a list of formal parameters which should correspond to individual forms or tokens at the time of expansion of a use of the new keyword.

If any of the enclosed k2Formal parameters are optional then any subsequent k2Formal parameters must also be optional.

Example:

(k2KeywordDefine EG
   (k2KeywordParameters
      (k2Formal a (k2Required)) 
      (k2Formal b (k2Required)))
   (k2Generate
      (k2Build pt (k2Actual a) (k2Actual b))))

This keyword definition shown in this example will generate the EDIF construct pt with values supplied by a and b. This shows the explicit definition of a keyword EG which has the same effect as a k1KeywordAlias for pt.

	')'

K2Literal generates the tokens specified within it, in the order specified. This avoids conflict between formal names of a k2KeywordDefine and identifiers desired in the keyword expansion.

k2Optional

k2Optional ::= '(' 'k2Optional'
	( k2Literal | k2Actual | k2Build )
	')'

Used by:

!k2Formal !k3Formal

Description:

K2Optional may appear within a k2Formal or k3Formal keyword parameter definition. It allows the use of formal parameters which need not be included in every use of a defined keyword. It contains the default value for its parameter. The default can be a literal value, the actual value of a parameter specified previously in the construct, or the result of building a form. The default value should generate a single token or form.

A k2Optional parameter may only be followed by further k2Optional parameters in the same list of k2KeywordParameters or k3KeywordParameters.

Example:

(k2KeywordDefine wait
   (k2KeywordParameters
      (k2Formal load (k2Required))
      (k2Formal load_capacitance
         (k2Optional (k2Literal 1))))
   (k2Generate
      (k2Build loadDelay
         (k2Actual load)
         (k2Actual load_capacitance))))

k3Build

k3Build ::= '(' 'k3Build'
	k1KeywordNameRef
	{ comment | k2Actual | k2Literal | k3Build | k3ForEach } 
	')'

Used by:

*k3Build *k3ForEach

Description:

K3Build is used within the context of a k3KeywordDefine to generate non- primitive output. It contains a k1KeywordNameRef, which is the name of an existing (or previously-defined) keyword. K3Build expands into a form with k1KeywordNameRef as its keyword, and with each component of the k3Build replaced by the result of generating the enclosed constructs in the order specified. The comments generate nothing, but provide documentation about the purpose or use of the keyword definition. The k3Build construct can use embedded k3ForEach constructs to process lists of arbitrary length.

Example:

(k3KeywordDefine inport
   (k3KeywordParameters
      (k3Formal name (k3Collector))
      (k3Formal load (k3Collector)))
   (k3Generate
      (k3ForEach (k3FormalList name load)
         (k3Build port (k2Actual name)
            (k3Build inputPort)
            (k3Build acLoad (k2Actual load))))))

This example defines a keyword which accepts any number of pairs consisting of a port name and a corresponding load value, such as

(inport p1 15 p2 20 p3 45)

which generates the following: 

(port p1 (inputPort) (acLoad 15))
(port p2 (inputPort) (acLoad 20))
(port p3 (inputPort) (acLoad 45))

k3Collector

k3Collector ::= '(' 'k3Collector'
	')'

Used by:

!k3Formal

Description:

K3Collector allows a k3Formal parameter to be bound to a list of values, as opposed to a single value.

If a k3Formal parameter contains a nested k3Collector, then it will be bound to all input arguments that are in excess of the number of k3Formal parameters defined for the keyword. Any k3Formal parameter following a k3Collector parameter must also be a k3Collector parameter. If there is more than one k3Collector parameter, then the extra values will be evenly distributed among them in turn. The number of actual forms and tokens bound as a list to each k3Collector parameter must be the same.

Example:

(k3KeywordDefine EG
   (k3KeywordParameters
      (k3Formal a (k2Required))
      (k3Formal b (k2Required))
      (k3Formal c (k3Collector)) ...)
   ...)

k3ForEach

k3ForEach ::= '(' 'k3ForEach'
	( k2FormalNameRef | k3FormalList )
	{ comment | k2Actual | k2Literal | k3Build | k3ForEach } 
	')'

Used by:

*k3Build *k3ForEach *k3Generate

Description:

K3ForEach is a looping construct that is used to build forms iteratively. It is used in conjunction with the keyword builder constructs k3Build and k3Generate. The builders specified within the k3ForEach will be expanded as long as the list of values bound to the k3Formal parameter (or parameters) specified in the k3ForEach is not exhausted. In other words, the builders contained within k3ForEach will be expanded for each value that is bound to the specified k3Formal parameters. K3ForEach is used to generate forms that use k3Formal parameters which are defined as k3Collector parameters.

Any k2Actual statements within k3ForEach which reference the same formal parameter should expand to a single value on each iteration.

Example:

(k3KeywordDefine inport
   (k3KeywordParameters
      (k3Formal name (k3Collector))
      (k3Formal load (k3Collector)))
   (k3Generate
      (k3ForEach (k3FormalList name load)
         (k3Build port (k2Actual name)
            (k3Build inputPort)
            (k3Build acLoad (k2Actual load))))))

This example defines a keyword that will create several input port declarations and specify an acLoad value for each. This could later be used in a statement such as:

(inport portA 12 portB 15 portC 6)

The name inport is not a native EDIF keyword and would not be legal without the appropriate definition.

This would generate: 

(port portA (inputPort) (acLoad 12))
(port portB (inputPort) (acLoad 15))
(port portC (inputPort) (acLoad 6))

k3FormalList

k3FormalList ::= '(' 'k3FormalList'
	{ k2FormalNameRef } 
	')'

Used by:

!k3ForEach

Similar Keywords:

k3Formal

Description:

K3FormalList contains a set of formal parameter references which are used to control the iterations of the k3ForEach form. Such iteration should step through the collected values of each referenced formal parameter in parallel, each of which should be bound to the same number of actual values.

Example:

(k3KeywordParameters
   (k3Formal name (k3Collector))
   (k3Formal load (k3Collector)))
(k3Generate
   (k3ForEach (k3FormalList name load)
      (k3Build port (k2Actual name)
         (k3Build inputPort)
         (k3Build acLoad (k2Actual load)))))

This example illustrates the collection and use of a series of port name and acLoad value pairs.

k3Generate

k3Generate ::= '(' 'k3Generate'
	{ comment | k2Actual | k2Build | k2Literal | k3ForEach } 
	')'

Used by:

!k3KeywordDefine

Description:

K3Generate is used to specify the expansion of a form which references a defined keyword. Since this construct contains an arbitrary number of builders, the use of a k3KeywordDefine can generate more than one form. In such cases it should not be used as a positional item within the enclosing construct.

Example:

(k3KeywordDefine inport
   (k3KeywordParameters
      (k3Formal name (k3Collector))
      (k3Formal load (k3Collector)))
   (k3Generate
      (k3ForEach (k3FormalList name load)
         (k3Build port (k2Actual name)
            (k3Build inputPort)
            (k3Build acLoad (k2Actual load))))))

This example shows the use of k3ForEach within a k3Generate keyword definition. A typical use could be: (inport IN1 10 IN2 20), which would generate: 

(port IN1 (inputPort) (acLoad 10))
(port IN2 (inputPort) (acLoad 20))
