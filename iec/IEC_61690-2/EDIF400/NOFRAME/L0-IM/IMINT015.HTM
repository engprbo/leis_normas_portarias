20 Sub-layouts

This chapter describes the concept of sub-layouts within a design. The model for sub_layout_definition can be found in the pcb_sub_layout_model schema. A sub_layout_definition is a description of a collection of layout items, which can later be instanced into another sub_layout_definition or onto a bare board. Figure 20.1 shows the model of sub_layout_definition.

Figure 20.1: The model of sub_layout_definition

A sub_layout_definition is divided into several categories:

  • bare_board_definition - a description of a re-usable bare board which supports the mounting and connection of components.

  • test_coupon_definition - a description of a collection of layout items which is used purely for testing purposes.

  • footprint_definition - a description of a collection of layout items which is specifically reserved for connection to or implementation of a component.

  • toeprint_definition - a description of a collection of layout items which is specifically reserved for connection to a component pin, or to implement a printed component pin.

  • padstack_definition - a description of a collection of layout items which is used primarily to provide for vertical connection between the conducting layers of a bare board.

  • non_specific_sub_layout_definition - a description of a collection of layout items which has no pre-defined purpose.

A sub_layout_instance is an instance of a sub_layout_definition. It is divided into several categories, depending on the type of the referenced sub_layout_definition. A test_coupon_instance is an instance of a test_coupon_definition. A footprint_instance is an instance of a footprint_definition. A toeprint_instance is an instance of a toeprint_definition. A padstack_instance is an instance of a padstack_definition. Finally, a non_specific_sub_layout_definition is an instance of a non_specific_sub_layout_definition. The model of sub_layout_instance is shown in figure 20.1.

20.1 Layout features

A collection of layout items may include layout_features, layout_text, sub_layout_instances or physical_nets. A layout_feature describes a single feature of the bare board. It can be a trace, a teardrop, a layout_shape or a hole. A trace is defined geometrically as a series of connected lines and arcs, which is applied to the bare board using real material, or cut out of other material that has already been applied to the bare board, or both. A layout_shape is used to describe features on the bare board which are more complex than traces. It can be either a pad or a non_specific_layout_shape. A pad describes part of a padstack and is usually defined geometrically as a simple shape. A non_specific_layout_shape describes a feature on the bare board which has a geometrical shape of arbitrary complexity. A hole is an absence of material on a physical layer or on multiple consecutive physical layers. It may be plated through or unplated. The two types of hole need to be distinguished because a plated_through_hole can form part of a physical_net, whereas an unplated_hole cannot. In addition, a hole can be either a conformant_hole or a non_conformant_hole. A conformant_hole is likely to be manufactured by a drilling process and has a circular cross-section. A non_conformant_hole can be manufactured by any appropriate process including drilling or stamping. Such a hole has an arbitrarily-shaped cross-section. Finally, a teardrop describes a pad taper which can be applied to a routed pad in order to provide a gradually narrowing connection to the route that the pad is connected to. 20.2 Physical nets

A physical_net describes a geometrically connected region of conductive material which provides connection of other artifacts to power, ground or a functional signal. Each such object is a collection of layout_features, sub_layout_instance_nets and other physical_nets. In addition, a physical_net may have a set of associated layout_text. A physical_net is divided into two categories. A bare_board_physical_net is owned directly by a bare_board_definition, whereas a non_specific_physical_net is owned directly by a sub_layout_definition which is not a bare_board_definition. A bare_board_physical_net may contain a set of planes. Each plane describes a region of a bare board which is to be plated with conductive material. Figure 20.3 shows the model of physical_net.

Figure 20.3: The model of physical_net

A sub_layout_definition may contain instances of other sub_layout_definitions. A physical_net may include instances of physical_nets on the sub_layout_instances. It ties physical_net instances together to make a net assembly. A sub_layout_instance_net references a physical net which is instantiated within a sub_layout_instance.
