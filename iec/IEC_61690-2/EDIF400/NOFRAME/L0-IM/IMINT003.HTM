5 Design hierarchy configuration

This chapter describes how an occurrence hierarchy is configured in EDIF. The model for configuration can be found in the hierarchy_model and the design_hierarchy_model.

As mentioned in section 2.3, EDIF introduces the notion of cluster which consists of an interface definition and the cell_representations sharing that interface. The cell definition may contain many clusters. Instances are created by instantiating clusters, rather than instantiating specific views. Therefore, for a given design to have an unambiguous tree structure, it is necessary to be able to specify for each instance which view is to be used. Furthermore, it is necessary to be able to specify alternative configurations for instances so that different design trees may be represented. Hence, the use of cluster provides the beginnings of a configuration mechanism.

The concepts of cluster_configuration and instance_configuration are defined to support the configuration mechanism. A cluster may contain many cluster_configurations, each of which describes how to continue expanding the hierarchy. A cluster_configuration can be either an expandable_cluster_configuration or a leaf_configuration.

An expandable_cluster_configuration identifies a view for the further expansion of the hierarchy. The chosen view must belong to the containing cluster of the expandable_cluster_configuration. Each instance defined within the chosen view must be either configured or unconfigured. To configure an instance, it is necessary to specify an instance_configuration which selects a valid cluster_configuration for the configured instance. The chosen cluster_configuration must be defined in the instantiated cluster of the configured instance. To unconfigure an instance, it is necessary to state explicitly that an instance is required to be unconfigured. Thus, an expandable_cluster_configuration may contain many unconfigured_instances and many instance_configurations. In a given expansion, an instance may be configured at most once.

If an instance has an instance_configuration which references a leaf_configuration, there is no further structure in the design tree below that instance.

A design_hierarchy is defined by selecting the top cluster_configuration. A design may contain many design hierarchies. For each design_hierarchy, the chosen cluster_configuration must be defined in the cluster_interface of the top_cell of the design.
