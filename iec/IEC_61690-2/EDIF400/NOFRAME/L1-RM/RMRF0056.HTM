portWidth

portWidth ::= '(' 'portWidth'
	integerExpression
	')'

Used by:

<port

Similar Keywords:

width

Description:

Specifies the number of individual one-bit port elements that will be produced by the enclosing port during hierarchy expansion. The port width may be dependent on parameter values.

The default port width is one.

Attributes defined for a port that has a portWidth are shared equally by all members of the port except nameInformation, which is specific to the wide port as a whole.

Example:

(portWidth 16)

This example specifies a port of width 16. 

(portWidth (integerParameterRef WIDTH))

This example specifies a port of width defined by a parameter.

Constraints:

1. The following constraint applies to this context: All contexts
A viewRef used inside previousVersion should reference a view of the same type as that which contains the previousVersion construct.

2. The following constraint applies to this context: All contexts
The latest timeStamp in the status of the view referenced by previousVersion should be before the earliest timeStamp in the status of the view containing the previousVersion construct.

PreviousVersion is used to indicate that a view is a new version of another view. PreviousVersion specifies the view that represents the previous version of this view.

Example:

         (previousVersion 
            (viewRef SCHEMATIC_0)
            ))
      ...))

In this example, the view SCHEMATIC is a new version of the view SCHEMATIC_0.

primaryName

	originalName
	{ <displayName> | <generated> | <nameStructure> } 
	')'

Used by:

!nameInformation

Description:

The originalName within primaryName is the basic name of the object in the source system. The other information within primaryName provides additional data about the name in the originating system.

The originalName within primaryName is the name the source system recommends the target system to use for the object being defined.

Alternative names or aliases may be given using nameAlias.

Example:

(signal S1 (signalJoined ...)
   (nameInformation 
      (primaryName "BusA0"
         (displayName "BusA"))) ...)

In this example, the signal with EDIF identifier S1 has a primaryName BusA0.

propertyDisplayOverride

propertyDisplayOverride ::= '(' 'propertyDisplayOverride'
	propertyNameRef
	( addDisplay | replaceDisplay | removeDisplay )
	{ <propertyNameDisplay> } 
	')'

Used by:

*pageBorder *pageTitleBlock *schematicComplexFigure *schematicForFrameBorder *schematicGlobalPortImplementation *schematicIfFrameBorder *schematicInstanceImplementation *schematicInterconnectTerminatorImplementation *schematicJunctionImplementation *schematicMasterPortImplementation *schematicOffPageConnectorImplementation *schematicOnPageConnectorImplementation *schematicOtherwiseFrameBorder *schematicRipperImplementation *schematicSymbolBorder *schematicSymbolPortImplementation

Similar Keywords:

cellPropertyDisplayOverride clusterPropertyDisplayOverride display portPropertyDisplayOverride property propertyDisplay propertyOverride

Constraints:

1. The following constraint applies to this context: All contexts
In a given context there may be no more than one propertyDisplayOverride for each property.

2. The following constraint applies to this context: All contexts
If a propertyDisplayOverride is present in the implementation of a template, then there must be a propertyDisplay for the property in the template.

Description:

PropertyDisplayOverride is used to override a propertyDisplay defined in a template.

The original propertyDisplay is effectively supplemented (using addDisplay), replaced (using replaceDisplay) or removed (using removeDisplay) in the implementation with the display data given in the propertyDisplayOverride.

Example:

(schematicGlobalPortTemplate GROUND_SYMBOL
   (schematicTemplateHeader 
      (schematicUnits ...)
      (property GPTP ...) ...)
   (hotspot (pt 0 0))
   (figure LINES ...)
   (propertyDisplay GPTP 
      (display TEXT 
         (transform (origin (pt 100 200)))))
   )
...
(cell Top_level_schematic (cellHeader ...)
   (cluster C1
      (interface ...)
      (clusterHeader ...)
      (schematicView schematic_sheet
         (schematicViewHeader ...)
         (logicalConnectivity
            ...
            (signal N1
               (signalJoined 
                  (globalPortRef ...) ...) ...))
         (schematicImplementation
            (page &1 (pageHeader ...)
               (schematicGlobalPortImplementation &1
                  (schematicGlobalPortTemplateRef 
                     GROUND_SYMBOL)
                  (globalPortRef ...)
                  (transform (origin (pt 1000 1000)))
                  (propertyDisplayOverride GPTP
                     (replaceDisplay
                        (display TEXT 
                           (transform 
                              (origin (pt 1300 1400)))))))
               )))))

In this example, the property GPTP belonging to the global port template GROUND_SYMBOL will be displayed at (pt 1300 1400) in the page and not at (pt 1100 1200). Note that the position (pt 100 200) is relative to the origin of the template, and was subject to transformation by the transform in the implementation.

	propertyNameRef
	( typedValue | untyped )

Used by:

*cellPropertyOverride *clusterPropertyOverride *figureGroupOverride *ifFrameAnnotate *instancePropertyOverride *interconnectAnnotate *otherwiseFrameAnnotate *pageBorder *pageTitleBlock *pcbBareBoard *pcbDrawingBorder *pcbDrawingTitleBlock *pcbFigureAttributeOverride *pcbMountableDiePhysicalTemplatePropertyOverride *pcbMountablePackagePropertyOverride *portPropertyOverride *propertyOverride *schematicComplexFigure *schematicForFrameBorder *schematicGlobalPortImplementation *schematicIfFrameBorder *schematicInstanceImplementation *schematicInterconnectTerminatorImplementation *schematicJunctionImplementation *schematicMasterPortImplementation *schematicOffPageConnectorImplementation *schematicOnPageConnectorImplementation *schematicOtherwiseFrameBorder *schematicRipperImplementation *schematicSymbolBorder *schematicSymbolPortImplementation *signalAnnotate *signalGroupAnnotate *viewPropertyOverride

Similar Keywords:

cellPropertyDisplayOverride clusterPropertyDisplayOverride portPropertyDisplayOverride property propertyDisplayOverride

Constraints:

1. The following constraint applies to this context: All contexts
The type of a propertyOverride must match that of the property being overridden.

2. The following constraint applies to this context: All contexts
The property being overridden with propertyOverride should not be fixed or notInherited.
(See also similar constraint in: notInherited)

Description:

PropertyOverride is used to override the value of a property on instantiation, back annotation or other appropriate positions.

It is appropriate to be able to specify fixed for a propertyOverride because this is used to prevent further propertyOverrides being applied at a later stage, e.g. in annotation.

It is not possible to override part of a property using nested propertyOverride; the whole property is always overridden.

Example:

(signal SIG1 (signalJoined ...)
   (property P1
      (string "ABCD")) ...)
...
(occurrenceAnnotate I1
   (signalAnnotate SIG1
      (propertyOverride P1 (string "PQRS"))))

In this example, the property P1 belonging to signal SIG1 is overridden with a new value in the signalAnnotate form.

pt

pt ::= '(' 'pt'
	xCoordinate
	yCoordinate
	')'

Used by:

pointValue

Description:

Pt is used to specify the coordinates of all geometric data such as line drawings and filled areas. It is also used to specify locations of objects. The first integerValue, xCoordinate, is the x-location, and the second integerValue, yCoordinate, is the y-location of the point.

Coordinates are scaled between views according to units defined by setDistance.

Example:

(pt 100 50)

This example specifies a point which is 100 units to the right of the coordinate origin and 50 units above it.
