pcbNonSpecificLayoutShapeClass

pcbNonSpecificLayoutShapeClass ::= '(' 'pcbNonSpecificLayoutShapeClass'
	')'

Used by:

<pcbKeepInItems <pcbKeepOutItems

Similar Keywords:

pcbNonSpecificLayoutShape shape

Description:

Specifies all non-specific layout shapes.

Example:

(pcbBareBoardRegionTechnologyRule TTTL2TR
   (pcbTechnologyRuleHeader ...)
   (pcbPhysicalLayerSet
      (pcbPhysicalLayerRef LAYER2))
   (rectangle (pt 100 200) (pt 500 500))
   (pcbTechnologyRuleDetails ...)
   (pcbKeepInItems (pcbNonSpecificLayoutShapeClass)))

In this example, all non-specific layout shapes are recommended to be kept in the specified region of LAYER2.

pcbPackageBallPitch

	')'

Used by:

Similar Keywords:

Constraints:

Description:

Specifies the distance between adjacent solder balls in the same row. The distance is center to center. PcbPackageBallPitch does not define the location of the solder balls; it merely indicates the pitch used. The actual locations of pins are defined within pcbPackageTerminalSolderBall.

   (occupiedSpace ...)

   (pcbPackageTerminalSolderBall ...) ...)

pcbPackagedConnectorComponent

pcbPackagedConnectorComponent ::= '(' 'pcbPackagedConnectorComponent'
	pcbComponentNameDef
	pcbPackagedConnectorPartRef

	')'

Used by:

Similar Keywords:

pcbAuxiliaryComponentConnector pcbPackagedConnectorComponentImplementation pcbPackagedConnectorComponentRef pcbPackagedConnectorComponentTerminalImplementation pcbPackagedConnectorPart pcbPackagedElectricalComponent pcbPrintedConnectorComponent

Description:

Defines a packaged connector component; that is, an instance of a packaged connector part. Packaged connector components are mounted onto the bare board naked, i.e. with no further package inserted (or onserted, etc.)

If a socket carries another package, the socket must be described as a pcbAuxiliaryComponent. In this case, the package that is mounted on the socket (e.g. a DIP) is the first-specified package in the pcbMountablePinPackage.

Example:

(pcbPackagedConnectorComponent SOCKET1
   (pcbPackagedConnectorPartRef RS_401-790)
   (pcbComponentHeader))

Specifies how a particular packaged connector component is implemented on the assembled board.    (pcbFootprintInstanceRef F16)

Here, the component I1_SN74S140 is defined. It is an instance of the part SN74S140.

Constraints:

1. The following constraint applies to this context: All contexts
A mountable package terminal may be referenced at most once within a component implementation, i.e. it can have at most one implementation.
(See also similar constraint in: pcbJumperComponentImplementation, pcbPackagedConnectorComponentImplementation)

Description:

Defines how the component referenced by pcbPackagedElectricalComponentRef is mounted onto the bare board.

UnscaledTransform specifies the position of the component on the bare board.

PcbMountablePackageRef specifies the mountable package that is used when mounting the component on the bare board.

PcbFootprintInstanceRef specifies the footprint on which the component is placed.

PcbPackagedElectricalComponentTerminalImplementation specifies the padstack in which each packaged component terminal is placed.

PcbMountablePackageTerminalImplementation may be used, rather than pcbPackagedElectricalComponentTerminalImplementation, in cases where the terminal is not associated with a part terminal, e.g. for a non-electrical pin.

Example:

(pcbPackagedElectricalComponentImplementation CI2
   (pcbPackagedElectricalComponentRef COMP2)
   (pcbMountablePackageRef DIP14_Dip_Bottom
      (libraryRef MOUNTABLE_PACKAGES))
   (unscaledTransform ...)
   (pcbFootprintInstanceRef FOOTP21)
   (pcbPackagedElectricalComponentTerminalImplementation T1_IMP
      (pcbElectricalPartTerminalRef P1)
      (pcbToeprintPadstackInstanceRef PADSTACK1
         (pcbFootprintToeprintInstanceRef TI1))
      (pcbMountablePackageTerminalRef T1))
   (pcbPackagedElectricalComponentTerminalImplementation T2_IMP
      (pcbElectricalPartTerminalRef P2)
      (pcbToeprintPadstackInstanceRef PADSTACK1
         (pcbFootprintToeprintInstanceRef TI2))
      (pcbMountablePackageTerminalRef T2)) ...)

An electrical, connector or jumper part must have at least one terminal.
(See also similar constraint in: pcbDieElectricalPart, pcbJumperPart, pcbPackagedConnectorPart, pcbPrintedConnectorPart, pcbPrintedElectricalPart)

2. The following constraint applies to this context: All contexts
In the context of pcbPackagedElectricalPart, each package terminal (of the package referenced) may be referenced by at most one of the pcbPackagedElectricalPartTerminal constructs contained within pcbPackagedElectricalPart.

Description:

A packaged electrical part corresponds to a data-book description of a packaged electrical object, such as an SN74LS00J (quadruple 2-input NAND gates packaged in a 14-pin ceramic DIL package).

The third required item references the part's package, e.g. pcbPinPackageRef.

The count of pcbPackagedElectricalPartTerminals defined within a pcbPackagedElectricalPart may be less than the count of package terminals (e.g. pcbPackageTerminalPin or pcbPackageTerminalSolderBall) defined within the package that is referenced by the pcbPackagedElectricalPart. This means that it is possible for some of the package terminals of the package to be referenced by none of the pcbPackagedElectricalPartTerminals. This does not mean that those package terminals are unconnected in the pcbPackagedElectricalPart; it means only that the pcbPackagedElectricalPart is not completely defined.

An unconnected package terminal is indicated in a pcbPackagedElectricalPart by defining the corresponding fully defined electrical part terminal as having a reference to a package terminal, but no references to any part function terminals.

This example describes the following:

pcbPackagedElectricalPartFullyDefined

pcbPackagedElectricalPartFullyDefined ::= '(' 'pcbPackagedElectricalPartFullyDefined'
	{ pcbElectricalPartFunction | pcbElectricalPartFunctionPermutable | 
	pcbPackagedElectricalPartTerminal } 
	')'

Used by:

pcbPackagedElectricalPartType

Similar Keywords:

pcbDieElectricalPartFullyDefined pcbPackagedElectricalPart pcbPackagedElectricalPartMinimallyDefined pcbPrintedElectricalPartFullyDefined

Description:

A fully-defined packaged electrical part includes the connectivity of the individual functions within the part and the permutability (i.e. swappability) of those functions.

The permutability of the function ports is defined by the cluster referenced within pcbElectricalPartFunction.

Example:

See pcbPackagedElectricalPart for a comprehensive example.

pcbPackagedElectricalPartMinimallyDefined

pcbPackagedElectricalPartMinimallyDefined ::= '(' 
	'pcbPackagedElectricalPartMinimallyDefined'
	{ pcbElectricalTerminalPermutable | pcbPackagedElectricalPartTerminal } 
	')'

Used by:

pcbPackagedElectricalPartType

Similar Keywords:

pcbDieElectricalPartMinimallyDefined pcbPackagedElectricalPart pcbPackagedElectricalPartFullyDefined pcbPrintedElectricalPartMinimallyDefined

Description:

A minimally-defined packaged electrical part does not include a definition of the functions and connectivity within the part, nor the permutability (i.e. swappability) of those functions. Instead, it defines the permutability of the part terminals.

Example:
