display

Constraints:

1. This construct is illegal in this context: pageTitleBlockTemplate

2. This construct is illegal in this context: schematicSymbolPortTemplate

Description:

RemoveDisplay is used to remove attribute display positions that are defined in a template, but are to be removed for the current use of that template. It is valid only in the context of an implementation of a template. It removes any display positions provided by the template.

Example:

(schematicGlobalPortTemplate GROUND_SYMBOL
   (schematicTemplateHeader 
      (schematicUnits ...)
      (property GPTP ...) ...)
   (hotspot (pt 0 0))
   (figure LINES ...)
   (propertyDisplay GPTP 
      (display TEXT 
         (transform (origin (pt 100 200)))))
   )
...
(cell Top_level_schematic (cellHeader ...)
   (cluster C1
      (interface ...)
      (clusterHeader ...)
      (schematicView schematic_sheet
         (schematicViewHeader ...)
         (logicalConnectivity
            ...
            (signal N1
               (signalJoined 
                  (globalPortRef ...) ...) ...))
         (schematicImplementation
            (page &1 (pageHeader ...)
               (schematicGlobalPortImplementation &1
                  (schematicGlobalPortTemplateRef 
                     GROUND_SYMBOL)
                  (globalPortRef ...)
                  (transform (origin (pt 1000 1000)))
                  (propertyDisplayOverride GPTP
                     (removeDisplay)))
               )))))

In this example, the property GPTP belonging to the global port template GROUND_SYMBOL will not be displayed within the implementation &1.

Description:

ReplaceDisplay is used to provide alternative display positions for an attribute that is to be displayed. It is valid only in the context of an implementation of a template, and replaces any display positions provided by the template.

Example:

(schematicGlobalPortTemplate GROUND_SYMBOL
   (schematicTemplateHeader 
      (schematicUnits ...)
      (property GPTP ...) ...)
   (hotspot (pt 0 0))
   (figure LINES ...)
   (propertyDisplay GPTP 
      (display TEXT 
         (transform (origin (pt 100 200)))))
   )
...
(cell Top_level_schematic (cellHeader ...)
   (cluster C1
      (interface ...)
      (clusterHeader ...)
      (schematicView schematic_sheet
         (schematicViewHeader ...)
         (logicalConnectivity
            ...
            (signal N1
               (signalJoined 
                  (globalPortRef ...) ...) ...))
         (schematicImplementation
            (page &1 (pageHeader ...)
               (schematicGlobalPortImplementation &1
                  (schematicGlobalPortTemplateRef 
                     GROUND_SYMBOL)
                  (globalPortRef ...)
                  (transform (origin (pt 1000 1000)))
                  (propertyDisplayOverride GPTP
                     (replaceDisplay
                        (display TEXT 
                           (transform 
                              (origin (pt 1300 1400)))))))
               )))))

In this example, the property GPTP belonging to the global port template GROUND_SYMBOL will be displayed at (pt 1300 1400) in the page and not at (pt 1100 1200) which is (pt 100 200) transformed to the origin of the template in the page, (pt 1000 1000).

resolves

resolves ::= '(' 'resolves'
	{ logicNameRef } 
	')'

Used by:

*logicValue

Description:

Resolves is used by logicValue in logicDefinitions to define the current logic value as the outcome when the specified logic values are in contention on a net. When used to indicate the result of contention between two sources of the same value, this overrides the default condition of self-domination.

Example:

(logicValue X
   (resolves T F))

In this example, a net that has the logic values T and F applied to it will take on the logic value of X.

scale

scale ::= '(' 'scale'
	numerator
	denominator
	')'

Used by:

<uniformScaleTransform

Similar Keywords:

fixedScaleTransform pcbDrawingFactorScaleDrawing pcbDrawingScaleFactor pcbDrawingScaleFactorDisplayString pcbDrawingScaleFactorDrawing scaleX scaleY

Constraints:

1. The following constraint applies to this context: All contexts
The numerator of a scale construct should not be zero.
(See also similar constraint in: numerator, scaleX, scaleY)

Description:

Specifies the scale factor for a transformation.This scale is specified as a numerator and denominator. The scale applies uniformly to the X and Y direction.

The default value of scale is (scale 1 1). It has the effect of multiplying all x-coordinates and y-coordinates by the given fraction, before any rotation implied by any associated rotation.

Scaling occurs relative to the origin of the object being transformed, as with scaleX and scaleY.

Example:

(pcbDrawingComplexFigure
   (pcbDrawingFigureMacroRef Fig_Mac1)
   (uniformScaleTransform 
      (scale 1000 1414)
      (origin (pt 100 700))))

scaleX

scaleX ::= '(' 'scaleX'
	numerator
	denominator
	')'

Used by:

<transform

Similar Keywords:

scale

Constraints:

1. The following constraint applies to this context: All contexts
The numerator of a scale construct should not be zero.
(See also similar constraint in: numerator, scale, scaleY)

2. The following constraint applies to this context: When present within display <schematicView
Within a schematicView the scaleX and scaleY used to transform a display must have absolute values of 1.
(See also similar constraint in: display, scaleY)

Description:

ScaleX is used to scale in the x direction within transform. The scale fraction is specified as a numerator and denominator.

When not specified, the scaling is assumed to be 1, i.e. (scaleX 1 1) is the default. It has the effect of multiplying all x-coordinates by the given fraction, before any rotation implied by any associated rotation.

Scaling occurs relative to the origin of the object being transformed. For example, given (rectangle (pt -2 -2) (pt 2 2)), which is part of the cell view, and given the x scaling (scaleX 2 1), the figure would be scaled before translation to (rectangle (pt -4 -2) (pt 4 2)).

Example:

(instance Inst_1 
   (clusterRef CL1 (cellRef cell1)))
...
(schematicInstanceImplementation &123 
   (instanceRef Inst_1)
   (schematicSymbolRef symbol)
   (transform
      (scaleX 2 1)
      (scaleY 3 1)))

This example scales the cell by 2 in the x direction.

schematicBus

schematicBus ::= '(' 'schematicBus'
	interconnectNameDef
	signalGroupRef
	schematicInterconnectHeader
	schematicBusJoined
	{ comment | <schematicBusDetails> | schematicBusSlice | 
	<schematicInterconnectAttributeDisplay> | userData } 
	')'

Used by:

*page *schematicFrameImplementationDetails

Similar Keywords:

schematicBusGraphics schematicSubBus schematicSubBusSet

Description:

A schematicBus is a structured representation of the connectivity of a collection of signals.

SchematicBus has a name, interconnectNameDef. Its structure in terms of the signals it contains is defined by a reference to a signalGroup given by signalGroupRef. Its structure in terms of the ports that it connects together is given within schematicBusJoined.

The schematicSubBusses within schematicBusDetails further describe the structure of the connectivity in a manner analogous to schematicSubNet for schematicNet. Also, the structure may be further elaborated by using schematicBusSlice, which takes a subset of the signals of a schematicBus.

A schematicBus provides further information about the connectivity described in the signals that it references.

Example:

(logicalConnectivity ...
   (signal A0 
      (signalJoined 
         (portInstanceRef P3_0
            (instanceRef I1))
         ...))
   (signal A1 
      (signalJoined 
         (portInstanceRef P3_1 
            (instanceRef I1))
         ...))
   (signal A2 
      (signalJoined 
         (portInstanceRef P3_2
            (instanceRef I1))
         ...))
   (signal A3 
      (signalJoined 
         (portInstanceRef P3_3 
            (instanceRef I1))
         ...))
   (signalGroup A 
      (signalList (signalRef A0) (signalRef A1)
         (signalRef A2) (signalRef A3)))
   ...)
(schematicImplementation ...
   (page &1 ...
      (schematicBus BUS_A 
         (signalGroupRef A)
         (schematicInterconnectHeader ...)
         (schematicBusJoined 
            (portJoined 
               (portInstanceRef P3 (instanceRef I1)))
            ...) 
         (schematicBusDetails
            (schematicBusGraphics 
               (figure BUS_GRAPHICS 
                  (path 
                     (pointList 
                        (pt 100 200) 
                        (pt 300 200)))))) ...) ...) ...)

In this example, there is an instance I1 with a portBundle P3 which is 4 bits wide. This instance port P3 is joined to schematicBus BUS_A, which is a schematicBus 4 bits wide. Notice that the signals contain the connectivity of the individual bits (P3_0, P3_1, P3_2 and P3_3) of the portBundle P3. The bus is implemented using a single line from (pt 100 200) to (pt 300 200).

schematicBusGraphics

schematicBusGraphics ::= '(' 'schematicBusGraphics'
	{ comment | figure | schematicComplexFigure | userData } 
	')'

Used by:

Similar Keywords:

Constraints:

1. The following constraint applies to this context: All contexts
The graphics associated with a schematic interconnect may only be described using the path construct, either directly with figure or indirectly through the use of complexGeometry or schematicComplexFigure.
(See also similar constraint in: schematicNetGraphics)

2. The following constraint applies to this context: All contexts
A path used to represent the graphics of a schematic interconnect must end at a hotspot or in space, i.e. it must not touch the graphics of another interconnect or instantiatable object.
(See also similar constraint in: schematicNetGraphics)

3. The following constraint applies to this context: All contexts
When two paths from different nets or busses cross, the point of intersection should not appear in the pointList of any of the paths used to represent the net or bus graphics.
(See also similar constraint in: schematicNetGraphics)

4. The following constraint applies to this context: All contexts
Segments of different paths in a schematic interconnect should not lie on top of each other.
(See also similar constraint in: schematicNetGraphics)

5. The following constraint applies to this context: All contexts
When two or more paths in the same schematic interconnect intersect or touch, a schematicJunctionImplementation must be placed at their intersection point and each path should include the intersection point in its pointList.
(See also similar constraint in: schematicJunctionImplementation, schematicNetGraphics)

Description:

SchematicBusGraphics provides details of the graphical implementation of a schematic bus, bus slice or subbus.

Example:

(schematicBus BUS1 (signalGroupRef A)
   (schematicInterconnectHeader ...)
   (schematicBusJoined ...)
   (schematicBusDetails
      (schematicBusGraphics
         (figure BUS_GRAPHICS 
            (path (pointList (pt 100 200) 
                  (pt 300 200)))))
      ))

In this example, the bus BUS1 is implemented using a single line from (pt 100 200) to (pt 300 200).

schematicBusJoined

schematicBusJoined ::= '(' 'schematicBusJoined'
	portJoined
	{ ripperHotspotRef | schematicGlobalPortImplementationRef |

	schematicJunctionImplementationRef |

Constraints:

1. The following constraint applies to this context: All contexts
A port, portBundle, globalPort, globalPortBundle or localPortGroup referenced in a connectivityBusJoined or schematicBusJoined must be the same size as the size of the flattened signalGroup which the bus (or parent bus in the case of a sub bus) references.
(See also similar constraint in: connectivityBusJoined)

2. The following constraint applies to this context: All contexts
If a schematicNetJoined or schematicBusJoined references a schematicGlobalPortImplementation then the schematicNetJoined or schematicBusJoined must also reference the globalPort or globalPortBundle that the schematicGlobalPortImplementation implements.
(See also similar constraint in: schematicGlobalPortImplementation, schematicNetJoined)

3. The following constraint applies to this context: All contexts
Each port or portBundle on an instance that is joined in a schematicNet or schematicBus must belong to an instance for which there is a schematicInstanceImplementation in the page that encloses the interconnect.
(See also similar constraint in: schematicInstanceImplementation, schematicNetJoined)

4. The following constraint applies to this context: All contexts
If a schematicNetJoined or schematicBusJoined references a schematicMasterPortImplementation, then the schematicNetJoined or schematicBusJoined must also reference the port or portBundle that the schematicMasterPortImplementation implements.
(See also similar constraint in: schematicMasterPortImplementation, schematicNetJoined)

5. The following constraint applies to this context: All contexts
The ports (port, portBundle, globalPort, globalPortBundle and localPortGroup), rippers (ripperHotspot) and instantiatable schematic objects (schematicGlobalPortImplementation, schematicInterconnectTerminatorImplementation, schematicJunctionImplementation, schematicMasterPortImplementation, schematicOffPageConnectorImplementation, schematicOnPageConnectorImplementation and schematicSymbolPortImplementation) referenced in a sub interconnect (schematicSubNet and schematicSubBus) must be a subset of those referenced in the parent interconnect (schematicNet, schematicSubNet, schematicBus, schematicSubBus and schematicBusSlice).
(See also similar constraint in: schematicNetJoined, schematicSubBus, schematicSubNet)

6. The following constraint applies to this context: All contexts
If a schematicNetJoined or schematicBusJoined references a schematicSymbolPortImplementation then the schematicNetJoined or schematicBusJoined must also reference the instance port or portBundle that the schematicSymbolPortImplementation implements.
(See also similar constraint in: schematicNetJoined, schematicSymbolPortImplementation)

7. The following constraint applies to this context: All contexts
When a portInstanceRef is used in a schematicBusJoined or connectivityBusJoined the size of the flattened signalGroup associated with the interconnect should equal either the size of the port or flattened portBundle, or the product of this size and the instanceWidth.
(See also similar constraint in: connectivityBusJoined, instanceWidth)

Description:

SchematicBusJoined lists all the ports and hotspots that are connected to the schematicBus, schematicBusSlice or schematicSubBus. It is analogous to schematicNetJoined in schematicNet.

When used within schematicSubBus, the schematicBusJoined must be a subset of the schematicBusJoined of the immediately-enclosing schematicBus, schematicSubBus or schematicBusSlice.

Example:

(schematicBusJoined 
   (portJoined (portRef MP1) ...)
   (ripperHotspotRef H1 
      (schematicRipperImplementationRef R1)))

In this example, the master port MP1 and one end of a schematicRipperImplementation R1 are joined to the schematicBus.
