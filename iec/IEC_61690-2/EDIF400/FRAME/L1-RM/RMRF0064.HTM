timeInterval

timeInterval ::= '(' 'timeInterval'
	( event | offsetEvent )
	( event | offsetEvent | duration )
	')'

Used by:

!forbiddenEvent

Similar Keywords:

time

Description:

TimeInterval is used to describe an interval between two times. Times can be described by events or offset events. The first construct gives the beginning of the time interval. The second construct gives the end of the time interval, or its duration.

A duration can be used instead of the second event to specify explicitly the length of the interval.

Example:

(timeInterval
   (event (portRef A) (transition I O))
   (duration 17))

In the first example, the time interval described is from the time when port A changes from I to O, to a time 17 time units after the event. Both the event time, and the point 17 time units after, are included in the window. 

(timeInterval
   (event (portRef ENA) (transition H L))
   (offsetEvent
      (event (portRef P1) (becomes Z))
      (e 14 -1)))

In the second example, the time interval is from the time when port ENA changes from H to L, to 1.4 time units after the port P1 next becomes Z.

timing

timing ::= '(' 'timing'
	timingNameDef
	derivation
	{ comment | forbiddenEvent | pathDelay | property | userData } 
	')'

Used by:

*connectivityFrameStructure *connectivityStructure *instance *interface *occurrenceAnnotate *occurrenceHierarchyAnnotate

Similar Keywords:

timingDisplay timingNameRef

Constraints:

1. This construct is illegal in this context: connectivityStructure <connectivityView <external

Description:

Timing is used to provide a set of path delays or simulation timing constraints (forbidden events). It is named so that it may be referenced from timingDisplay. Derivation indicates whether the value is calculated, measured or a required value.

Example:

(timing T1 (calculated)
   (pathDelay
      (delay (mnm (e 18 -1) (e 37 -1) (e 84 -1)))
      (event (portRef CK) (transition L H))
      (event (portRef Q) (transition L H)))
   (forbiddenEvent
      (timeInterval
         (offsetEvent 
            (event (portRef CK) 
               (transition H L)) (e -48 -1))
         (duration (e 72 -1)))
      (event (portRef D))))

This example describes a calculated path delay from port CK to port Q, with a logic transition from L to H. The delay required has a minimum value of 1.8 time units, a nominal value of 3.7 time units, and a maximum value of 8.4 time units.

The forbiddenEvent statement requires that port D is stable for at least 4.8 time units before a falling (H to L) transition of CK, and remains stable for at least 2.4 time units after the CK transition, giving a stability requirement of 7.2 time units.

transform

transform ::= '(' 'transform'
	{ <origin> | <rotation> | <scaleX> | <scaleY> } 
	')'

Used by:

!complexGeometry !display !pageBorder !pageTitleBlock !schematicComplexFigure !schematicForFrameBorder !schematicGlobalPortImplementation !schematicIfFrameBorder !schematicInstanceImplementation !schematicInterconnectTerminatorImplementation !schematicJunctionImplementation !schematicMasterPortImplementation !schematicOffPageConnectorImplementation !schematicOnPageConnectorImplementation !schematicOtherwiseFrameBorder !schematicRipperImplementation !schematicSymbolBorder !schematicSymbolPortImplementation

Similar Keywords:

fixedScaleTransform uniformScaleTransform unscaledTransform

Description:

Transform is used to locate an implementation of a symbol or other object that can be instantiated, and to specify the location and scaling of text.

ScaleX and scaleY are used to indicate scale factors. The default scaling is 1 for scaleX and scaleY. Negative values indicate mirroring.

Rotation is used to describe the rotation of the object, and rotation angle is measured in units defined by setAngle. The default rotation is zero radians.

Origin is used to describe the translation point of an instance. The default origin is (pt 0 0).

Each operation within transform is applied in the following order: scaleX, scaleY, rotation and finally translation (origin). This order is not affected by the ordering within transform.

Example:

(instance INST_1
   (clusterRef CL1 (cellRef CELL1)))
...
(schematicInstanceImplementation IMPL_1 
   (instanceRef INST_1)
   (schematicSymbolRef SYM1)
   (transform
      (scaleX 2 1)
      (scaleY 3 1)
      (rotation 90)
      (origin (pt 10 70))))

In the above example, the instance is scaled by 2 in the x direction and by 3 in the y direction. The instance is then rotated 90 degrees and placed at (10, 70).

A typical point such as (100, 500) in SYM1 would map to (-1490, 270).

transition

transition ::= '(' 'transition'
	previousLogicValue
	presentLogicValue
	')'

Used by:

*event *interconnectDelay *portDelay *portDelayOverride *portLoadDelay *portLoadDelayOverride

Constraints:

1. The following constraint applies to this context: All contexts
When a logicList is used the size of the list should match that of the port or portBundle or other logic lists associated with the enclosing construct.
(See also similar constraint in: becomes, event)

Description:

Transition is used to describe a logic state transition from the previous logic value to the present value.

In the case of a transition which contains a logicList, the transition occurs as soon as the following conditions are met. At some previous time each associated port had a logic value equal to the corresponding value of the first logicList; each port has a logic value equal to the corresponding value of the second logicList; each individual port has had no more than one logic transition between these times.

LogicOneOf is used to provide a choice of logic values or logic lists. Any match in the logicOneOf is considered a match for the transition statement.

Example:

(transition L H)

The first example specifies the transition from the logic value L to the logic value H. 

(transition Z (logicOneOf H L))

The second example specifies the transition from the logic value Z to the logic value H or the transition from the logic value Z to the logic value L.
