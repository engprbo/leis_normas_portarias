design

design ::= '(' 'design'
	designNameDef
	cellRef
	designHeader
	{ comment | designHierarchy | userData } 
	')'

Used by:

*edif

Similar Keywords:

designHierarchyHeader designHierarchyNameCaseSensitive designHierarchyNameDef designNameCaseSensitive designUnits

Description:

Design identifies the cell at the top level of the hierarchy of a particular design within a library. Since a single EDIF file may contain many designs, the reader/translator must know the name of the design and view to be processed if only a single design is desired.

Within design, the cellRef must always contain a libraryRef, as no cells are directly visible from that context.

Design also contains design hierarchies and annotation data for any particular view in the cell referenced by cellRef.

If design is omitted from EDIF data, then the data allows the transfer of library information only. It is invalid to interpret any cell, in any library, other than ones referenced directly by designs as the top of a design hierarchy.

Example:

(design root
   (cellRef TopOfDesignCell
      (libraryRef CMOSLibrary))
   (designHeader ...))

In the above example, the design root is specified to start at the cell named TopOfDesignCell, which can be found in the library called CMOSLibrary.

designator

designator ::= '(' 'designator'
	stringValue
	')'

Used by:

<instance <instancePortAttributes <interface <leafOccurrenceAnnotate <occurrenceAnnotate <pcbComponentHeader <pcbElectricalPartFunction <port <portAnnotate

Similar Keywords:

designatorDisplay pcbDesignatorDrawing pcbDesignatorFabrication pcbDesignatorFabricationOverride

Description:

Designator is used to specify the designated number or name; for example, of a port or an instance. In the PCB environment, the designators on ports are typically referred to as pin numbers, and the designators on cell instances are typically referred to as component reference designators.

Example:

(cell Foo ...
   (cluster C1 
      (interface ... (designator "U000")
         (port A ... (designator "x"))) ...))
(cell Fer ...
   (cluster C1 ...
      (schematicView V1 (schematicViewHeader ...)
         (logicalConnectivity 
            (instance I1 
               (clusterRef C1 (cellRef Foo))
               (designator "U123")
               (instancePortAttributes A
                   ... (designator "1"))))
         (schematicImplementation ...))))
(cell Fee ...
   (cluster C1 ...
      (schematicView V1 (schematicViewHeader ...) 
         (logicalConnectivity 
            (instance I2 (clusterRef C1 (cellRef Fer))
               ...) ...)
         (schematicImplementation ...))
      (clusterConfiguration CONFIG1 (viewRef V1)...)))
(design TOP
   (cellRef Fee ...) 
   (designHeader ...)
   (designHierarchy H1
      (clusterRef C1)
      (clusterConfigurationRef CONFIG1)
      (designHierarchyHeader ...)
      (occurrenceHierarchyAnnotate 
         (occurrenceAnnotate I2
            (designator "U42")
            (portAnnotate A
               ... (designator "2"))))))

In the above example, a cell named Foo is defined with a default component reference designator "U000", and a port named A with a default pin name of "x".

A cell named Fer is defined in which the cluster C1 of the cell Foo is instantiated with an instance name of I1 and assigned the component reference designator of "U123"; the port instance of port A is assigned the component reference designator of "1".

A cell named Fee is defined in which cluster C1 of the cell Fer is instantiated with an instance name I2. In the design named TOP which has cell Fee as its top-level cell, a designator is back-annotated to I2 as "U42", and a pin number of "2" is assigned to port A.

acLoadDisplay approvedDateDisplay associatedInterconnectNameDisplay cellPropertyDisplayOverride checkDateDisplay clusterPropertyDisplayOverride companyNameDisplay conditionDisplay connectedSignalIndexGeneratorDisplay contractDisplay copyrightDisplay dcFanInLoadDisplay dcFanOutLoadDisplay dcMaxFanInDisplay dcMaxFanOutDisplay designatorDisplay displayAttributes displayName displayNameOverride drawingDescriptionDisplay drawingIdentificationDisplay drawingSizeDisplay engineeringDateDisplay forFrameIndexDisplay indexEndDisplay indexNameDisplay indexStartDisplay indexStepDisplay instanceNameGeneratorDisplay instancePortAttributeDisplay instanceWidthDisplay originalDrawingDateDisplay pageIdentificationDisplay pageTitleBlockAttributeDisplay pageTitleDisplay parameterDisplay parameterNameDisplay pcbDrawingScaleFactorDisplayString pcbDrawingTextDisplay pcbDrawingTitleBlockAttributeDisplay portAttributeDisplay portNameGeneratorDisplay portPropertyDisplayOverride propertyDisplayOverride removeDisplay repetitionCountDisplay revisionDisplay schematicInterconnectAttributeDisplay totalPagesDisplay

Constraints:

1. The following constraint applies to this context: When present within schematicView
Within a schematicView the scaleX and scaleY used to transform a display must have absolute values of 1.

Description:

The display construct is used to indicate a display position for a text string or an attribute.

The transform attribute controls the relative placement, rotation and mirroring of the displayed text or attribute. The origin is specified in the coordinate space of the object in which the text exists.

The height, font and justification are determined by the display attributes within figureGroup or figureGroupOverride.

Example:

(annotate "Something"
   (display 
      (figureGroupOverride Green
         (displayAttributes 
            (verticalJustification (bottomJustify))
            (horizontalJustification (leftJustify)))) 
      (transform (origin (pt 25 30)) 
         (rotation 90))))

In the above example, the string "Something" is displayed in the Green figureGroup. The bottom left of the text is at the x and y coordinates of 25 and 30 units respectively, and the text is rotated counter clockwise by 90 degrees about this point, as shown in the figure below.

displayAttributes

displayAttributes ::= '(' 'displayAttributes'
	{ <borderPattern> | <borderPatternVisible> | <borderWidth> | <color> 
	| <fillPattern> | <fillPatternVisible> | <fontRef> | 
	<horizontalJustification> | <textHeight> | <verticalJustification> | 
	<visible> } 
	')'

Used by:

<figureGroup <figureGroupOverride

Similar Keywords:

display

Description:

DisplayAttributes is used to group together figureGroup attributes that are for display purposes only and do not apply to fabrication.

Text is displayed according to the attribute values in displayAttributes for the figureGroup associated with the display of the text. The figureGroup contains the following attributes within displayAttributes that apply to text: color, fontRef, horizontalJustification, verticalJustification and textHeight. These attributes can be overridden, using figureGroupOverride, e.g. if the size of the text to be displayed is not the same as defined in figureGroup.

To place text in its final position, transform is used. Transform allows scaling, rotation and translation to move the text to its desired origin. Scaling of text is done by first scaling the bounding box. The scaling of the text itself depends on the fonts available in the receiving system. The origin of the text relative to the text itself is specified by horizontalJustification and verticalJustification. Whenever possible, the font size must be chosen in such a way that the text does not extend the transformed bounding box. If this is not possible, the bounding box must be extended in such a way that the original justification is maintained.

The final orientation of the displayed text depends on the text display facilities available in the receiving system. Nevertheless, the sequence of transformations should be maintained.

Example:

(figureGroup small_text
   (displayAttributes 
      (color 0 0 50) 
      (fontRef courier)
      (horizontalJustification (leftJustify))
      (verticalJustification (middleJustify))
      (textHeight 160)) ...)
