nonPermutable ::= '(' 'nonPermutable'
	{ permutable | portRef } 
	')'

*permutable

Constraints:

1. The following constraint applies to this context: All contexts
The number of portRefs used inside permutable or nonPermutable constructs should be equal when they are nested in further permutable or nonPermutable constructs.
(See also similar constraint in: permutable)

2. The following constraint applies to this context: All contexts
A port can be referenced at most once by any permutable or nonPermutable constructs in an interface.
(See also similar constraint in: permutable)

Description:

NonPermutable is used to describe ports or groups of ports which cannot be interchanged. Used in conjunction, the nonPermutable and permutable constructs define a permutability tree structure of ports within the interface. The order of portRefs is significant, as in the schematic below.

In the context of a permutable construct, corresponding ports may be exchanged as a whole or not at all; partial exchanges are not permitted.

nonPermutable schematic

Example:

(permutable
   (nonPermutable (portRef A) (portRef B))
   (nonPermutable (portRef C) (portRef D)))

The example states that the ports A and B are not permutable, and also that the ports C and D are not permutable. However, the ports A and C may be permuted as long as the ports B and D are permuted at the same time. This structure could be appropriate for the previously-illustrated schematic.

occurrenceAnnotate

occurrenceAnnotate ::= '(' 'occurrenceAnnotate'
	( extendInstanceDef | extendInstanceMemberDef )
	{ cellPropertyOverride | clusterPropertyOverride | comment | <designator> 
	| forFrameAnnotate | ifFrameAnnotate | instancePropertyOverride | 
	interconnectAnnotate | leafOccurrenceAnnotate | occurrenceAnnotate | 
	otherwiseFrameAnnotate | pageAnnotate | portAnnotate | property | 
	signalAnnotate | signalGroupAnnotate | timing | viewPropertyOverride } 
	')'

Used by:

*forFrameAnnotate *ifFrameAnnotate *occurrenceAnnotate *occurrenceHierarchyAnnotate *otherwiseFrameAnnotate

Similar Keywords:

annotate

Constraints:

1. The following constraint applies to this context: All contexts
Only one occurrenceAnnotate is allowed per instance within a designHierarchy.

2. The following constraint applies to this context: All contexts
The clusterConfiguration associated in an occurrenceAnnotate must be expandable, i.e. it should not be a leaf configuration or unconfigured.
(See also similar constraint in: clusterConfiguration)

Description:

OccurrenceAnnotate introduces annotation data for an instance, or in the case of a wide instance an instance member, and all of the instances beneath it in the instance (occurrence) hierarchy.

ExtendInstanceDef or extendInstanceMemberDef refers to the instance or instance member to which this annotation applies. This identifies a cluster which is being instantiated. If further annotation is to be given for instances below this one, then nested occurrenceAnnotate or leafOccurrenceAnnotate forms are used to give their annotation. Nested annotation must be consistent with the hierarchy configuration.

Example:

(occurrenceAnnotate hier1
   (leafOccurrenceAnnotate elem1
      (designator "U2")
      (portAnnotate &1 ...
         (designator "11"))
      (portAnnotate &2 ...
         (designator "12"))
      (portAnnotate &3 ...
         (designator "13")))
   (leafOccurrenceAnnotate elem2
      (designator "U2")
      (portAnnotate &1 ...
         (designator "6"))
      (portAnnotate &2 ...
         (designator "7"))
      (portAnnotate &3 ...
         (designator "8"))))

In this example, hier1 is a hierarchical instance. Within the selected view of the cluster instantiated by hier1, there are two instances: elem1 and elem2. Each of these has a designator and port annotation data.

	event
	numberValue
	')'

Used by:

Description:

OffsetEvent is used to define a time relative to an event. A positive number value indicates a time after the specified event. A negative number value indicates a time before the specified event. The number value is the offset time, and is in units defined by setTime.

Example:

(offsetEvent
   (event
      (portRef CK)
      (transition H L))
   (e -48 -1))

This example defines a time 4.8 units before a transition from H to L on port CK.

Origin is used to specify the translation point of an object when it is transformed. Translation of an object is always the last operation performed when transforming an object.

The first example specifies that the symbol is placed so that its origin lies at point (100, 0). 

(annotate "U12"
   (display 
      (figureGroupOverride text 
         (displayAttributes 
            (verticalJustification (bottomJustify))
            (horizontalJustification (leftJustify))))
      (transform (rotation 270)
         (origin (pt 4 6)))))

The second example specifies that the string "U12" is to be displayed such that the lower left of the text (below and left of the "U"), is at point (4, 6).
