integerToken

[ '-' | '+' ] 
digit
{ digit }

Used by:

dayNumber edifLevelValue exponent fromInteger hourNumber *ieeeSection !integerConstant integerExpression integerValue iso8859Part issue *k2Literal mantissa mark minuteNumber monthNumber nonNegativeInteger positiveInteger rowSize scaledInteger secondNumber subIssue toInteger !totalPages *userData yearNumber

Similar Keywords:

integer

Description:

IntegerToken is a basic EDIF token, expressed in normal decimal notation. Its absolute value must be less than 231. IntegerTokens are terminated by whiteSpace, quotation marks, a left or right parenthesis or percent character within encodedCharacter. WhiteSpace must not occur within the token nor after the optional sign.

An integerToken will typically be recognized by a lexical scanner.

Example:

0
123
-456
789
2147483647

This example illustrates five integer tokens. The last one is the maximum-allowed value for an integerToken.

Description:

InterconnectAttachedText is used to attach some text to a point on the graphics of the net or bus. The text may be simple annotation or the display of a property or attribute. The annotation and the property displayed are both attached to the point (pt 200 300) in this example. The display positions are given separately and are typically different from the attachment point.

interconnectDelay

interconnectDelay ::= '(' 'interconnectDelay'
	interconnectDelayNameDef
	derivation
	delay
	{ becomes | transition } 
	')'

Used by:

*interconnectAnnotate *interconnectHeader *schematicInterconnectHeader *schematicSubInterconnectHeader

Similar Keywords:

interconnectDelayDisplay interconnectDelayNameRef

Constraints:

1. The following constraint applies to this context: All contexts
The timeDelay associated with an interconnectDelay should not be negative.

Description:

InterconnectDelay is an attribute of an interconnect which is used to specify a delay for the given set of transitions. If no transition or becomes is specified, then the default is relevant for any transition.

Such a delay is effective between any two ports connected to the interconnect, and acts in addition to any specified port delays.

Example:

(connectivityNet N1 (signalRef SIG1) 
   (interconnectHeader 
      (interconnectDelay
         delay1
         (calculated)
         (delay (e 3 1))
         (transition HS LR)))
   (connectivityNetJoined ...))

The above example specifies a calculated delay of 30 time units when a transition from HS to LR occurs on net N1.

interface

interface ::= '(' 'interface'
	interfaceUnits
	{ booleanParameter | <designator> | integerParameter | interfaceJoined | 
	mustJoin | numberParameter | permutable | port | portBundle | 
	stringParameter | timing | weakJoined } 
	')'

Used by:

!cluster

Constraints:

1. The following constraint applies to this context: All contexts
When a cluster is instantiated each parameter in the interface of the cluster must either have a default value or there should be a parameter assign construct in the instance which assigns a value to it.
(See also similar constraint in: instance)

Description:

The interface defines objects which can be seen, and defines relationships which are true for all views and symbols in the cluster.

Objects include the ports themselves, and the properties and attributes defined in the interface and in the ports. Relationships define which ports of the cell are shorted together (interfaceJoined) and which ports can be interchanged (permutable).

The ports defined in the interface are referred to as master ports in this manual.

Example:

(cell CZ ...
   (cluster CZ
      (interface (interfaceUnits)
         (port A (inputPort))
         (port B (inputPort))
         (port O (outputPort))
         (designator "000")
         (interfaceJoined (portRef A) (portRef B)))
      (clusterHeader (property basic (string "XXX")))
      (connectivityView CZNet ...)
      ...))

The above example specifies the interface of the cluster named CZ of cell CZ. The objects defined include the ports A, B and O, and the designator attribute. The relationship that port A is joined to port B is also specified. The property basic belongs to the cluster.

interfaceJoined

interfaceJoined ::= '(' 'interfaceJoined'
	{ portRef } 
	')'

Used by:

*interface *mustJoin *weakJoined

Constraints:

1. The following constraint applies to this context: All contexts
A port can be referenced at most once by any interfaceJoined, mustJoin or weakJoined constructs in an interface.
(See also similar constraint in: mustJoin, weakJoined)

Description:

InterfaceJoined is used to specify that certain ports are shorted together.

InterfaceJoined may refer only to master ports, i.e. ports defined in the interface. The interfaceJoined may be nested with mustJoin and weakJoined to specify complex relationships between master ports. This relationship forms a tree structure. Within the interface a port may be referenced no more than once in interfaceJoined, mustJoin and weakJoined.

The portRef may refer to ports and not to portBundles.

InterfaceJoined has no influence on how interface ports are joined together when the cluster is instantiated. Thus, two ports that are interfaceJoined may or may not be in the same signal when the cluster is instantiated.

Example:

(interfaceJoined (portRef A) (portRef B))

The first example states that the master ports A and B are connected.
