23 PCB/MCM views

This chapter describes the concept of the PCB/MCM view which describes a printed circuit assembly. The model of the PCB/MCM view can be found in the pcb_mcm_view_model schema. A PCB/MCM view may convey three types of connectivity information. The logical connectivity information describes the electrical functionality that is to be realised by the assembled board. The component connectivity information specifies the components to be used on the assembled board and their interconnections. The physical connectivity describes the component placements on the board and the connections implemented by conductive material.

Figure 23.1 shows the model of the internal_pcb_mcm_view. The logical connectivity information (see section 4.1) is described in terms of instances and signals. The component connectivity information (see sections 23.1 and 23.2) is described in terms of components and component_signals. The physical connectivity is described by defining an assembled_board (see chapter 24) which specifies the placements of components and implementation of component_signals on the board.

Figure 23.1: The model of internal_pcb_mcm_view

23.1 Components

A component is the instantiation of a part (see chapter 19). A component is divided into several categories, depending on the type of the instantiated part. It can be a mechanical_component, a connector_component, an electrical_component or a jumper_component. A mechanical_component is the instantiation of a mechanical_part; a connector_component is the instantiation of a connector_part; an electrical_component is the instantiation of an electrical_part and a jumper_component is the instantiation of a jumper_part. 23.2 Component signals

In a PCB/MCM view, the set of component_signals defines the intended connectivity of an assembled_board (see chapter 24). Each component_signal joins a collection of component_terminals and describes the connection between the terminals of the components in the same PCB/MCM view. A component_terminal is divided into several categories, depending on the type of the referenced component. It can be a connector_component_terminal, a jumper_component_terminal or an electrical_component_terminal. A terminal of an electrical_component is referenced by an electrical_component_terminal which specifies the connected electrical_component and the electrical_part_terminal. The referenced electrical_part_terminal must be defined in the electrical_part from which the electrical_component is instantiated. Similarly, a terminal of a connector_component is referenced by a connector_component_terminal which specifies the connected connector_component and the connector_part_terminal. 23.3 Component function allocations

The logical connectivity and the component connectivity information are related by allocating component functions to instances in the same PCB/MCM view. As shown in figure 23.2, an electrical_component can be either a fully_defined_electrical_component or a minimally_defined_electrical_component. A fully_defined_electrical_component is the instantiation of a fully_defined_electrical_part which contains part_functions. Each fully_defined_electrical_component includes a collection of component_function_allocations, each of which determines the functionality of the instantiated part_function. It is divided into several categories. An allocated_component_function specifies how an instantiated part_function is allocated to an instance defined in the logical connectivity section of the PCB/MCM view. It may include a collection of allocated_component_function_terminals. Each allocated_component_function_terminal describes how terminals of an instantiated part_function are allocated to a port on the allocated instance. An unallocated_component_function specifies that a component function is unallocated. It has a boolean flag indicating whether or not this electrical function can be used for further allocation. An unknown_component_function_allocation specifies that the allocation of a component function is unknown to the sending system. Finally, a post_function_layout specifies that the component function is for a specific purpose and should not be used in allocation. A post_function_layout allocation is available for those electrical components that are added to the component netlist but which have no corresponding functions in the logical connectivity (e.g. pull-up resistors, decoupling capacitors).
