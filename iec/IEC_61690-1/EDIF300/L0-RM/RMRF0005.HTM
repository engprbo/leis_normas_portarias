e

e ::= '(' 'e'
	mantissa
	exponent
	')'

Used by:

scaledInteger

Description:

A scale factor can be applied to an integer to represent fractional numbers or numbers too large to be expressed using an integer alone. The e construct consists of two integer tokens, representing the mantissa and exponent respectively. Its value is the mantissa times ten raised to the power of the exponent. The absolute value of this expression must be equal to zero or lie within the range 10-35 to 1035.

Example:

(e  100  1)
(e  42  0)
(e  9  -1)
(e  -12325  -3)
(e  -644  4)

The above examples represent the values 1000, 42, 0.9, -12.325 and

-6440000 respectively.

See also:

integerValue number

edif

edif ::= '(' 'edif'
	edifNameDef
	edifVersion
	edifHeader
	{ comment | design | external | library | userData } 
	')'

Used by:

$goal

Description:

The edif keyword marks the highest-level structure within the EDIF hierarchy, containing, directly or indirectly, all information transmitted within the file. The corresponding set of matching parentheses delimit that logical file. The initial substructures, edifNameDef, edifVersion, and edifHeader contain the information required to read the file. Subsequent structures embody the actual design data and may occur in any order, subject only to the restriction that all references to any name defined within the file occur after the named construct.

An EDIF file may contain several designs and several libraries (using external and library) of cell definitions. The libraries serve to group relevant design information according to common characteristics. The designs indicate the particular cells within the libraries that convey the top-level, or root, descriptions of the design hierarchies.

Reference to this file cannot be made by name from within the file.

Example:

(edif Prototype
   (edifVersion 3 0 0)
   (edifHeader
      (edifLevel 0)
      (keywordMap (k0KeywordLevel))
      (unitDefinitions ...)
      (fontDefinitions ...)
      (physicalDefaults ...)
      (status ...) ...)
   (external Standard_Cells ...)
   (library VHSIC_CMOS
      (libraryHeader
         (edifLevel 0)
         (nameCaseSensitivity)
         (technology ...) ...)
      (cell B_Shift  ...)  ...)
   (design Barrel_Shifter 
      (cellRef B_Shift (libraryRef VHSIC_CMOS)) ...))

In the example, the file named Prototype contains a design named Barrel_Shifter drawn from the VHSIC_CMOS library. The reference to Barrel_Shifter occurs after the defining occurrence within its library. The file is written in Level 0 EDIF Version 3 0 0 and has no mapped keywords.

See also:

edifLevel edifVersion status

edifHeader

edifHeader ::= '(' 'edifHeader'
	edifLevel
	keywordMap
	unitDefinitions
	fontDefinitions
	physicalDefaults
	{ <characterEncoding> | documentation | <globalPortDefinitions> | 
	<nameCaseSensitivity> | <nameInformation> | <physicalScaling> | 
	property | <status> } 
	')'

Used by:

edif

Description:

EdifHeader collects all data which, by default, applies to the whole EDIF data. This includes information on unit and global port definitions, how stringTokens should be interpreted (characterEncoding), and status information which relates to the entire EDIF data.

Example:

(edifHeader (edifLevel 0)
   (keywordMap (k0KeywordLevel))
   (unitDefinitions ...)
   (fontDefinitions ...)
   (physicalDefaults ...)
   (status ...)
   (characterEncoding (ascii))
   (physicalScaling
      (pcbLayoutUnits (setDistance (unitRef mm)) ...)))

See also:

libraryHeader

edifLevel

edifLevel ::= '(' 'edifLevel'
	edifLevelValue
	')'

Used by:

edifHeader libraryHeader

Description:

EdifLevel tells the reader the greatest EDIF level that could be found when processing the file or library. The integer token, edifLevelValue, may take the value zero or one only.

A Level 0 structure will contain only the most primitive of the EDIF constructs.

At Level 1, schematic frames are introduced and expressions and parameters may be employed to describe the design information.

Example:

(library nMOS_X
   (libraryHeader
      (edifLevel 0)
      (nameCaseSensitivity)
      (technology  ...))
   (cell  ...)
   ...)

The example indicates that the library has been created using Level 0 EDIF constructs.

See also:

edifVersion

edifNameDef

edifNameDef ::= nameDef

Used by:

edif

Description:

An edifNameDef is used to identify the entire EDIF data.

The name defined by the edifNameDef has meaning only outside the EDIF data, where it might be used by external file-handling mechanisms. This occurrence does not serve to define this name within any contained name space. Thus, the name is free for further use within the EDIF data.

edifVersion

edifVersion ::= '(' 'edifVersion'
	mark
	issue
	subIssue
	')'

Used by:

edif

Description:

EdifVersion indicates the version of EDIF used to create the file. The three integers are constrained to be those representing valid EDIF versions as defined by the EDIF Steering Committee. At present, this comprises the following versions: 1 0 0, 1 1 0, 2 0 0, 2 9 0 and 3 0 0. Only the latter is valid for this version.

Example:

    (edifVersion 3 0 0)

The example indicates a file written in the current version of EDIF.

encodedCharacter

'%'
{ integerToken }
'%'

Used by:

stringToken

Description:

EncodedCharacter represents a sequence of characters within a stringToken. The value of each integerToken is interpreted as an ASCII code unless the characterEncoding has been specified in the EDIF header as something other than ascii, in which case it is interpreted as a code in the specified character set. There are no set bounds for the value of the code, although 65535 should be sufficient for all currently-known sets.

WhiteSpace is used within this construct to separate consecutive integer tokens, but it is optional before the first value and after the last value.

None of the special properties associated with various characters (such as quote and percent) should be attributed to these characters. This enables any character from the applicable character set to be explicitly incorporated into a string token.

Example:

"abc%9%defg"

This string represents eight characters. 

"% 8 9 10 13 32 34 37 %"

The second example illustrates a stringToken which represents the characters: back-space, horizontal-tab, line-feed, carriage-return, space, quote and percent, assuming the applicable character set is ASCII.

If 

(characterEncoding (iso8859 1))

had been included in the header, then the string: 

"viele M%246%glichkeiten"

should interpret the %246% sequence as an ö (with an umlaut), so the string represents viele Möglichkeiten.

endType

endType ::= '(' 'endType'
	( truncate | round | extend )
	')'

Used by:

figureGroup figureGroupOverride

Description:

EndType is used to describe the ends of paths and openShapes in figure groups. It may be specified in figureGroup in the technology block of a library. In this case, the end type is the default end type to be used for all path ends in the figure group. EndType may also be specified in figureGroupOverride within the figure itself. In this case, the end type specified is used to override temporarily the default end type.

With extend, the end is extended by half the value of the associated pathWidth. Round ends are terminated with a semicircle centered at the end point with its radius half the value of the pathWidth. The figure ends exactly at the specified end point in the case where endType is truncate.

EndType and cornerType apply to cases in which one or two arcs are used, by using the tangents to those arcs at the point of intersection in the role of the simple center-lines referred to in the above definitions.

The default for endType is truncate.

Example:

(figureGroup METAL
   (endType (extend))
(comment "specifies a default end type of 
         extend"))
...
(figure 
   (figureGroupOverride METAL
      (endType (truncate))
      (comment "override end type with 
         truncate end type"))
   (path ...))

This example illustrates the use of endType to establish a default expansion attribute and to override that attribute within a figure statement.

These figures illustrate an example of each end type.

See also:

cornerType pathWidth

event

event ::= '(' 'event'
	( portRef | portList | portSet | interconnectRef | interconnectSet )
	{ becomes | transition } 
	')'

Used by:

forbiddenEvent offsetEvent pathDelay timeInterval

Description:

Event is used to describe an event on a port or on an interconnect using logic state transitions. Events can also be described for unordered groups of ports or interconnects using portSet or interconnectSet. An ordered list of ports may also be used using a portList. If an ordered list of ports is specified and transitions are also specified, the size of the logic list and the port list must be equal. If no transitions are specified, then the default meaning is any logic state change.

Example:

(event (portRef A) (transition H L))

In the first example, the event described is port A changing from logic state H to logic state L. 

(event (portSet (portRef A) (portRef B)))

In the second example, the event described is any logic state change which occurs on port A or port B. 

(event (portList (portRef A) (portRef B) (portRef C))
   (transition (logicList L H X) (logicList X L H)))

In the third example, the event described is a logic state change from L to X on port A and a logic state change from H to L on port B and a logic state change from X to H on port C. The event is satisfied when the all ports have made the transitions; the event occurs at the time of the last such change. None of the ports should have changed value more than once during the time since just before the first port transition.

See also:

transition becomes

extendInstanceDef

extendInstanceDef ::= instanceNameRef

Used by:

leafOccurrenceAnnotate occurrenceAnnotate

Description:

ExtendInstanceDef references an instance to add additional data or to override existing data.

The additional data specified within the context of an extendInstanceDef must not clash with existing data within the instance referenced. In particular, any nameDefs defined within the scope of an extendInstanceDef must not clash with any nameDefs of the same class already defined within the instance.

ExtendInstanceDef must not be used when the instanceWidth of the instance referenced is greater than one.

extendInstanceMemberDef

extendInstanceMemberDef ::= instanceMemberRef

Used by:

leafOccurrenceAnnotate occurrenceAnnotate

Description:

ExtendInstanceMemberDef references a member of a wide instance to add additional data or to override existing data. The additional data specified within the context of an extendInstanceMemberDef must not clash with existing data within the instance referenced. In particular, any nameDefs defined within the scope of an extendInstanceMemberDef must not clash with any nameDefs of the same class already defined within the instance.

The following are equivalent: 

(occurrenceAnnotate I1 ...)

and 

(occurrenceAnnotate
   (instanceMemberRef I1 (indexValue 0)) ...)

Example:

(instance I1 ...
   (instanceWidth 48) ...)
...
(occurrenceAnnotate
   (instanceMemberRef I1 (indexValue 3)) ...)

In this example, the wide instance I1 has some annotation data applied to it.

extendPortDef

extendPortDef ::= portNameRef

Used by:

Description:

ExtendPortDef references a port to add additional data or to override existing data.

The additional data specified within the context of an extendPortDef must not clash with existing data within the port referenced. In particular, any nameDefs defined within the scope of an extendPortDef must not clash with any nameDefs of the same class already defined within the port.

Example:

(cell A ...
   (cluster C 
      (interface (interfaceUnits ...)
         (port P ... (property PX (integer 1))
            (portDelay PD1 (measured) ...))) ...))
...
(instance I
   (clusterRef C (cellRef A))
   (instancePortAttributes P
      (property PY (boolean (true)))
      (portPropertyOverride PX (integer 2))
      (portDelay PD2 (calculated) ...)))

This example shows that in the context of the port instance P in instance I, the property PX is overridden and a new property, PY is added. A portDelay PD2 is also added. It would have been a semantic error to specify a portDelay PD1 in the instancePortAttributes related to P.

external

external ::= '(' 'external'
	libraryNameDef
	libraryHeader
	{ cell | comment | geometryMacro | pageBorderTemplate | 
	pageTitleBlockTemplate | schematicFigureMacro | 
	schematicGlobalPortTemplate | schematicInterconnectTerminatorTemplate | 
	schematicJunctionTemplate | schematicMasterPortTemplate | 
	schematicOffPageConnectorTemplate | schematicOnPageConnectorTemplate 
	| schematicRipperTemplate | schematicSymbolBorderTemplate | 
	schematicSymbolPortTemplate | userData } 
	')'

Used by:

edif

Description:

External declares a library to which reference is made, but which is not actually present within the current EDIF data. This may include any library which has been exchanged by means outside the current EDIF data.

The structure and semantics of external are parallel to those of library except that external is known to be incomplete; external libraries that are declared contain only minimal information. Any information present, such as status, must agree with the information available in the reader's libraryof the same name. External represents one way in which reference can be made to external information from within an EDIF file. The information represented is sufficient only to support the instantiation or use of the library objects, not to expand them.

External should occur within a file only with prior consent of the intended receiving party, since it must be assumed that the missing library has already been transmitted.

Example:

(external ECL_H
   (libraryHeader (edifLevel 0)
      (nameCaseSensitivity)
      (technology  ...))
   (cell  ...)
   (comment "Access to this library is restricted"))

This example shows the declaration of an external Level 0 library.

See also:

library

figure

figure ::= '(' 'figure'
	( figureGroupNameRef | figureGroupOverride )
	{ circle | comment | complexGeometry | dot | openShape | path | polygon | 
	rectangle | shape | userData } 
	')'

Used by:

commentGraphics diagram pageBorderTemplate pageCommentGraphics pageTitleBlockTemplate schematicBusGraphics schematicFigureMacro schematicGlobalPortTemplate schematicInterconnectTerminatorTemplate schematicJunctionTemplate schematicMasterPortTemplate schematicNetGraphics schematicOffPageConnectorTemplate schematicOnPageConnectorTemplate schematicRipperTemplate schematicSymbol schematicSymbolBorderTemplate schematicSymbolPortTemplate

Description:

A figure is a collection of geometric objects. The figure plays a central role in the geometric views. The figure refers to a set of default characteristics defined in a figureGroup construct. More than one figure statement may refer to the same figureGroup in the same context.

The figure statement identifies the figureGroup into which geometrical figures will be accumulated. The figureGroup must have been previously defined with a figureGroup statement within the context of the same library or external construct.

ComplexGeometry may be used to place a pre-defined set of geometric objects into a figureGroup.

Example:

(figure
   (figureGroupOverride POLY (pathWidth 2))
   (path (pointList (pt 0 0) (pt 0 10))) 
   (path (pointList (pt 5 0) (pt 10 0))))

This example describes two paths, each with a pathWidth of 2 distance units, as shown in the figure below.

See also:

complexGeometry schematicComplexFigure

figureGroup

figureGroup ::= '(' 'figureGroup'
	figureGroupNameDef
	{ comment | <cornerType> | <displayAttributes> | <endType> | 
	<nameInformation> | <pathWidth> | property | userData } 
	')'

Used by:

technology

Description:

FigureGroup allows default figure group attributes to be defined. Such a definition must exist for every collection of geometries referred to within any display or figure statement in the library. The default figure group attributes can be overridden with a figureGroupOverride within a display or figure statement.

Geometry is accumulated into figure groups by later figure statements in the context of cell representations.

FigureGroup attributes relating to display only and not to fabrication are collected within the displayAttributes construct.

In this version only, the units applicable to information in figureGroups are those defined in schematicUnits.

Example:

(figureGroup Metal
   (pathWidth 3))

In this example, the default width for Metal paths is 3 distance units. 

(figure
   (figureGroupOverride Metal
      (pathWidth 5))  ...)

The second example overrides the default width with a value of 5 distance units for the specified figure. 

    (figure Metal (path  ...))

The final figure statement describes a path of width 3, using the defined default value.

See also:

display figure figureGroupOverride library
