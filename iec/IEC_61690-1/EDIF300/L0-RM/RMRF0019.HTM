schematicWireAffinity

schematicWireAffinity ::= '(' 'schematicWireAffinity'
	( narrowWire | wideWire | unrestricted )
	')'

Used by:

hotspot

Description:

SchematicWireAffinity specifies the type of schematic wire that is appropriate for a hotspot. The hotspot is intended to be connected to a schematic interconnect with a corresponding schematicWireStyle. This is not a semantic rule. The default is unrestricted.

See schematicWireStyle for a full example.

See also:

schematicWireStyle

schematicWireStyle

schematicWireStyle ::= '(' 'schematicWireStyle'
	( narrowWire | wideWire )
	')'

Used by:

schematicInterconnectHeader

Description:

SchematicWireStyle indicates the style of schematic wire that is appropriate to represent a particular schematic interconnect.

If schematicWireStyle is specified for an interconnect, then the schematicWireAffinity of any hotspots connected to the schematic interconnect would usually correspond with this, according to the table below.

SchematicWireStyle
Corresponding schematicWireAffinity for
hotspots
narrowWire
narrowWire or unrestricted
wideWire
wideWire or unrestricted

Example:

(schematicMasterPortTemplate A 
   (schematicTemplateHeader ...)
   (hotspot (pt 0 0) 
      (schematicWireAffinity (wideWire)))
   (input)
   (schematicPortStyle (widePort)))
...
(schematicBus B (signalGroupRef ...)
   (schematicInterconnectHeader ...
      (schematicWireStyle (wideWire)) ...)
   (schematicBusJoined ...) ...)

In this example the master port template A could be connected only to schematic interconnects with schematicWireStyle of wideWire, for example the bus B.

See also:

schematicWireAffinity

section

section ::= '(' 'section'
	sectionNameDef
	sectionTitle
	{ diagram | section | stringValue } 
	')'

Used by:

documentation section

Description:

Section is used to divide a document into sections.

Sections may be nested with other sections. This nesting can be used by a document processor to give hierarchical number schemes to sections.

The body of the section is implemented using any number of EDIF strings and diagrams.

The order of items within section is significant.

Example:

(section S1 (sectionTitle "Hierarchical Design")
   (section S1_1 
      (sectionTitle "Why it does not work") 
      "..." ...)
   (section S1_2 
      (sectionTitle "An alternative: Matrix Design")
      ".  .  .  .  "
      (section  S1_2_1
          (sectionTitle 
            "Each circuit has two functions" ) 
         ".  .  .  .  ")
      (section  S1_2_2 
         (sectionTitle "Early results")
         ".  .  .  .  " ...))
   (section S1_3 (sectionTitle "Summary")
        ".  .  .  .  "))

sequence

sequence ::= '(' 'sequence'
	fromInteger
	toInteger
	{ <step> } 
	')'

Used by:

nameDimensionStructure

Description:

Sequence is used to specify a range of integer values that start at fromInteger and end at toInteger, and are incremented up or down by the absolute value of the integerValue given by step. There must be an integer "k" for which toInteger equals fromInteger plus or minus "k" multiplied by the absolute value of integerValue in step.

Example:

(sequence 3 5)

This defines the series of integers 3, 4, 5. 

(sequence 3 18 (step 5))

This defines the series of integers 3, 8, 13, 18. 

(sequence 7 3 (step -2))

Here the ordered range of integers 7, 5 and 3 is specified. 

(sequence 7 3 (step 2))

Just as in the previous example, here the ordered range of integers 7, 5 and 3 is specified.

See also:

bitOrder complementedName complexName integerValue simpleName

shape

shape ::= '(' 'shape'
	curve
	')'

Used by:

figure geometryMacro

Description:

Shape is similar to polygon, except that it may include arcs in its perimeter. Shape is closed by definition. If the last point specified is not the same as the first point specified, a straight line is used to close the shape.

The shape must not touch or intersect itself, although its edges may be coincident.

Example:

(shape
   (curve
      (pt 20 100)
      (arc
         (pt 40 100)
         (numberPoint 50 110)
         (pt 40 120))
      (pt 20 120)))

This example consists of one arc from (40, 100) through (50, 110) to (40, 120), and three straight line segments: from (40, 120) to (20, 120), from (20, 120) back to (20, 100), and from (20, 100) to (40, 100). This is shown in the figure below, assuming hollow filled.

See also:

arc openShape polygon

signal

signal ::= '(' 'signal'
	signalNameDef
	signalJoined
	{ <nameInformation> | property } 
	')'

Used by:

logicalConnectivity

Description:

A signal is a named object which lists ALL the ports, master, instance and global, which are electrically common at a given level of hierarchy. A signal definition applies to an entire view.

A signal is always one bit wide in Level 0.

The signals define all the connectivity at a given level of hierarchy within a view.

Example:

(signal SIG1 
   (signalJoined 
      (portRef MP1) 
      (portInstanceRef P1 (instanceRef I1))))

In this example, the signal SIG1 joins the master port MP1 and the port P1 of instance I1.

signalGroup

signalGroup ::= '(' 'signalGroup'
	signalGroupNameDef
	signalList
	{ <nameInformation> | property } 
	')'

Used by:

logicalConnectivity

Description:

A signalGroup is a named object which provides a grouping mechanism for signals. This provides a basis for the structured connectivity established by busses by allowing a hierarchical grouping mechanism for signals.

A signalGroup does not establish connectivity; it has no signalJoined.

A signalGroup is defined in terms of an ordered list of one or more signals or signalGroups. No two signalGroups may have the same list of members, although when flattened, two signalGroups may possibly resolve to the same ordered list of signals. Thus, different signalGroups will have different structure.

A signalGroup has a width that is equal to the sum of the widths of its constituent members.

The same signal or signal group may be referenced in the signalList of more than one signalGroup.

The same signal or signal group may be referenced more than once in a single signalGroup definition.

SignalGroups define their structure in terms of the signals and signalGroups that they reference. This structure is independent of the port ordering or port structure.

Example:

(signal OP_0 ...)
(signal OP_1 ...)
(signal OP_2 ...)
(signal OP_3 ...)
(signalGroup OP_0_1 
   (signalList (signalRef OP_0) (signalRef OP_1)))
(signalGroup OP_2_3 
   (signalList (signalRef OP_2) (signalRef OP_3)))
(signalGroup OP 
   (signalList (signalRef OP_0_1) (signalRef OP_2_3)))

In this example, four signals are defined and then grouped. The first two, OP_0 and OP_1, are grouped into one signalGroup, OP_0_1. The second two, OP_2 and OP_3, are grouped into another signalGroup, OP_2_3. Finally a signalGroup OP is defined as a grouping of the previously-defined signalGroups OP_0_1 and OP_2_3.

See also:

signal

signalJoined

signalJoined ::= '(' 'signalJoined'
	{ globalPortRef | portInstanceRef | portRef } 
	')'

Used by:

signal

Description:

SignalJoined defines the set of all master ports and instance ports that are electrically connected together to form a signal. The ports referenced must not be portBundles or globalPortBundles.

No instance port, master port or global port may be referenced by more than one signalJoined within the context of a logicalConnectivity.

Example:

(signal SIG1 
   (signalJoined 
      (portRef MP1) 
      (portInstanceRef P1 (instanceRef I1))))

In this example, the signalJoined specifies that the signal SIG1 joins the master port MP1 and the port P1 of instance I1.

See also:
