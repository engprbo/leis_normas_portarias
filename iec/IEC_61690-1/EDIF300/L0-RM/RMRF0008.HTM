instance

instance ::= '(' 'instance'
	instanceNameDef
	clusterRef
	{ cellPropertyOverride | clusterPropertyOverride | comment | <designator> 
	| instancePortAttributes | <instanceWidth> | <nameInformation> | property 
	| timing | userData } 
	')'

Used by:

logicalConnectivity

Description:

Instance allows a cluster to be referenced within a view of another cell to create the instance hierarchy of a design.

An instance of a cluster means that some mechanism is required to select from that cluster the view which is most appropriate. The configuration of views applicable to a particular design can be specified using clusterConfiguration.

The representation of the instance in a page is achieved by using the construct schematicInstanceImplementation, which selects, in the case of a schematic page, a schematic symbol from the referenced cluster.

In the context of instance, cellRef is required within clusterRef.

The instanceWidth attribute can be used to indicate that the instance is wide. In the context of a schematic view, the wide instance is represented by a single implementation. An object connected to a port of an instance of width greater than one will follow this rule:

Let N equal the product of instance width and the instance port/portBundle width divided by the connecting bus/net width. In level 0, N may be either equal to the instance width, or to one; other values are a semantic error.

A full description of the logical connectivity for these two conditions can be found in the Information Model.

If instanceWidth is greater than one, all attributes of the instance apply equally to each member of the set. This includes properties, instancePortAttributes, propertyOverrides, but excludes nameInformation, which applies to the wide instance as whole.

Example:

(instance nand12 
   (clusterRef C1 (cellRef nand)) ...)

The above example describes an instance named nand12 of the cluster named C1 of the cell named nand.

See also:

schematicInstanceImplementation

instanceConfiguration

instanceConfiguration ::= '(' 'instanceConfiguration'
	instanceNameRef
	clusterConfigurationRef
	')'

Used by:

clusterConfiguration

Description:

InstanceConfiguration selects a configuration for a particular instance in a view. This is done by referencing a clusterConfiguration within the cluster of the instance referenced by instanceNameRef. Therefore, the name referenced by clusterConfigurationRef must exist in the cluster instantiated by the instance named instanceNameRef.

It is not mandatory to specify an instanceConfiguration for each instance. During the specification of configuration, if an instance has no associated instanceConfiguration, the default cluster configuration of its instantiated cluster is assumed.

If the referenced instance has an instanceWidth greater than one, the configuration applies to all member instances equally.

Example:

(instanceConfiguration BLOCK1
   (clusterConfigurationRef CONFIG1))

See also:

design defaultClusterConfiguration

   (instanceRef nand12)
   (schematicSymbolRef symbol)
   (transform ...)

      (portAttributeDisplay
         (designatorDisplay 
            (addDisplay
               (display TEXT 
                  (transform (origin (pt 10 20))))))
      )))

In this example, instancePortAttributeDisplay is used to change the position in which the designator is displayed for the port P1 in instance I1.

instancePortAttributes

instancePortAttributes ::= '(' 'instancePortAttributes'
	extendPortDef
	{ <acLoad> | comment | <designator> | 
	<directionalPortAttributeOverride> | portDelay | portDelayOverride | 
	portLoadDelay | portLoadDelayOverride | portPropertyOverride | property | 
	<unused> } 
	')'

Used by:

instance

Description:

InstancePortAttributes is used to attach or modify properties and attributes of the occurrence of a port within an instance. InstancePortAttributes refers to the port instance and not the port definition in the cell cluster.

The port instance inherits all inheritable properties and attributes of the port in the instantiated cluster. When the properties are inherited and not fixed, the values may be overridden within instancePortAttributes for this particular instance. Attribute values may also be overridden, e.g. acLoad given in instancePortAttributes overrides the value (if any) given on the port.

The directionalPortAttributeOverride must match the portDirection of the original port. Direction specific attributes may be overridden within this construct.

These properties and attributes may be displayed using instancePortAttributeDisplay.

Within the context of any one instance, each extendPortDef must be unique.

Example:

(cell LS04 ...
   (cluster C1 
      (interface (interfaceUnits ...)
         (designator "UXXX")
         (port in (inputPort)
            (designator "XX"))
         (port out (outputPort)
            (designator "QQ")))
      (clusterHeader ...)
      (schematicSymbol primary_symbol 
         ...)))
(cell Top_level_schematic ...
   (cluster C1
      (interface ...) ...
      (schematicView schematic_sheet
         (schematicViewHeader ...)
         (logicalConnectivity
            (instance &1
               (clusterRef C1 (cellRef LS04))
               (designator "U1")
               (instancePortAttributes in
                  (designator "1"))
               (instancePortAttributes out
                  (designator "2"))) ...)
         (schematicImplementation..))))

In this example, a cluster C1 of cell LS04 will be created in every case with designator "UXXX" and with pin designators "XX" and "QQ", unless these lower-level designators are overridden by higher-level designators, such as those that appear in instance 1. In this instance, and only this instance, the designators are specified to be "U1" with pins "1" and "2".

See also:

port portAnnotate instancePortAttributeDisplay

integerToken

[ '-' | '+' ]
digit
{ digit }

Used by:

dayNumber edifLevelValue exponent fromInteger hourNumber ieeeSection indexValue instanceWidth integerValue iso8859Part issue k2Literal mantissa mark minuteNumber monthNumber rowSize scaledInteger secondNumber subIssue toInteger totalPages userData yearNumber

Description:

IntegerToken is a basic EDIF token, expressed in normal decimal notation. Its absolute value must be less than 231. IntegerTokens are terminated by whiteSpace, quotation marks, a left or right parenthesis or percent character within encodedCharacter. WhiteSpace must not occur within the token nor after the optional sign.

An integerToken will typically be recognized by a lexical scanner.

Example:

0
123
-456
789
2147483647

This example illustrates five integer tokens. The last one is the maximum-allowed value for an integerToken.

See also:

identifier stringToken whiteSpace

interconnectAttachedText

interconnectAttachedText ::= '(' 'interconnectAttachedText'
	attachmentPoint
	{ annotate | <criticalityDisplay> | interconnectDelayDisplay | 
	<interconnectNameDisplay> | interconnectPropertyDisplay } 
	')'

Used by:

schematicInterconnectAttributeDisplay

Description:

InterconnectAttachedText is used to attach some text to a point on the graphics of the net or bus. The text may be simple annotation or the display of a property or attribute. The attachment point must be a specified point within the graphics of the net or bus, though not necessarily at the same level in the nested hierarchy of a net, subnet, bus, subbus or bus slice.

The display positions are relative to (0,0) and not relative to the attachment point.

Example:

(interconnectAttachedText (pt 200 300)
   (annotate "See note 3" (display ...))
   (interconnectPropertyDisplay route_width 
      (display ...)))

The annotation and the property displayed are both attached to the point (pt 200 300) in this example. The display positions are given separately and are typically different from the attachment point.

See also:

display

interconnectDelay

interconnectDelay ::= '(' 'interconnectDelay'
	interconnectDelayNameDef
	derivation
	delay
	{ becomes | transition } 
	')'

Used by:

interconnectAnnotate interconnectHeader schematicInterconnectHeader schematicSubInterconnectHeader

Description:

InterconnectDelay is an attribute of an interconnect which is used to specify a delay for the given set of transitions. If no transition or becomes is specified, then the default is relevant for any transition.

Such a delay is effective between any two ports connected to the interconnect, and acts in addition to any specified port delays.

The timeValue within delay in this context must not be negative.

Example:

(connectivityNet N1 (signalRef SIG1) 
   (interconnectHeader 
      (interconnectDelay
         delay1
         (calculated)
         (delay (e 3 1))
         (transition HS LR)))
   (connectivityNetJoined ...))

The above example specifies a calculated delay of 30 time units when a transition from HS to LR occurs on net N1.

      (schematicBusJoined ...)
      (schematicInterconnectAttributeDisplay

               (transform 
                  (origin (pt 110 200)))))) ...))
