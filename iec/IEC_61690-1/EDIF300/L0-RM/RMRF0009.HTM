interconnectRef

interconnectRef ::= '(' 'interconnectRef'
	interconnectNameRef
	[ pageRef ]
	')'

Used by:

event interconnectSet

Description:

InterconnectRef is used to reference an interconnect.

Example:

(interconnectRef AN1
   (pageRef P))

The first example illustrates a reference to an interconnect named AN1, which is defined within a page named P.

interface

interface ::= '(' 'interface'
	interfaceUnits
	{ <designator> | interfaceJoined | mustJoin | permutable | port | portBundle 
	| timing | weakJoined } 
	')'

Used by:

cluster

Description:

The interface defines objects which can be seen, and defines relationships which are true for all views and symbols in the cluster.

Objects include the ports themselves, and the properties and attributes defined in the interface and in the ports. Relationships define which ports of the cell are shorted together (interfaceJoined)and which ports can be interchanged (permutable).

The ports defined in the interface are referred to as master ports in this manual.

Example:

(cell CZ ...
   (cluster CZ
      (interface (interfaceUnits)
         (port A (inputPort))
         (port B (inputPort))
         (port O (outputPort))
         (designator "000")
         (interfaceJoined (portRef A) (portRef B)))
      (clusterHeader (property basic (string "XXX")))
      (connectivityView CZNet ...)
...))

The above example specifies the interface of the cluster named CZ of cell CZ. The objects defined include the ports A, B and O, and the designator attribute. The relationship that port A is joined to port B is also specified. The property basic belongs to the cluster.

See also:

cell instance

interfaceJoined

interfaceJoined ::= '(' 'interfaceJoined'
	{ portRef } 
	')'

Used by:

interface mustJoin weakJoined

Description:

InterfaceJoined is used to specify that certain ports are shorted together.

InterfaceJoined may refer only to master ports, i.e. ports defined in the interface. The interfaceJoined may be nested with mustJoin and weakJoined to specify complex relationships between master ports. This relationship forms a tree structure. Within the interface a port may be referenced no more than once in interfaceJoined, mustJoin and weakJoined.

The portRef may refer to ports and not to portBundles.

InterfaceJoined has no influence on how interface ports are joined together when the cluster is instantiated. Thus, two ports that are interfaceJoined may or may not be in the same signal when the cluster is instantiated.

Example:

(interfaceJoined (portRef A) (portRef B))

The first example states that the master ports A and B are connected.

See also:

connectivityNetJoined connectivityBusJoined schematicNetJoined schematicBusJoined

iso8859

iso8859 ::= '(' 'iso8859'
	iso8859Part
	')'

Used by:

characterEncoding

Description:

Iso8859 is used to indicate that characters within % delimiters in strings are encoded using the ISO 8859 standard.

The ISO 8859 standard has 8 parts. Each one is a complete description of an 8-bit word, with graphical representations for the 256 codes possible. All the ISO 8859 standards are built around ANSI X3.4-1986. In other words, the ISO 8859 character sets build on the ASCII codes. In all cases, the ISO character sets define a set of characters whose most-significant bit is set, and relegate the ASCII characters to their values with the 8th, i.e. most-significant bit, set to zero.

Example:

(characterEncoding (iso8859 5))

Specifies that the codes in quoted strings represent characters in the ISO 8859-5 character set (Part 5: Latin/Cyrillic alphabet).

See also:

ascii encodedCharacter jisx0201 jisx0208

iso8859Part

iso8859Part ::= integerToken

Used by:

iso8859

Description:

Iso8859Part is an integer with minimum value 1 and maximum value 8. The numeric value represents the part of ISO 8859. These are listed below:

Part 1: Latin Alphabet No. 1 - Applicable to many countries

Part 2: Latin Alphabet No. 2 - Characters for Albanian, Czech, English, German, Hungarian, Polish, Rumanian, Serbocroatian, Slovak, and Slovene.

Part 3: Latin Alphabet No. 3 - Afrikaans, Catalan, Dutch, English, Esperanto, German, Italian, Maltese, Spanish, and Turkish.

Part 4: Latin Alphabet No. 4 - Danish, English, Estonian, Finnish, German, Greenlandic, Lappish, Latvian, Lithuanian, Swedish, and Norwegian.

Part 5: Latin/Cyrillic Alphabet

Part 6: Latin/Arabic Alphabet

Part 7: Latin/Greek Alphabet

Part 8: Latin/Hebrew Alphabet

See also:

ascii jisx0201 jisx0208

isolated

isolated ::= '(' 'isolated'
	')'

Used by:

logicValue

Description:

Isolated is an attribute of a logic value and is used to indicate the logic value which is used for isolated or undriven interconnects, i.e. those without any source. There may be only one logicValue which contains isolated in a logicDefinitions construct.

Example:

(logicDefinitions ...
   (logicValue T)
   (logicValue F)
   (logicValue Z (isolated)))

This defines a logic value Z and declares that it is the isolated value.

jisx0201

jisx0201 ::= '(' 'jisx0201'
	')'

Used by:

characterEncoding

Description:

The JIS (Japanese Industrial Standard) includes JIS X 0201, JIS X 0208 and others. Jisx0201 is used to indicate the standard JIS X 0201.

JIS X 0201 presents an 8-bit standard that encodes the normal ASCII printing characters in their normal positions, with the 8th and most-significant bit set to zero. There are two exceptions: \ (backslash) is replaced by the Yen sign, and ~ (tilde) is replaced by an overbar, much like the _ (underscore) character, but made to go at the top of the character. The part of the code with the most-significant bit set to one describes an analog of the ASCII set with 33 codes left undefined, analogs of the control characters and space of ASCII, and the Katakana characters following.

Using JIS X 201 does not preclude embedding 16-bit JIS X 0208 characters in the strings. Readers understanding JIS X 0201 characters may wish to observe the escape sequences that would embed JIS X 0208 characters in the string.

See also:

jisx0208 ascii iso8859

Description:

The JIS (Japanese Industrial Standard) includes JIS X 0201, JIS X 0208, and others. Jisx0208 is used to indicate the standard JIS X 0208.

JIS X 0208 is a 16-bit character set. Within it, are defined a set of graphics characters, mathematical-notation characters, the Latin character set capitalized and small, the numbers 0-8, a Katakana set, a Hiragana set, a (big) Kanji set with Greek (upper and lower case), and Cyrillic (upper and lower case).

k2Actual

k2Actual ::= '(' 'k2Actual'
	k2FormalNameRef
	')'

Used by:

k2Build k2Generate k2Optional k3Build k3ForEach k3Generate

Description:

K2Actual generates the actual token or form that corresponds in position within the use of the keyword being defined, to the formal parameter definition within the k2KeywordDefine or k3KeywordDefine form. If the k2Formal parameter is bound to several forms, the k2Actual expands to several forms, unless it is used within a k3ForEach statement which references the same formal parameter.

Example:

    (k2KeywordDefine EG
        (k2KeywordParameters
            (k2Formal layer (k2Required))
             ...)
        (k2Generate
            (k2Build figure
                (k2Actual layer)
                 ...) ) )

See also:

k2Formal k3Formal

k2Build

k2Build ::= '(' 'k2Build'
	k1KeywordNameRef
	{ comment | k2Actual | k2Build | k2Literal } 
	')'

Used by:

k2Build k2Generate k2Optional k3Generate

Description:

K2Build is used within the context of a k2KeywordDefine to generate non- primitive output. It contains a k1KeywordNameRef, which is the name of an existing or previously-defined keyword. K2Build expands into a formwith k1KeywordNameRef as its keyword, and each component of the k2Build replaced by the result of generating the enclosed constructs in the order specified. The enclosed comments generate nothing, but provide documentation about the purpose or use of the new keyword definition

K2Build may nest to create nested output forms.

Example:

(k2KeywordDefine REV
   (k2KeywordParameters
      (k2Formal A (k2Required)) 
      (k2Formal B (k2Required)))
   (k2Generate
      (k2Build PT
         (k2Actual B) (k2Actual A))))

See also:

k3Build

k2Formal

k2Formal ::= '(' 'k2Formal'
	k2FormalNameDef
	( k2Optional | k2Required )
	')'

Used by:

k2KeywordParameters

Description:

This construct is used to specify a formal parameter for use with the k2KeywordParameters section of a k2KeywordDefine form. These formalparameters will be substituted for positionally, by actual parameter values, in subsequent invocation of the defined keyword. The k2Optional form allows the use of formal parameters; these need not be included in every use of the new keyword. Any k2Formal parameter following a k2Optional parameter must also be a k2Optional.

Example:

(k2KeywordDefine wait
   (k2KeywordParameters
      (k2Formal load_time (k2Optional (k2Literal 5)))
      (k2Formal load_capacitance
         (k2Optional (k2Literal 1))))
   (k2Generate
      (k2Build loadDelay
         (k2Actual load_time)
         (k2Actual load_capacitance))))

This keyword definition creates a loadDelay construct. If the load value is not specified, the default value of 5 is used. A later use such as (wait 10) or (wait 15 20) would be legal in any context in which loadDelay is legal. These are equivalent to (loadDelay 5 1) and (loadDelay 20 1) respectively.

See also:

k3Formal

k2Generate

k2Generate ::= '(' 'k2Generate'
	{ comment | k2Actual | k2Build | k2Literal } 
	')'

Used by:

k2KeywordDefine

Description:

K2Generate is used to specify the expansion of a form which references a defined keyword at keyword level k2 or higher. Since this construct contains an arbitrary number of builders, the use of a k2KeywordDefine can generate more than one formIn such cases it should not be used as a positional item within the enclosing construct.

Example:

(k2KeywordDefine polyFigure
   (k2KeywordParameters (k2Formal figure (k2Required)))
   (k2Generate
      (k2Build figure
         (k2Literal POLY)
         (k2Actual figure))))

See also:

k3Generate

k2KeywordDefine

k2KeywordDefine ::= '(' 'k2KeywordDefine'
	k1KeywordNameDef
	k2KeywordParameters
	k2Generate
	')'

Used by:

k2KeywordLevel

Description:

The k2KeywordDefine construct provides the capability in EDIF of defining new keywords in terms of existing ones. It is intended to act as a reasonably powerful method of abbreviating EDIF descriptions using a general method which could be resolved in a pre-processing input step. Keywords have to be defined within keywordMap at the top level of the EDIF data, i.e. they cannot be defined inside a design or library, or anywhere other than a keywordMap.

In the above syntax, k1KeywordNameDef is an identifier which is being defined to be a keyword, k2KeywordParameters is a construct that defines all arguments to be passed to the k2KeywordDefine, and k2Generate is a construct that specifies what the k2KeywordDefine form will generate when processed. The defined keyword is not available for use until after the end of the k2KeywordDefine statement. Existing keyword names may not be redefined with this construct.

Example:

(k2KeywordDefine rev
   (k2KeywordParameters
      (k2Formal a (k2Required)) 
      (k2Formal b (k2Required)))
   (k2Generate
      (k2Build pt
         (k2Actual b) (k2Actual a))))

This example defines a new keyword rev in terms of the native keyword pt. A subsequent use such as (rev 1 2) should be interpreted in the same way as its expansion (pt 2 1).

See also:

k3KeywordDefine

k2KeywordParameters

k2KeywordParameters ::= '(' 'k2KeywordParameters'
	{ k2Formal } 
	')'

Used by:

k2KeywordDefine

Description:

K2KeywordParameters contains a list of formal parameters which should correspond to individual forms or tokens at the time of expansion of a use of the new keyword.

If any of the enclosed k2Formal parameters are optional then any subsequent k2Formal parameters must also be optional.

Example:

(k2KeywordDefine EG
   (k2KeywordParameters
      (k2Formal a (k2Required)) 
      (k2Formal b (k2Required)))
   (k2Generate
      (k2Build pt (k2Actual a) (k2Actual b))))

This keyword definition shown in this example will generate the EDIF construct pt with values supplied by a and b. This shows the explicit definition of a keyword EG which has the same effect as a k1KeywordAlias for pt.

See also:

k3KeywordParameters

k2Optional

k2Optional ::= '(' 'k2Optional'
	( k2Literal | k2Actual | k2Build )
	')'

Used by:

k2Formal k3Formal

Description:

K2Optional may appear within a k2Formal or k3Formal keyword parameter definition. It allows the use of formal parameters which need not be included in every use of a defined keyword. It contains the default value for its parameter. The default can be a literal value, the actual value of a parameter specified previously in the construct, or the result of building a formThe default value should generate a single token or form.

A k2Optional parameter may only be followed by further k2Optional parameters in the same list of k2KeywordParameters or k3KeywordParameters.

Example:

(k2KeywordDefine wait
   (k2KeywordParameters
      (k2Formal load (k2Required))
      (k2Formal load_capacitance
         (k2Optional (k2Literal 1))))
   (k2Generate
      (k2Build loadDelay
         (k2Actual load)
         (k2Actual load_capacitance))))

See also:

k2KeywordParameters k3KeywordParameters
