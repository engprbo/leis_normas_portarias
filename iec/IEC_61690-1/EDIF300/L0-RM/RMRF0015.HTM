previousVersion

previousVersion ::= '(' 'previousVersion'
	viewRef
	{ <reason> } 
	')'

Used by:

connectivityViewHeader schematicSymbolHeader schematicViewHeader

Description:

PreviousVersion is used to indicate that a view is a new version of another view. PreviousVersion specifies the view that represents the previous version of this view. The view from which this is derived must come from the same cell, i.e. there must be no cellRef within the viewRef.

The view referenced by viewRef must be of the same type as the view containing previousVersion.

Example:

(cluster C1
   (interface ...)
   (clusterHeader)
   (schematicView SCHEMATIC_0 ...)
   (schematicView SCHEMATIC 
      (schematicViewHeader
         (schematicUnits)
         (previousVersion 
            (viewRef SCHEMATIC_0)
            ))
      ...))

In this example, the view SCHEMATIC is a new version of the view SCHEMATIC_0.

See also:

derivedFrom

primaryName

primaryName ::= '(' 'primaryName'
	originalName
	{ <displayName> | <generated> | <nameStructure> } 
	')'

Used by:

nameInformation

Description:

The originalName within primaryName is the basic name of the object in the source system. The other information within primaryName provides additional data about the name in the originating system.

The originalName within primaryName is the name the source system recommends the target system to use for the object being defined.

Alternative names or aliases may be given using nameAlias.

Example:

(signal S1 (signalJoined ...)
   (nameInformation 
      (primaryName "BusA0"
         (displayName "BusA"))) ...)

In this example, the signal with EDIF identifier S1 has a primaryName BusA0.

See also:

nameAlias

property

property ::= '(' 'property'
	propertyNameDef
	( typedValue | untyped )
	{ comment | <nameInformation> | <owner> | property | 
	<propertyInheritanceControl> | <unitRef> } 
	')'

Used by:

cellHeader clusterConfiguration clusterHeader connectivityViewHeader designHeader designHierarchyHeader edifHeader figureGroup font geometryMacroHeader globalPort globalPortBundle instance instancePortAttributes interconnectAnnotate interconnectHeader leafOccurrenceAnnotate libraryHeader localPortGroup logicValue occurrenceAnnotate pageHeader pageTitleBlock port portAnnotate portBundle property schematicInterconnectHeader schematicOffPageConnectorImplementation schematicOnPageConnectorImplementation schematicRipperImplementation schematicSubInterconnectHeader schematicSymbolHeader schematicTemplateHeader schematicViewHeader signal signalAnnotate signalGroup signalGroupAnnotate timing viewGroupHeader

Description:

Property is used to associate name value pairs with EDIF objects. The property definition is referenced by propertyNameRef. Its type and value are specified by the boolean, integer, miNoMax, number, point, or string typedValue constructs.

The optional owner is used to indicate the owner or originator of the property type and its definition. The optional unitRef may be used to describe the units of the property so that the property values may be scaled. Properties can be nested to describe complex structures. Properties cannot be defined as arrays.

Property values may be overridden using propertyOverride.

Example:

(property xyz (integer 2))

The above example gives an integer property named xyz the value 2. 

(property abc (untyped)
   (property a (boolean (true)))
   (property b (integer 2))
   (property c (string "This is property abc")))

In the above example, the nested property abc is defined with three subproperties.

See also:

boolean integer miNoMax number point propertyDisplay propertyOverride string userData

propertyDisplay

propertyDisplay ::= '(' 'propertyDisplay'
	propertyNameRef
	{ display | <propertyNameDisplay> } 
	')'

Used by:

Description:

PropertyDisplay is used to specify display locations and display attributes for the display of property values. There may be no more than one for each property.

The value to display is referenced by a propertyNameRef. This refers to a property of the same object as that containing the propertyDisplay construct.

Used in commentGraphics, it refers to a property of the object containing the commentGraphics.

Example:

(page P1 (pageHeader .. (property P1 ...) ...)
   (propertyDisplay P1 (display ...))
      ...)

In the above example, the value of the page property named P1 is to be displayed on the page.

See also:

propertyDisplayOverride

propertyDisplayOverride

propertyDisplayOverride ::= '(' 'propertyDisplayOverride'
	propertyNameRef
	( addDisplay | replaceDisplay | removeDisplay )
	{ <propertyNameDisplay> } 
	')'

Used by:

pageBorder pageTitleBlock schematicComplexFigure schematicGlobalPortImplementation schematicInstanceImplementation schematicInterconnectTerminatorImplementation schematicJunctionImplementation schematicMasterPortImplementation schematicOffPageConnectorImplementation schematicOnPageConnectorImplementation schematicRipperImplementation schematicSymbolBorder schematicSymbolPortImplementation

Description:

PropertyDisplayOverride is used to override a propertyDisplay defined in a template. If propertyDisplayOverride is present in an implementation of a template, then there must be a propertyDisplay for that property within the template.

The original propertyDisplay is effectively supplemented (using addDisplay), replaced (using replaceDisplay) or removed (using removeDisplay) in the implementation with the display data given in the propertyDisplayOverride. There may be no more than one for each property.

Example:

(schematicGlobalPortTemplate GROUND_SYMBOL
   (schematicTemplateHeader 
      (schematicUnits ...)
      (property GPTP ...) ...)
   (hotspot (pt 0 0))
   (figure LINES ...)
   (propertyDisplay GPTP 
      (display TEXT 
         (transform (origin (pt 100 200)))))
   )
...
(cell Top_level_schematic (cellHeader ...)
   (cluster C1
      (interface ...)
      (clusterHeader ...)
      (schematicView schematic_sheet
         (schematicViewHeader ...)
         (logicalConnectivity
            ...
            (signal N1
               (signalJoined 
                  (globalPortRef ...) ...) ...))
         (schematicImplementation
            (page &1 (pageHeader ...)
               (schematicGlobalPortImplementation &1
                  (schematicGlobalPortTemplateRef 
                     GROUND_SYMBOL)
                  (globalPortRef ...)
                  (transform (origin (pt 1000 1000)))
                  (propertyDisplayOverride GPTP
                     (replaceDisplay
                        (display TEXT 
                        (transform 
                        (origin (pt 1300 1400)))))))
            )))))

In this example, the property GPTP belonging to the global port template GROUND_SYMBOL will be displayed at (pt 1300 1400) in the page and not at (pt 1100 1200). Note that the position (pt 100 200) is relative to the origin of the template, and was subject to transformation by the transform in the implementation.

See also:

propertyOverride

propertyOverride ::= '(' 'propertyOverride'
	propertyNameRef
	( typedValue | untyped )
	{ comment | <fixed> | propertyOverride } 
	')'

Used by:

cellPropertyOverride clusterPropertyOverride figureGroupOverride instancePropertyOverride interconnectAnnotate pageBorder pageTitleBlock portPropertyOverride propertyOverride schematicComplexFigure schematicGlobalPortImplementation schematicInstanceImplementation schematicInterconnectTerminatorImplementation schematicJunctionImplementation schematicMasterPortImplementation schematicOffPageConnectorImplementation schematicOnPageConnectorImplementation schematicRipperImplementation schematicSymbolBorder schematicSymbolPortImplementation signalAnnotate signalGroupAnnotate viewPropertyOverride

Description:

PropertyOverride is used to override the value of a property on instantiation, back annotation or other appropriate positions. The property overridden must always be present on the object, it must be of the same type as the typedValue in propertyOverride and it must not have a fixed or notInherited form in it.

It is appropriate to be able to specify fixed for a propertyOverride because this is used to prevent further propertyOverrides being applied at a later stage, e.g. in annotation.

It is not possible to override part of a property using nested propertyOverride; the whole property is always overridden.

Example:

(signal SIG1 (signalJoined ...)
   (property P1
         (string "ABCD")) ...)
...
(occurrenceAnnotate  I1
   (signalAnnotate SIG1
      (propertyOverride P1 (string "PQRS"))))

In this example, the property P1 belonging to signal SIG1 is overridden with a new value in the signalAnnotate form.

See also:

pt

pt ::= '(' 'pt'
	xCoordinate
	yCoordinate
	')'

Used by:

pointValue

Description:

Pt is used to specify the coordinates of all geometric data such as line drawings and filled areas. It is also used to specify locations when transforming objects such as symbols and text.The first integerValue, xCoordinate, is the x-location, and the second integerValue, yCoordinate, is the y-location of the point.

Coordinates are scaled between views according to units defined by setDistance.

Example:

(pt 100 50)

This example specifies a point which is 100 units to the right of the coordinate origin and 50 units above it.

resolves

resolves ::= '(' 'resolves'
	{ logicNameRef } 
	')'

Used by:

logicValue

Description:

Resolves is used by logicValue in logicDefinitions to define the current logic value as the outcome when the specified logic values are in contention on a net. When used to indicate the result of contention between two sources of the same value, this overrides the default condition of self-domination.

Example:

(logicValue X
   (resolves T F))

In this example, a net that has the logic values T and F applied to it will take on the logic value of X.

See also:
