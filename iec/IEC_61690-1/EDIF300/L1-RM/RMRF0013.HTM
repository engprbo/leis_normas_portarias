libraryRef

libraryRef ::= '(' 'libraryRef'
	libraryNameRef
	')'

Used by:

cellRef geometryMacroRef logicRef pageBorderTemplateRef pageTitleBlockTemplateRef schematicFigureMacroRef schematicForFrameBorderTemplateRef schematicGlobalPortTemplateRef schematicIfFrameBorderTemplateRef schematicInterconnectTerminatorTemplateRef schematicJunctionTemplateRef schematicMasterPortTemplateRef schematicOffPageConnectorTemplateRef schematicOnPageConnectorTemplateRef schematicOtherwiseFrameBorderTemplateRef schematicRipperTemplateRef schematicSymbolBorderTemplateRef schematicSymbolPortTemplateRef

Description:

LibraryRef contains a reference to the name of a library that is defined in the EDIF data using either external or library. This is used in cellRef to qualify a cell as belonging to a particular library, and to qualify a reference to a template. It is also used in logicRef to reference defined logic values.

Example:

(design ALU_32
   (cellRef ALU_CMOS_32
      (libraryRef CMOS2M)) ...)

This example refers to a cell named ALU_CMOS_32 in the library named CMOS2M. This library should have been defined earlier in the EDIF file using either the library or external constructs. The libraryRef is required in this context since the design form is not in the context of a library.

See also:

design external instance library viewRef

loadDelay

loadDelay ::= '(' 'loadDelay'
	acLoadFactorTime
	acLoadFactorCapacitance
	')'

Used by:

portLoadDelay portLoadDelayOverride

Description:

LoadDelay is used to specify a delay in propagating a signal. AcLoadFactorTime and acLoadFactorCapacitance specify the amount of delay per load capacitance as specified by the acLoad on each of the ports connected to the driving port. None of these values may be negative. AcLoadFactorCapacitance will typically be 1.

Example:

(loadDelay (e 2 -1) 1)

The first example describes a load-dependent delay of 0.2 time units per unit load capacitance. 

(port P1 (bidirectionalPort)
   (portDelay PD1 (measured) (delay 25))
   (portLoadDelay PLD1 (measured)
      (loadDelay 2 1)
      (transition D U)))

The second example specifies a measured delay of 25 time units plus 2 time units per unit acLoad of load-dependent delay. This occurs on a transition from D to U of the port named P1.

See also:

acLoad delay setTime setCapacitance

localPortGroup

localPortGroup ::= '(' 'localPortGroup'
	localPortGroupNameDef
	portList
	{ comment | <nameInformation> | property | userData } 
	')'

Used by:

connectivityStructure page

Description:

LocalPortGroup provides a mechanism to describe structured ports which have not been defined in the interface, but which are required to support structural connectivity. LocalPortGroup is a structuring mechanism only and does not itself define the ports or modify the interface in any way. A localPortGroup may be referenced, for example, from schematicMasterPortImplementation.

A localPortGroup is defined as an ordered list of master ports and master port bundles, described in portList. There must be at least two portRefs in the portList. PortList may only reference master ports and master port bundles and not other localPortGroups.

A port or portBundle may be directly referenced by zero or more localPortGroups in the same page or connectivityStructure. A localPortGroup may not reference a port or portBundle more than once, either directly or indirectly.

It is not permitted to form a localPortGroup whose portList is identical to the portList of an existing portBundle. However, it is permitted to form two localPortGroups that have identical portLists.

Example:

...
(interface
   (interfaceUnits)
   (port a ...)
   (port b0 ...)
   (port b1 ...)
   (port b2 ...)
   (port b3 ...)
   (port b4 ...)
   ...
   (port b31 ...)
   (portBundle B_BUN
      (portList
         (portRef b0)
         (portRef b1)
         (portRef b2)
         ...
         (portRef b30)
         (portRef b31)))...)
...
(schematicImplementation
   (page P1
      (pageHeader ...)
      ...
      (localPortGroup tempGroup
         (portList
            (portRef a)
            (portRef b2)
            (portRef b3)))
      ...
      (schematicMasterPortImplementation PIN3
         (schematicMasterPortTemplateRef INPORT
            (libraryRef SCHEMLIB))
         (localPortGroupRef tempGroup)
            (transform ...)...)...)...)

In this example the interface contains the port a, ports b0 through b31 and a portBundle B_BUN grouping b0 through b31. The schematicMasterPortImplementation references ports a, b2 and b3. This local grouping is represented by a localPortGroup.

See also:

schematicMasterPortImplementation

logicalConnectivity

logicalConnectivity ::= '(' 'logicalConnectivity'
	{ comment | forFrame | ifFrame | instance | otherwiseFrame | signal | 
	signalGroup | userData } 
	')'

Used by:

connectivityView forFrame ifFrame otherwiseFrame schematicView

Description:

LogicalConnectivity defines all the instances in a view and specifies how the master ports, instance ports and global ports are connected together into signals. It also describes the grouping of signals into signalGroups.

The logicalConnectivity construct provides a simple but complete description of the interconnection of ports at a given level of hierarchy. Details of how this connectivity is achieved are given in the implementation of each view, e.g. schematicImplementation for schematicView.

All connectivity within a structural connectivity section must also be represented within logicalConnectivity.

Example:

(logicalConnectivity
   (instance I1 
      (clusterRef C1 (cellRef INVERTER)))
   (instance I2 
      (clusterRef C1 (cellRef INVERTER)))
   ...
   (signal SIG1
      (signalJoined 
         (portInstanceRef IN (instanceRef I1))
         (portRef INPUT)))
   (signal SIG2
      (signalJoined 
         (portInstanceRef OUT (instanceRef I1))
         (portInstanceRef IN (instanceRef I2))))
   (signal SIG3
      (signalJoined 
         (portInstanceRef OUT (instanceRef I2))
         (portRef OUTPUT)))
   ...)

In this example, two instances of an inverter are connected together and to the INPUT and OUTPUT master ports.

See also:

connectivityStructure

logicDefinitions

logicDefinitions ::= '(' 'logicDefinitions'
	setVoltage
	setCurrent
	{ comment | logicValue } 
	')'

Used by:

technology

Description:

All information about the logic values used within a library are collected in logicDefinitions, including relationships of ambiguity and wired functions. Mappings between the logic values of different libraries can also be given, as well as the electrical characteristics associated with each value.

Each logic value used within a library must be declared within the corresponding logicDefinitions. It is advisable to supply as much information as possible in order to assist in mapping into external simulation values.

Example:

(logicDefinitions
   (setVoltage (unitRef mV))
   (setCurrent (unitRef uA))
   (logicValue T)
   (logicValue F))

This example shows a simple declaration of a pair of logic values and the units for voltage and current associated with logicDefinitions.

See also:

booleanMap currentMap logicValue voltageMap

logicMapInput

logicMapInput ::= '(' 'logicMapInput'
	{ logicRef } 
	')'

Used by:

logicValue

Description:

LogicMapInput is used in logicValue in logicDefinitions to map the present logic value to a value or values being input to the models in the present library from models in previously-defined libraries. This construct is appropriate when models from multiple libraries or technologies are used during the same simulation.

Example:

(logicValue T
   (logicMapInput (logicRef HI (libraryRef Blib))))

The above example describes that when the value HI is received from a model in library Blib, it should be treated as the local logic value T.

See also:

logicMapOutput logicDefinitions

logicMapOutput

logicMapOutput ::= '(' 'logicMapOutput'
	{ logicRef } 
	')'

Used by:

logicValue

Description:

LogicMapOutput is used in logicValue in logicDefinitions to map the present logic value to a value or values being output to models in a previously-defined library or libraries. There should be no more than one logic reference for each such library. This construct is appropriate when models from multiple libraries or technologies are used during the same simulation.

Example:

(logicValue ST
   (logicMapOutput (logicRef HI (libraryRef Blib))))

The above example describes that the local logic value ST maps to the logic value HI in the library Blib.

See also:

logicMapInput logicDefinitions

logicOneOf

logicOneOf ::= '(' 'logicOneOf'
	{ logicList | logicNameRef } 
	')'

Used by:

becomes logicList presentLogicValue previousLogicValue

Description:

LogicOneOf supplies a list of alternative logic values or logic lists. Where logicList is used, the sizes of the logicLists must all be equal. When used, any match in logicOneOf is considered as a match for the containing construct. It may thus act as a specific "don't care" condition.

Example:

(logicList A B C (logicOneOf D E F))

This expression indicates a list A, B, C, (D or E or F). 


(logicOneOf
   (logicList A B C D)
   (logicList A B C E)
   (logicList A B C F))

The second expression indicates a list which is one of three lists: (A, B, C, D), (A, B, C, E), or (A, B, C, F). The two examples are therefore equivalent.

See also:

compound ignore

logicValue

logicValue ::= '(' 'logicValue'
	logicNameDef
	{ <booleanMap> | comment | <compound> | <currentMap> | 
	<dominates> | <isolated> | <logicMapInput> | <logicMapOutput> | 
	<nameInformation> | property | resolves | <strong> | <voltageMap> | 
	<weak> } 
	')'

Used by:

logicDefinitions

Description:

LogicValue is used within logicDefinitions to define a logic value to use for modeling in the logicModelView. A value can be specified by name and also by specifying the characteristics of the value. The characteristics can be electrical, boolean, relational between other logic values, and relational between logic values specified in previously-defined libraries.

Example:

(logicValue ST
   (voltageMap (mnm 25 48 50)) 
   (currentMap (mnm 10 15 20))
   (booleanMap (true))
   (strong T) 
   (dominates T Z WT WF)
   (logicMapOutput (logicRef HI (libraryRef MyLib))))

This example defines a logic value ST, giving explicit electrical and boolean mappings and wiring contention information.

See also:

isolated logicRef

lsbToMsb

lsbToMsb ::= '(' 'lsbToMsb'
	')'

Used by:

bitOrder

Description:

LsbToMsb specifies that the bit order is from the least-significant bit to the most-significant bit.

Example:

(nameInformation
   (primaryName "a[5:1:-2]"
      (nameStructure
         (complexName "a"
            (nameDimension
               (nameDimensionStructure
                  (sequence 5 1 (step 2)))
               (bitOrder (lsbToMsb)))))))

Here, the one-dimensional object "a" is specified to be a three-bit object with bit 5 being the least significant and bit 1 being the most significant.

See also:

minimumStringLength

minimumStringLength ::= '(' 'minimumStringLength'
	substringLength
	')'

Used by:

decimalToString

Description:

Specifies the minimum number of characters in the string which holds the result of the decimalToString construct. If the result from decimalToString is too short to fill this string, the result is right justified, with the unfilled locations zero-filled.

Example:

(decimalToString 25
   (minimumStringLength 5))

The above example returns "00025" (three zeros followed by 25). 

(decimalToString 137
   (minimumStringLength 2))

The above example returns "137", which is longer than the specified minimum string length.

See also:

stringLength
