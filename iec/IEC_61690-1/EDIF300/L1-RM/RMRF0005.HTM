directionalPortAttributeOverride

directionalPortAttributeOverride ::= '(' 'directionalPortAttributeOverride'
	( inputPortAttributes | outputPortAttributes | bidirectionalPortAttributes )
	')'

Used by:

instancePortAttributes portAnnotate

Description:

DirectionalPortAttributeOverride overrides port attributes for a port of a particular direction. The portDirection of the port whose attributes are being overridden must correspond with the construct within directionalPortAttributeOverride, e.g. for a port with portDirection specified as inputPort, the construct within directionalPortAttributeOverride must be inputPortAttributes.

Example:

(directionalPortAttributeOverride  
   (bidirectionalPortAttributes
      (dcFanInLoad ...)))

In this example, the dcFanInLoad of a bidirectional port is overridden.

See also:

portDirection

display

display ::= '(' 'display'
	( figureGroupNameRef | figureGroupOverride )
	transform
	')'

Used by:

addDisplay annotate cellNameDisplay cellPropertyDisplay clusterPropertyDisplay connectivityTagGeneratorDisplay criticalityDisplay globalPortNameDisplay globalPortPropertyDisplay hotspotNameDisplay implementationNameDisplay instanceNameDisplay instancePropertyDisplay interconnectDelayDisplay interconnectNameDisplay interconnectPropertyDisplay pagePropertyDisplay portDelayDisplay portLoadDelayDisplay portNameDisplay portPropertyDisplay propertyDisplay propertyNameDisplay replaceDisplay timingDisplay viewNameDisplay viewPropertyDisplay

Description:

The display construct is used to indicate a display position for a text string or an attribute.

The transform attribute controls the relative placement, rotation and mirroring of the displayed text or attribute. The origin is specified in the coordinate space of the object in which the text exists.

The height, font and justification are determined by the display attributes within figureGroup or figureGroupOverride. Hence, in the context of schematicView, scaleX and scaleY within display must have absolute values of 1.

Example:

(annotate "Something"
   (display 
      (figureGroupOverride Green
         (displayAttributes 
            (verticalJustification (bottomJustify))
            (horizontalJustification (leftJustify)))) 
      (transform (origin (pt 25 30)) 
         (rotation 90))))

In the above example, the string "Something" is displayed in the Green figureGroup. The bottom left of the text is at the x and y coordinates of 25 and 30 units respectively, and the text is rotated counter clockwise by 90 degrees about this point, as shown in the figure below.

See also:

figureGroupOverride textHeight figureGroup

displayAttributes

displayAttributes ::= '(' 'displayAttributes'
	{ <borderPattern> | <borderPatternVisible> | <borderWidth> | <color> 
	| <fillPattern> | <fillPatternVisible> | <fontRef> | 
	<horizontalJustification> | <textHeight> | <verticalJustification> | 
	<visible> } 
	')'

Used by:

figureGroup figureGroupOverride

Description:

DisplayAttributes is used to group together figureGroup attributes that are for display purposes only and do not apply to fabrication.

Text is displayed according to the attribute values in displayAttributes for the figureGroup associated with the display of the text. The figureGroup contains the following attributes within displayAttributes that apply to text: color, fontRef, horizontalJustification, verticalJustification and textHeight. These attributes can be overridden, using figureGroupOverride, e.g. if the size of the text to be displayed is not the same as defined in figureGroup.

To place text in its final position, transform is used. Transform allows scaling, rotation and translation to move the text to its desired origin. Scaling of text is done by first scaling the bounding box. The scaling of the text itself depends on the fonts available in the receiving system. The origin of the text relative to the text itself is specified by horizontalJustification and verticalJustification. Whenever possible, the font size must be chosen in such a way that the text does not extend the transformed bounding box. If this is not possible, the bounding box must be extended in such a way that the original justification is maintained.

The final orientation of the displayed text depends on the text display facilities available in the receiving system. Nevertheless, the sequence of transformations should be maintained.

Example:

(figureGroup small_text
   (displayAttributes 
      (color 0 0 50) 
      (fontRef courier)
      (horizontalJustification (leftJustify))
      (verticalJustification (middleJustify))
      (textHeight 160)) ...)

See also:

display

	')'

Description:

The displayName of an object is a string displayed on the source system which gives a visual name to the object. This may not be the actual name used internally in the source system for referencing the object.

Example:

This example specifies that when the name of the port is to be displayed, the string "port1" should be used.

displayNameOverride

displayNameOverride ::= '(' 'displayNameOverride'
	stringToken
	( addDisplay | replaceDisplay | removeDisplay )
	')'

Used by:

cellNameDisplay globalPortNameDisplay hotspotNameDisplay implementationNameDisplay instanceNameDisplay interconnectNameDisplay portNameDisplay propertyNameDisplay viewNameDisplay

Description:

DisplayNameOverride is used when a name is to be displayed and there is a requirement to override the default for the display name. To determine the name that is to be displayed in any particular situation, the following order of preference is used:

1. DisplayNameOverride

2. DisplayName within primaryName

3. NameStructure within primaryName is used to construct a name in a system-dependent manner.

4. OriginalName within primaryName

5. The EDIF identifier, with any leading '&' removed.

Example:

(cell &4
   (cellHeader 
      (nameInformation  (primaryName "04")) ...) ..)
...
(cellNameDisplay
   (display TEXT (transform (origin (pt 100 200))))
   (displayNameOverride "LS04" 
      (addDisplay
      (display TEXT (transform (origin (pt 120 200))))))
   (displayNameOverride "Cell: LS04"
      (addDisplay
      (display TEXT (transform (origin (pt 130 200))))))
   )

In this example, the cell name, 4, is displayed at (pt 100 200), the string LS04 is displayed at (pt 120 200) and the string Cell: LS04 is displayed at (pt 130 200).

See also:

displayName

dominates

dominates ::= '(' 'dominates'
	{ logicNameRef } 
	')'

Used by:

logicValue

Description:

Dominates is an attribute of a logic value used to specify the outcome of interconnect contention when the logic value being defined is one of the values in contention when on an interconnect. Dominates specifies that the logic value being defined will be the logic value seen when it is applied to an interconnect at the same time as any of the other specified values.

Unless overridden by an explicit resolves statement, each logic value should be taken to dominate itself, i.e. if an interconnect is driven multiple times by the same logic value, the result is that same logic value.

Example:

    (logicValue T
        (dominates WT Z WF))

In the above example, if T and WT, Z, or WF are applied to a net at the same time, the net will take on the value of T.

See also:

resolves logicDefinitions strong weak

e

e ::= '(' 'e'
	mantissa
	exponent
	')'

Used by:

scaledInteger

Description:

A scale factor can be applied to an integer to represent fractional numbers or numbers too large to be expressed using an integer alone. The e construct consists of two integer tokens, representing the mantissa and exponent respectively. Its value is the mantissa times ten raised to the power of the exponent. The absolute value of this expression must be equal to zero or lie within the range 10-35 to 1035.

Example:

(e  100  1)
(e  42  0)
(e  9  -1)
(e  -12325  -3)
(e  -644  4)

The above examples represent the values 1000, 42, 0.9, -12.325 and

-6440000 respectively.

See also:

integerValue number

edif

edif ::= '(' 'edif'
	edifNameDef
	edifVersion
	edifHeader
	{ comment | design | external | library | userData } 
	')'

Used by:

$goal

Description:

The edif keyword marks the highest-level structure within the EDIF hierarchy, containing, directly or indirectly, all information transmitted within the file. The corresponding set of matching parentheses delimit that logical file. The initial substructures, edifNameDef, edifVersion, and edifHeader contain the information required to read the file. Subsequent structures embody the actual design data and may occur in any order, subject only to the restriction that all references to any name defined within the file occur after the named construct.

An EDIF file may contain several designs and several libraries (using external and library) of cell definitions. The libraries serve to group relevant design information according to common characteristics. The designs indicate the particular cells within the libraries that convey the top-level, or root, descriptions of the design hierarchies.

Reference to this file cannot be made by name from within the file.

Example:

(edif Prototype
   (edifVersion 3 0 0)
   (edifHeader
      (edifLevel 0)
      (keywordMap (k0KeywordLevel))
      (unitDefinitions ...)
      (fontDefinitions ...)
      (physicalDefaults ...)
      (status ...) ...)
   (external Standard_Cells ...)
   (library VHSIC_CMOS
      (libraryHeader
         (edifLevel 0)
         (nameCaseSensitivity)
         (technology ...) ...)
      (cell B_Shift  ...)  ...)
   (design Barrel_Shifter 
      (cellRef B_Shift (libraryRef VHSIC_CMOS)) ...))

In the example, the file named Prototype contains a design named Barrel_Shifter drawn from the VHSIC_CMOS library. The reference to Barrel_Shifter occurs after the defining occurrence within its library. The file is written in Level 0 EDIF Version 3 0 0 and has no mapped keywords.

See also:

edifLevel edifVersion status

edifLevel

edifLevel ::= '(' 'edifLevel'
	edifLevelValue
	')'

Used by:

edifHeader libraryHeader

Description:

EdifLevel tells the reader the greatest EDIF level that could be found when processing the file or library. The integer token, edifLevelValue, may take the value zero or one only.

A Level 0 structure will contain only the most primitive of the EDIF constructs.

At Level 1, schematic frames are introduced and expressions and parameters may be employed to describe the design information.

Example:

(library nMOS_X
   (libraryHeader
      (edifLevel 0)
      (nameCaseSensitivity)
      (technology  ...))
   (cell  ...)
   ...)

The example indicates that the library has been created using Level 0 EDIF constructs.

See also:

edifVersion

encodedCharacter

'%'
{ integerToken }
'%'

Used by:

stringToken

Description:

EncodedCharacter represents a sequence of characters within a stringToken. The value of each integerToken is interpreted as an ASCII code unless the characterEncoding has been specified in the EDIF header as something other than ascii, in which case it is interpreted as a code in the specified character set. There are no set bounds for the value of the code, although 65535 should be sufficient for all currently-known sets.

WhiteSpace is used within this construct to separate consecutive integer tokens, but it is optional before the first value and after the last value.

None of the special properties associated with various characters (such as quote and percent) should be attributed to these characters. This enables any character from the applicable character set to be explicitly incorporated into a string token.

Example:

"abc%9%defg"

This string represents eight characters. 

"% 8 9 10 13 32 34 37 %"

The second example illustrates a stringToken which represents the characters: back-space, horizontal-tab, line-feed, carriage-return, space, quote and percent, assuming the applicable character set is ASCII.

If 

(characterEncoding (iso8859 1))

had been included in the header, then the string: 

"viele M%246%glichkeiten"

should interpret the %246% sequence as an ö (with an umlaut), so the string represents viele Möglichkeiten.
