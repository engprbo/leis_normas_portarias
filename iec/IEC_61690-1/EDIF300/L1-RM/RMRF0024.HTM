stringEqual

stringEqual ::= '(' 'stringEqual'
	firstStringExpression
	secondStringExpression
	')'

Used by:

booleanExpression

Description:

This booleanExpression evaluates to true if the two stringExpressions are equal strings. Case is significant to the string comparison.

Example:

(condition
   (stringEqual  
      (stringParameterRef processType)
      "cmos1u"))

In this example, the condition is satisfied only if processType has the value "cmos1u".

stringParameter

stringParameter ::= '(' 'stringParameter'
	parameterNameDef
	{ <nameInformation> | <string> } 
	')'

Used by:

interface

Description:

Defines a stringParameter and optionally specifies its default value. ParameterNameDef may be referenced by a corresponding parameterNameRef in string expressions within the containing cluster, including in subsequent parameter definitions. The parameter may be assigned a new value using stringParameterAssign.

If no default is specified there must be a corresponding parameter assignment in all instances of the containing cluster. The parameter is used during expansion of the design hierarchy only.

Example:

(stringParameter TCmembers 
   (string "Hilary, Jonathan, Laurence, Rachel, Rich, Robin, Steve"))

stringPrefix

stringPrefix ::= '(' 'stringPrefix'
	stringExpression
	substringLength
	')'

Used by:

stringExpression

Description:

This returns a specified number of characters from the beginning (left hand side) of stringExpression The number of characters to return, and hence the length of the result is specified by substringLength.

If substringLength is greater than the number of characters in stringExpression, the value of stringExpression is returned. In this case, the number of characters in the stringExpression is also unchanged.

If substringLength is less than or equal to zero, the empty string ("") is returned.

Note that for any string s, the following expression always returns s:

(stringConcatenate
(stringPrefix s n)
(stringSuffix s n))

Example:

(stringPrefix "abcdef" 4)

The above example yields "abcd".

See also:

stringConcatenate stringSuffix substring

stringSuffix

stringSuffix ::= '(' 'stringSuffix'
	stringExpression
	substringOffset
	')'

Used by:

stringExpression

Description:

This returns a number of characters from the end (right hand side) of stringExpression. The offset (i.e. the number of characters to ignore) from the left hand side of stringExpression is specified by substringOffset.

If substringOffset is greater than the number of characters in stringExpression, the empty string ("") is returned.

If substringOffset is less than or equal to zero, the entire stringExpression is returned.

Example:

(stringSuffix "abcde" 2)

The above example yields "cde". 

(stringSuffix "abcde" 0)

The above example yields "abcde". 

(stringSuffix "abcde" 6)

The above example yields "".

See also:

stringConcatenate stringPrefix substring

stringToken

'"'
{ alpha | encodedCharacter | digit | specialCharacter | whiteSpace }
'"'

Used by:

author comment companyName contract copyright dataOrigin displayName displayNameOverride drawingDescription drawingIdentification drawingSize fontFamily ieeeDesignation k2Literal namePartSeparator originalName pageIdentification pageTitle reason revision sectionTitle simpleName stringConstant stringExpression stringValue typefaceSuffix userData

Description:

This is a basic token type and is described as a sequence of printable characters surrounded by quotation marks. This is normally recognized by a lexical scanner.

A space or tab character represents itself within string tokens; other white space characters (newline and carriage return) are ignored. The quote and percent characters cannot be specified directly, but may be represented using the encodedCharacter notation.

There is no limit to the length of a stringToken.

Example:

"a string token"
"quote% 34 %character"
""

This example illustrates three string tokens. The first is typical, the second contains an embedded description of quote character, and the third is a null string.

See also:

encodedCharacter identifier integerToken specialCharacter

strong

strong ::= '(' 'strong'
	logicNameRef
	')'

Used by:

logicValue

Description:

Strong is an attribute of a logic value which is used to indicate that the current logic value is stronger than the referenced logic value. Strong also implies that the present logic value dominates the referenced value.

Example:

(logicDefinitions ...
   (logicValue F)
   (logicValue T
      (dominates F))
   ...
   (logicValue ST
      (strong T)))

The above example states that the logic value ST is stronger than the logic value T.

substring

substring ::= '(' 'substring'
	stringExpression
	substringLength
	substringOffset
	')'

Used by:

stringExpression

Description:

This evaluates to a substring of stringExpression. SubstringLength specifies the length of the substring. The offset (i.e. the number of characters to ignore) from the left hand side of stringExpression is specified by substringOffset.

For (substring S L F), if S has a string length N, then:

1. If F >= N, substring returns "".

2. If L <= 0, substring returns "".

3. If F + L > N, substring returns all the characters from the offset position, and the string returned has a length equal to N - F.

Note that the following two constructs are equivalent:

(substring string length offset)

(stringPrefix (stringSuffix string offset) length)

Example:

(substring "abcdefg" 4 2 )

This yields "cdef".

See also:

technology

technology ::= '(' 'technology'
	physicalScaling
	{ comment | figureGroup | <logicDefinitions> | userData } 
	')'

Used by:

libraryHeader

Description:

The technology construct contains the information related to the intended implementation of the library. The description applies to every object of the library. The technology block is required for every library. It includes scaling information, definitions of the figure groups, and the default figure group attributes, and simulation information. PhysicalScaling is required to ensure that scaling information is defined before any values which may need to be scaled.

Example:

(library LIB1
   (libraryHeader (edifLevel 0)
      (nameCaseSensitivity  ...)
      (technology
         (physicalScaling
            (pcbLayoutUnits
               (setDistance (unitRef micron))))
         (figureGroup FG1  ...)
         (figureGroup FG2   ...) ...))  ...)

In the above example, the technology block defines the scaling and figure group defaults for the library named LIB1.

See also:

unitDefinitions

textHeight

textHeight ::= '(' 'textHeight'
	lengthValue
	')'

Used by:

displayAttributes schematicRequiredDefaults

Description:

TextHeight is used to express the height of text in a figure group.

TextHeight may be specified within figureGroup in the technology block of a library. In this case, the text height is the default text height value to be used for text in the figure group. TextHeight may also be specified in the figureGroupOverride within a display. In this case, the text height value is used to override the default text height value for a single display.

Example:

(setDistance (unitRef mm))
...
(figureGroup TextDisplay
   (displayAttributes (textHeight 8) ...) ...)

The first example in a technology construct defines a default text height of 8 mm. 


(display
   (figureGroupOverride TextDisplay
      (displayAttributes (textHeight 15))) 
   (transform ...))

The second example overrides the default text height with a value of 15 mm for this display.

See also:

display fontRef horizontalJustification setDistance verticalJustification

timeInterval

timeInterval ::= '(' 'timeInterval'
	( event | offsetEvent )
	( event | offsetEvent | duration )
	')'

Used by:

forbiddenEvent

Description:

TimeInterval is used to describe an interval between two times. Times can be described by events or offset events. The first construct gives the beginning of the time interval. The second construct gives the end of the time interval, or its duration.

A duration can be used instead of the second event to specify explicitly the length of the interval.

Example:

(timeInterval
   (event (portRef A) (transition I O))
   (duration 17))

In the first example, the time interval described is from the time when port A changes from I to O, to a time 17 time units after the event. Both the event time, and the point 17 time units after, are included in the window. 

(timeInterval
   (event (portRef ENA) (transition H L))
   (offsetEvent
      (event (portRef P1) (becomes Z))
      (e 14 -1)))

In the second example, the time interval is from the time when port ENA changes from H to L, to 1.4 time units after the port P1 next becomes Z.

See also:

duration event offsetEvent

timeStamp

timeStamp ::= '(' 'timeStamp'
	date
	time
	')'

Used by:

written

Description:

The timeStamp identifies the time in Universal Time Coordinated when the data was created or last modified. The year includes the century. If part of a file is created and then modified, a new written with a new timeStamp may be inserted to indicate this. TimeStamp is required in written.

Example:

(status
   (written
      (timeStamp (date 1986 12 31) 
         (time 23 59 59))))

The above status indicates that the associated data was created or modified on December 31st 1986 at 23:59:59 UTC.

See also:

status

timing

timing ::= '(' 'timing'
	timingNameDef
	derivation
	{ comment | forbiddenEvent | pathDelay | property | userData } 
	')'

Used by:

connectivityFrameStructure connectivityStructure instance interface occurrenceAnnotate occurrenceHierarchyAnnotate

Description:

Timing is used to provide a set of path delays or simulation timing constraints (forbidden events). It is named so that it may be referenced from timingDisplay. Derivation indicates whether the value is calculated, measured or a required value.

Example:

(timing T1 (calculated)
   (pathDelay
      (delay (mnm (e 18 -1) (e 37 -1) (e 84 -1)))
      (event (portRef CK) (transition L H))
      (event (portRef Q) (transition L H)))
   (forbiddenEvent
      (timeInterval
         (offsetEvent (event (portRef CK) 
            (transition H L)) (e -48 -1))
         (duration (e 72 -1)))
      (event (portRef D))))

This example describes a calculated path delay from port CK to port Q, with a logic transition from L to H. The delay required has a minimum value of 1.8 time units, a nominal value of 3.7 time units, and a maximum value of 8.4 time units.

The forbiddenEvent statement requires that port D is stable for at least 4.8 time units before a falling (H to L) transition of CK, and remains stable for at least 2.4 time units after the CK transition, giving a stability requirement of 7.2 time units.

See also:

timingDisplay
