occurrenceAnnotate

occurrenceAnnotate ::= '(' 'occurrenceAnnotate'
	( extendInstanceDef | extendInstanceMemberDef )
	{ cellPropertyOverride | clusterPropertyOverride | comment | <designator> 
	| forFrameAnnotate | ifFrameAnnotate | instancePropertyOverride | 
	interconnectAnnotate | leafOccurrenceAnnotate | occurrenceAnnotate | 
	otherwiseFrameAnnotate | pageAnnotate | portAnnotate | property | 
	signalAnnotate | signalGroupAnnotate | timing | viewPropertyOverride } 
	')'

Used by:

forFrameAnnotate ifFrameAnnotate occurrenceAnnotate occurrenceHierarchyAnnotate otherwiseFrameAnnotate

Description:

OccurrenceAnnotate introduces annotation data for an instance, or in the case of a wide instance an instance member, and all of the instances beneath it in the instance (occurrence) hierarchy.

ExtendInstanceDef or extendInstanceMemberDef refers to the instance or instance member to which this annotation applies. This identifies a cluster which is being instantiated. If further annotation is to be given for instances below this one, then nested occurrenceAnnotate or leafOccurrenceAnnotate forms are used to give their annotation. Nested annotation must be consistent with the hierarchy configuration.

Only one occurrenceAnnotate is allowed per instance.

Example:

(occurrenceAnnotate hier1
   (leafOccurrenceAnnotate elem1
      (designator "U2")
      (portAnnotate &1 ...
         (designator "11"))
      (portAnnotate &2 ...
         (designator "12"))
      (portAnnotate &3 ...
         (designator "13")))
   (leafOccurrenceAnnotate elem2
      (designator "U2")
      (portAnnotate &1 ...
         (designator "6"))
      (portAnnotate &2 ...
         (designator "7"))
      (portAnnotate &3 ...
         (designator "8"))))

In this example, hier1 is a hierarchical instance. Within the selected view of the cluster instantiated by hier1, there are two instances: elem1 and elem2. Each of these has a designator and port annotation data.

See also:

design

occurrenceHierarchyAnnotate

occurrenceHierarchyAnnotate ::= '(' 'occurrenceHierarchyAnnotate'
	{ cellPropertyOverride | clusterPropertyOverride | comment | 
	forFrameAnnotate | ifFrameAnnotate | interconnectAnnotate | 
	leafOccurrenceAnnotate | occurrenceAnnotate | otherwiseFrameAnnotate | 
	pageAnnotate | portAnnotate | signalAnnotate | signalGroupAnnotate | timing 
	| viewPropertyOverride } 
	')'

Used by:

designHierarchy

Description:

OccurrenceHierarchyAnnotate provides a set of annotation for an occurrence hierarchy. It provides overriding properties for the top view in the occurrence hierarchy tree and further annotation data for instances below this are provided using occurrenceAnnotate and leafOccurrenceAnnotate.

Example:

(design TOP
   (cellRef Fee ...) 
   (designHeader ...)
   (designHierarchy H1
      (clusterRef C1)
      (clusterConfigurationRef CONFIG1)
      (designHierarchyHeader ...)
      (occurrenceHierarchyAnnotate 
         (occurrenceAnnotate  I2
            (designator "U42")
            (portAnnotate A
            ... (designator "2"))))))

See also:

design

offsetEvent

offsetEvent ::= '(' 'offsetEvent'
	event
	numberValue
	')'

Used by:

timeInterval

Description:

OffsetEvent is used to define a time relative to an event. A positive number value indicates a time after the specified event. A negative number value indicates a time before the specified event. The number value is the offset time, and is in units defined by setTime.

Example:

(offsetEvent
   (event
      (portRef CK)
      (transition H L))
   (e -48 -1))

This example defines a time 4.8 units before a transition from H to L on port CK.

See also:

event forbiddenEvent

openShape

openShape ::= '(' 'openShape'
	curve
	')'

Used by:

figure geometryMacro

Description:

OpenShape is similar to path except that it may include arcs. OpenShape is open by definition, and therefore not filled.

Example:

(openShape
   (curve
      (arc (pt 0 4) (numberPoint 1 2) (pt 0 0))))
(shape
   (curve
      (arc (pt 1 4) (numberPoint 4 3) (pt 5 2))
      (arc (pt 5 2) (numberPoint 4 1) (pt 1 0))
      (arc (pt 1 0) (numberPoint 2 2) (pt 1 4))))

This example uses openShape as part of the graphics for a typical xor symbol, as shown in the figure below.

The shape would be filled according to the fillPattern and fillPatternVisible described for the figureGroup referenced by the figure containing the shape. 

(openShape
   (curve
      (arc (pt 0 4) (numberPoint 1 2) (pt 0 0))))
(openShape
   (curve
      (arc (pt 1 4) (numberPoint 4 3) (pt 5 2))
      (arc (pt 5 2) (numberPoint 4 1) (pt 1 0))
      (arc (pt 1 0) (numberPoint 2 2) (pt 1 4))))

This example uses openShape describing all the graphics for a typical xor symbol. In this case, the main body of the symbol would not be filled, as shown in the figure below.

See also:

arc path shape

origin

origin ::= '(' 'origin'
	pointValue
	')'

Used by:

transform

Description:

Origin is used to specify the translation point of an object when it is transformed. Translation of an object is always the last operation performed when transforming an object.

The pointValue identifies the location with respect to the enclosing context which corresponds to the point with zero coordinates in an instantiated object, or the point indicated by the justification in a textual display.

Example:

(schematicInstanceImplementation &123 
   (instanceRef NAND1)
   (schematicSymbolRef SYMBOL)
   (transform (origin (pt 100 0))))

The first example specifies that the symbol is placed so that its origin lies at point (100, 0). 

(annotate "U12"
   (display 
      (figureGroupOverride text 
         (displayAttributes 
            (verticalJustification (bottomJustify))
            (horizontalJustification (leftJustify))))
      (transform (rotation 270)
         (origin (pt 4 6)))))

The second example specifies that the string "U12" is to be displayed such that the lower left of the text (below and left of the "U"), is at point (4, 6).

See also:

horizontalJustification rotation verticalJustification

originalBoundingBox

originalBoundingBox ::= '(' 'originalBoundingBox'
	rectangle
	')'

Used by:

commentGraphics geometryMacroHeader pageHeader schematicSymbolHeader schematicTemplateHeader

Description:

OriginalBoundingBox is the bounding box defined in the original (source) system which can contain all of the graphical information specified in the same context. There are no semantic rules associated with originalBoundingBox because its definition will depend on the source system. It may be used by a reader as a guide only.

Example:

(commentGraphics
   (originalBoundingBox 
      (rectangle (pt 38 65) (pt 110 250)))
   (figure Green
      (rectangle (pt 100 65) (pt 110 120)))
   (figure Orange
      (dot (pt 38 250))))

This example shows the use of a originalBoundingBox within a commentGraphics that uses two figures. This is illustrated in the figure below.

See also:

originalName

originalName ::= stringToken

Used by:

nameAlias primaryName

Description:

The stringToken specifies the basic name of an object in the source system.

OriginalName is not scoped within EDIF, so it is legal for several objects within the same EDIF name space and name scope to have identical original names. This could be the case if they were all generated from one object in the originating system.

Example:

(signal S1 (signalJoined ...)
   (nameInformation 
      (primaryName "BusA0"
         (displayName "BusA"))))

In this example, the originalName for the signal is "BusA0".

otherwiseFrame

otherwiseFrame ::= '(' 'otherwiseFrame'
	frameNameDef
	ifFrameSet
	logicalConnectivity
	{ comment | documentation | <nameInformation> | property | userData } 
	')'

Used by:

logicalConnectivity

Description:

This defines an otherwiseFrame. The contents of the otherwiseFrame are included during a hierarchy expansion only if none of the frames specified in ifFrameSet can be included, i.e. if none of the conditions within the if frames referenced by ifFrameSet evaluate to true.

Example:

(otherwiseFrame defaultFrame
   (ifFrameSet (ifFrameRef F1) (ifFrameRef F2))
   (logicalConnectivity ...))

Here, the frame called defaultFrame is included in the hierarchy expansion if neither F1 nor F2 can be included due to a condition not being satisfied.

See also:

connectivityFrameStructure forFrame ifFrame otherwiseFrameAnnotate schematicOtherwiseFrameImplementation

page

page ::= '(' 'page'
	pageNameDef
	pageHeader
	{ cellPropertyDisplay | clusterPropertyDisplay | comment | localPortGroup 
	| pageCommentGraphics | pageTitleBlock | propertyDisplay | schematicBus | 
	schematicForFrameImplementation | schematicGlobalPortImplementation | 
	schematicIfFrameImplementation | schematicInstanceImplementation | 
	schematicMasterPortImplementation | schematicNet | 
	schematicOffPageConnectorImplementation | 
	schematicOnPageConnectorImplementation | 
	schematicOtherwiseFrameImplementation | schematicRipperImplementation | 
	userData | viewPropertyDisplay } 
	')'

Used by:

schematicImplementation

Description:

Page is used for implementing the pages of a schematic design. Page contains much of the same information found in the implementation section of other views of a cell.

In the schematic view, all schematics sheets are represented as page. If a system does not support multiple page designs, only one page will exist per schematic view.

Each page establishes a local coordinate space.

Example:

(cell BIG ...
   (cluster C1
      (interface ...) ...
      (schematicView V1  
         (schematicViewHeader ...)
         (logicalConnectivity 
            (instance I1 ...)
            (instance I2 ...)
            (instance I3 ...)
            (instance I4 ...)
            (signal SIG1..) ...)
         (schematicImplementation 
            (page &1 (pageHeader ...)
               (schematicInstanceImplementation I1 ...)
               (schematicInstanceImplementation I2 ...)
               (schematicNet N1 (signalRef SIG1)..)
               (schematicNet N2 ...)
            ...)
            (page &2 (pageHeader ...)
               (schematicInstanceImplementation I3 ...)
               (schematicInstanceImplementation I4 ...)
               (schematicNet N1 (signalRef SIG1)..)
               (schematicNet N3 ...)
            ...)
         ...))))

In the above example, the view named V1 of cell BIG is implemented with two schematic pages named 1 and 2. The instances are defined in the logicalConnectivity section and implemented within page, with only one implementation allowed per instance. Three schematicNets named N1, N2 and N3 are defined and implemented within pages 1 and 2.

Notice that there is a schematicNet N1 is defined in both pages, but they are distinct nets which are, in this case, associated with the same signal and will therefore be electrically common.

See also:

totalPages
