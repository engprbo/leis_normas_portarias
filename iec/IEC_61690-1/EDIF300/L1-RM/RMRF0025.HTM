transform

transform ::= '(' 'transform'
	{ <origin> | <rotation> | <scaleX> | <scaleY> } 
	')'

Used by:

complexGeometry display pageBorder pageTitleBlock schematicComplexFigure schematicForFrameBorder schematicGlobalPortImplementation schematicIfFrameBorder schematicInstanceImplementation schematicInterconnectTerminatorImplementation schematicJunctionImplementation schematicMasterPortImplementation schematicOffPageConnectorImplementation schematicOnPageConnectorImplementation schematicOtherwiseFrameBorder schematicRipperImplementation schematicSymbolBorder schematicSymbolPortImplementation

Description:

Transform is used to locate an implementation of a symbol or other object that can be instantiated, and to specify the location and scaling of text.

ScaleX and scaleY are used to indicate scale factors. The default scaling is 1 for scaleX and scaleY. Negative values indicate mirroring.

Rotation is used to describe the rotation of the object, and rotation angle is measured in units defined by setAngle. The default rotation is zero radians.

Origin is used to describe the translation point of an instance. The default origin is (pt 0 0).

Each operation within transform is applied in the following order: scaleX, scaleY, rotation and finally translation (origin). This order is not affected by the ordering within transform.

Example:

(instance INST_1
   (clusterRef CL1 (cellRef CELL1)))
...
(schematicInstanceImplementation IMPL_1 
   (instanceRef INST_1)
   (schematicSymbolRef SYM1)
   (transform
      (scaleX 2 1)
      (scaleY 3 1)
      (rotation 90)
      (origin (pt 10 70))))

In the above example, the instance is scaled by 2 in the x direction and by 3 in the y direction. The instance is then rotated 90 degrees and placed at (10,70).

A typical point such as (100, 500) in SYM1 would map to (-1490, 270).

transition

transition ::= '(' 'transition'
	previousLogicValue
	presentLogicValue
	')'

Used by:

event interconnectDelay portDelay portDelayOverride portLoadDelay portLoadDelayOverride

Description:

Transition is used to describe a logic state transition from the previous logic value to the present value.

LogicList is used in conjunction with lists or port bundles. When used, the size of the logic list must match the size of the port list.

In the case of a transition which contains a logicList, the transition occurs as soon as the following conditions are met. At some previous time each associated port had a logic value equal to the corresponding value of the first logicList; each port has a logic value equal to the corresponding value of the second logicList; each individual port has had no more than one logic transition between these times.

LogicOneOf is used to provide a choice of logic values or logic lists. Any match in the logicOneOf is considered a match for the transition statement.

Example:

(transition L H)

The first example specifies the transition from the logic value L to the logic value H. 

(transition Z (logicOneOf H L))

The second example specifies the transition from the logic value Z to the logic value H or the transition from the logic value Z to the logic value L.

See also:

becomes logicList logicOneOf pathDelay

unit

unit ::= '(' 'unit'
	unitNameDef
	numberOfNewUnits
	numberOfBasicUnits
	{ <ampere> | <candela> | <celsius> | <coulomb> | <degree> | 
	<fahrenheit> | <farad> | <henry> | <hertz> | <joule> | <kelvin> | 
	<kilogram> | <meter> | <mole> | <ohm> | <radian> | <second> | 
	<siemens> | <volt> | <watt> | <weber> } 
	')'

Used by:

unitDefinitions

Description:

Unit allows units of measurement to be defined. These are used to define units of distance, angle, etc. in the EDIF data, and they may also be referenced from properties to indicate the unit of measurement for a property.

Most of the units that are used to define new units are SI units. However, other units have been introduced where they are in common usage and derivation in terms of SI units is difficult or inaccurate. Examples of these are fahrenheit and degree.

Example:

(unit mm 1 (e 1 -3) (meter 1))

This example shows the definition of millimeter (mm). It indicates that the unit is meter, and that 1 mm is equivalent to 10-3 meters. 

(unit pF 1 (e 1 -12) (farad 1))

This example shows the definition of pico farad (pF). It indicates that the unit is farad, and that 1 pF is equivalent to 10-12 farads. 

(unit pound_foot 1 (e 1383 -4) (kilogram 1) (meter 1))

This example shows the definition of pound foot (pound_foot). It indicates that the unit is kg m, and that 1 pound_foot is equivalent to 0.1383 kg m. 

(unit knot 1 (e 5148 -4) (meter 1) (second -1))

This example shows the definition of knot. It indicates that the unit is m/s, and that 1 knot is equivalent to 0.5148 m/s. 

(unit rpm 60 1 (hertz 1))
(unit rpm_approx 1 (e 1047 -4) (radian 1) (second -1))

This example shows the definition of revolutions per minute (rpm). It indicates that the unit is hertz, and that 60 rpm is equivalent to 1 Hz. The second example shows a less-accurate definition in terms of radians per second.

unused

unused ::= '(' 'unused'
	')'

Used by:

instancePortAttributes port

Description:

Unused is an attribute of ports and port instances. When unused is embedded in a port in the interface of a cluster, it indicates that this particular port is not being used internally by the views within the cluster, and hence a view in which it is instantiated may use it for any purpose without influencing the operation of the cell in any way.

When used in the instancePortAttributes in an instance in a view, it indicates that the port of an instantiated view will not be used by the instantiating view. That is, it is not connected to any signal in that view.

DefaultConnection and unused are not allowed as attributes of the same master port.

Unused is allowed to be an attribute of an instance port whose master port definition has a defaultConnection attribute. In this context, unused means that there is not an explicit connection between a local signal and the instance port, but it does not override the meaning of a defaultConnection attribute, since defaultConnection applies to global connectivity and the unused attribute applies to local connectivity. Thus, unused on an instance port whose master port has a defaultConnection attribute means that the user purposely did not make an explicit connection to the instance port and that the default connection should apply. Unused on an instance port whose master port does not have a defaultConnection attribute means that the user purposely did not make an explicit connection to the instance port.

Example:

(interface (interfaceUnits)
   (port A (unspecifiedDirectionPort) (unused))  ...)

In the first example, the port named A is not used for internal connections and so is available for use by the external environment. 

(logicalConnectivity
   (instance AND2_3
      (clusterRef  ...)
      (instancePortAttributes B 
         (unused))))

Within the instance this indicates that port B of the cluster referred to by clusterRef in this instance is not used for connectivity of the local view.

See also:

interface interfaceJoined connectivityNet

usableArea

usableArea ::= '(' 'usableArea'
	{ rectangle } 
	')'

Used by:

pageBorderTemplate schematicForFrameBorderTemplate schematicIfFrameBorderTemplate schematicOtherwiseFrameBorderTemplate schematicSymbolBorderTemplate

Description:

UsableArea provides a definition of the area in which graphics may be placed. It excludes the areas used for title blocks. The area that can be used is the union of all the rectangles. This may produce a number of disjoint areas.

Example:

(usableArea (rectangle (pt 10 10) (pt 990 990)))

In this example, the usable area is defined as a single rectangle. 

(usableArea 
   (rectangle (pt 10 100) (pt 990 990))
   (rectangle (pt 100 10) (pt 990 100)))

In this example, the usable area is defined as two adjacent rectangles, leaving a small area in the bottom left corner that is not to be used. This is typically reserved for the title block.

version

version ::= '(' 'version'
	stringValue
	')'

Used by:

dataOrigin program

Description:

Version is used to provide a revision code (defined by the EDIF writer) which can be used to keep track of the origin and creator of the written EDIF data. If problems occur in this transfer, the version information may be used to help analyze them. Any interpretation of the revision code must be external to the EDIF data.

Example:

(dataOrigin "EDIFCo, Atlantic Division"
   (version "D10-37"))
(program "NetLister"
   (version "3.72"))

In the above example, version strings are specified for the data from which the EDIF information was created and for the program which created the EDIF data. The format for the version strings was determined by the writer.

See also:

status written
