Appendix C

Mapping between syntax and information model

 

At present, the purpose of the EDIF Information Model is to describe the design information carried by an EDIF file. Future work needs to be done to formalise the mappings between the EDIF Information Model and the EDIF syntax. The mapping can be carried out in both directions. It should be possible to map the Information Model to the syntax and vice versa. This chapter outlines how to use EXPRESS to define a formal mapping model.

In figure C.1, the information_model schema represents an abstract model of the domain and the syntax_model schema represents a concrete implementation of the abstract model. For example, entity integer_point in the information_model schema describes a point whose coordinates are specified in integer_distance_value; entity pt in the syntax_model is its corresponding implementation.

 


  schema information_model;
    entity integer_point;
      x_coordinate, y_coordinate : integer_distance_value;
    end_entity;
  end_schema;

  schema syntax_model;
      reference from information_model 
        (integer_point, integer_distance_value AS integerValue);

    entity pt;
      xCoordinate, yCoordinate : integerValue;
    end_entity;

    function map_integer_point_to_pt 
      (abstract_form : integer_point) : pt;
      return( pt(abstract_form.x_coordinate, 
                 abstract_form.y_coordinate) );
    end_function;

    function map_pt_to_integer_point 
      (concrete_form : pt) : integer_point;
      return( integer_point(concrete_form.xCoordinate, 
                            concrete_form.yCoordinate) );
    end_function;
  end_schema;
Figure C.1:   An example of formalising mapping between information model and syntax

Objects defined in the abstract model may be mapped onto one or more objects defined in the concrete model and vice versa. The mappings between objects defined in the information_model and objects defined in the syntax_model are also formalised in the syntax_model schema. The mapping from entity integer_point to entity pt is defined in function map_integer_point_to_pt. On the other hand, the mapping from entity pt to entity integer_point is defined in function map_pt_to_integer_point.

In the above example, the mapping between the abstract object and the concrete object is straightforward. However, this is not always the case. For example, the transform construct in the EDIF syntax may contain an origin construct. If the origin construct is missing, the transform construct would have a default value for the origin, which is (pt 0 0). The mechanism used to provide a default value for a construct is not within the scope of an abstract information model. This should be modelled separately in the mapping function between the abstract object and the concrete object.

In figure C.2, there is a simplified model of the transform concept. In the information_model, the origin attribute of entity abstract_transform is a required attribute. Hence every occurrence of abstract_transform must have a value of that attribute. However, in the syntax_model, the origin attribute of entity concrete_transform is optional. Therefore not every occurrence of concrete_transform would have a value of that attribute. To formalise the mapping from entity concrete_transform to entity abstract_transform, it is necessary to provide a default value of the origin attribute for each occurrence of abstract_transform, if its corresponding concrete_transform does not specify the value of the origin. The mapping from entity concrete_transform to entity abstract_transform is defined in the function map_concrete_transform_to_abstract_transform. This function checks that if an occurrence of concrete_transform specifies the value of its origin, the origin of the corresponding abstract_transform would take the same value. Otherwise, the origin of the abstract_transform would take the value of the default_origin, which is integer_point(0,0).

 


  schema information_model;
    entity abstract_transform;
      origin          : integer_point;
    end_entity;
  end_schema;

  schema syntax_model;
      reference from information_model;
    constant
      default_origin   : integer_point := integer_point(0,0);
    end_constant;

    entity concrete_transform;
      origin          : optional pt;
    end_entity;

    function map_concrete_transform_to_abstract_transform
      (concrete_form : concrete_transform) : abstract_transform;
      local
        abstract_form : abstract_transform;
      end_local;
      if exists(concrete_form.origin) then
         abstract_form.origin.x_coordinate 
           := concrete_form.origin.xCoordinate;
         abstract_form.origin.y_coordinate 
           := concrete_form.origin.yCoordinate;
      else
         abstract_form.origin := default_origin;
      end_if
    end_function;
  end_schema;
