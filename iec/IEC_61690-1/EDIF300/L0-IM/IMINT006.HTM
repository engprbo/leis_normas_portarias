Chapter 6

Design annotation

 

This chapter describes the concepts of annotation of a design hierarchy. The model for annotation can be found in the design_hierarchy_model .

6.1 Problem statement

In EDIF Version 2 0 0, the viewMap construct is used within a cell for two purposes. Firstly, it allows mappings between objects of the same type in different views of a cell. Secondly, it is used to attach back-annotation information to objects (i.e. ports, nets and instances) defined within a view.

However, it is inappropriate to attach annotation information to a view because annotation addresses objects in an expanded design hierarchy. As a result, there is a need to allow annotation information to be specified within the context of a design hierarchy.

6.2 Solution

In chapter 5, the concepts of design_hierarchy, cluster_configuration and instance_configuration are described. A design_hierarchy points to a cluster_configuration which can be either an expandable_cluster_configuration or a leaf_configuration. An expandable_cluster_configuration selects the top view to expand the hierarchy and then for some instances defined within that chosen view, instance_configurations may be specified which in turn select other cluster_configurations for the further expansion of the hierarchy. However, if a design_hierarchy points to a leaf_configuration, it means that there is no further expansion of the hierarchy.

In EDIF Version 3 0 0, annotation information is added to design hierarchies. The top level occurrence of a design_hierarchy is annotated by an occurrence_hierarchy_annotate . Master ports, interconnects and signals defined within the top view may be annotated. A master_port_annotate is used to attach or modify attributes and properties which are associated with a master_port occurrence in the top level occurrence. An interconnect_annotate is used to associate physical characteristics with an interconnect structure within an occurrence hierarchy. A signal_annotate is used to attach or modify properties which are associated with a signal occurrence within an occurrence hierarchy.

If further annotation is to be given for occurrences further down in the design_hierarchy, it is necessary to specify an occurrence_annotate which selects an occurrence to be annotated next. An occurrence_annotate is used to annotate occurrences at any level of the design_hierarchy, apart from the top level and the leaf level occurrences. It selects the annotated occurrence by referencing an instance_configuration which specifies the annotated instance and the chosen view for that annotated instance. Similarly, interconnects and signals defined within the chosen view may be annotated by interconnect_annotates and signal_annotates respectively. Instance ports on the annotated instance may be annotated by instance_port_annotates. An instance_port_annotate is used to attach or modify properties and attributes which are associated with an instance_port occurrence within an occurrence hierarchy.

Finally, any leaf level occurrence of a design_hierarchy is annotated by the leaf_occurrence_annotate. A leaf level occurrence is selected by referencing an instance_configuration which points to a leaf_configuration. Instance ports on the annotated instance may be annotated by the instance_port_annotates.
