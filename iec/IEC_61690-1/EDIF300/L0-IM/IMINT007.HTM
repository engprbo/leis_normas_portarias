Chapter 7

Names

This chapter describes the concept of names associated with design objects. The model for name_information can be found in the support_definition_model schema.

7.1 Problem statement

In EDIF Version 2 0 0, all objects can be named in one of two ways, either by specifying an EDIF identifier, or by specifying an EDIF identifier plus a rename string.

The EDIF identifier is defined to be case insensitive and uses a restricted subset of the ASCII character set. These names have a well defined scope and name class in EDIF Version 2 0 0. All references to objects in EDIF Version 2 0 0 are specified using this name. There are no rules which state how to relate this name to names in the source system.

The rename string is case sensitive and uses the full ASCII character set. There are no well defined rules in EDIF Version 2 0 0 for this name. This name has no specified scope and the relationship this name has with respect to names specified in the source system is not defined. It is also not clear what the relationship is between the rename string and the EDIF identifier. The only statement made in EDIF Version 2 0 0 about the rename string is that it is recommended that the EDIF reader should try to use it, if it exists, in the target system.

The lack of rules and other attributes regarding names in EDIF Version 2 0 0 means that it can be difficult to use EDIF Version 2 0 0 to retain necessary object naming information as a design is translated.

7.2 Solution

In EDIF Version 3 0 0, the naming characteristics of an object are captured. The name_information of an object provides a primary name_set which should be used to name the object in the target system if possible. The name_set consists of different types of name defined as follows.

  • original_name

    This is the name of an object, exactly as it is specified in the source system. An original_name may be machine generated, rather than created by a human. If a name is machine generated, it can be changed with no effect on the human users of this object, except for backannotation purposes.

    Many systems use special characters and sub-strings embedded within an object name to indicate information about the object, e.g. logical complement, boolean relationships, dimensionality, bit ranges or indices. A name_structure is used to specify in detail the structural parts of a name without the use of special characters. It should be used if the sending system uses the name structure to specify the structure of the design object.

  • display_name

    This is the name which will get displayed for an object.

In addition, the name_information may give aliases which are considered to be secondary names of the object.
