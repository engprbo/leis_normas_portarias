support_definition_model

Description:

The support_definition_model schema contains general information which applies to other schemas. Typical examples are the entities name_information and unit which are not confined to individual schemas. In addition, it holds definitions of some generic functions whose sole purpose is to clarify and improve understanding of constraints written in EXPRESS.

non_negative_capacitance

  FUNCTION non_negative_capacitance
    (load : minomax_value) : BOOLEAN;
     RETURN((('NOT_FIXED' IN TYPEOF(load.min)) OR (load.min >= 0)) AND
            (('NOT_FIXED' IN TYPEOF(load.nom)) OR (load.nom >= 0)) AND
            (('NOT_FIXED' IN TYPEOF(load.max)) OR (load.max >= 0)));
  END_FUNCTION;

Description:

The non_negative_capacitance function checks every instance of capacitance_value. If the numeric value exists (i.e. min, nom or max), then it must be greater than or equal to zero. This function is used to ensure that the load capacitance of a port must not be negative.

valid_range

  FUNCTION valid_range
    (num1, num2, num3 : number_or_not_fixed) : BOOLEAN;

  (*
  ** The "not_greater_than" function (a) checks that both parameters (N1 and N2)
  ** have numeric values, and (b) returns true if the value of N1 is less than or
  ** equal to the value of N2 . If either N1, N2 or both have missing numeric
  ** values, then it always returns true.
  *)
    FUNCTION not_greater_than
      (N1, N2 : number_or_not_fixed) : BOOLEAN;
      IF ('NUMBER' IN TYPEOF(N1)) AND ('NUMBER' IN TYPEOF(N2)) THEN
         RETURN(N1 <= N2);
      ELSE
         RETURN(TRUE);
      END_IF;
    END_FUNCTION;
    RETURN(not_greater_than(num1, num2) AND
           not_greater_than(num2, num3) AND
           not_greater_than(num1, num3));
  END_FUNCTION;

Description:

The valid_range function checks that, if any one of the parameters (i.e. num1, num2 or num3) has a numeric value, then they must be in non-decreasing order.

valid_unit_type

  FUNCTION valid_unit_type 
    (chosen_unit : unit; chosen_type : physical_unit) : BOOLEAN;
    RETURN((SIZEOF(chosen_unit.physical_type) = 1) AND
           (chosen_unit.physical_type[1].basic_unit = chosen_type) AND
           (chosen_unit.physical_type[1].exponent = 1));
  END_FUNCTION;

Description:

The valid_unit_type function returns true if the physical type of the chosen unit is same as the chosen type.

name_string

  TYPE name_string                                                               
    = string_token;                                                              
  END_TYPE;

Description:

A name_string is a string_token that is devoid of any special characters or formats that are used to specify things such as structure, dimensioning and complementing in the original_name of an object. Such special characters are defined in the system where the object was created and may not be used in a name_string. For example, an array object name "A[0:3]" contains the special characters '[', ']', ':' and the integers 0 and 3 which are part of a range format, thus only the string A may be a name_string.

integer_sequence

  ENTITY integer_sequence;
    from_value : integer_token;
    to_value   : integer_token;
    step       : integer_token;
  WHERE
    valid_step :
      (* The step value must not be equal to zero. *)
      step <> 0;

    valid_sequence :
      (* The from_value, the to_value and the step must satisfy the condition
         that the to_value = from_value + k * abs(step), for some integer k. *)
          (((to_value - from_value) MOD ABS(step)) = 0);
  END_ENTITY;

Description:

An integer_sequence specifies a list of integer values. The first index value is given by the from_value attribute and the last index value is given by the to_value attribute. The step attribute indicates the step between each index, which may be not zero.
