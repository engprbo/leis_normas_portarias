NAME DEFINITIONS AND REFERENCES

INTRODUCTION

This section gives details of the name definitions and references.

First, name definitions (XXnameDef, where XX varies according to the type of object being defined) and scoping constructs are detailed together with a list of where they may occur. This is a hierarchical reference from the XXnameDef up through enclosing forms to a higher named form, i.e. form which has a nameDef or extendXXDef.

In this list, the note "(n lines missing)" means that the list of possible positions has been defined previously and so is not repeated.

The scope of a name is the enclosing named form. This list of name definitions may be used to find where each named item may be defined.

Following this, the name references (XXnameRef) are given together with a list of where they may occur, in a similar format. This list of references may be used to determine the context in which name references may occur and this is useful, for example, in writing code to follow a reference back to its definition.

The list is an exhaustive list of where these items may occur, and it includes all syntactically possible situations. However, some of these may be semantically illegal. The following diagram shows all the major name classes and their relative scoping. It does not show intervening structures such as libraryHeader or interface as these are syntactic wrappers and do not affect the name structure. A '*' indicates where a recursive nesting is permitted, such as interconnect names in the context of an interconnect. The nameDef suffix is omitted for brevity.

Note: For Level 1, Name References for constantNameRef, parameterNameRef and indexNameRef are not shown: there are too many occurrences of these to be included.
