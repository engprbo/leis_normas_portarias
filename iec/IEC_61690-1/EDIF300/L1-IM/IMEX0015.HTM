logical_connectivity_model

Description:

The logical_connectivity_model schema describes what logical connectivity information can be found in an EDIF view. The logical connectivity of a view may include signals and signal_groups. A signal is defined as a named object which lists all the ports which are electrically common at a given level of hierarchy. A signal_group provides a grouping mechanism for signals. It does not modify connectivity.

signal

  ENTITY signal
      ABSTRACT SUPERTYPE OF (ONEOF(mergeable_signal,
                                   non_mergeable_signal));
    joined_global_ports                 : OPTIONAL SET [1:?] OF -- reference
                                          global_port;
    joined_instance_member_port_members : OPTIONAL SET [1:?] OF
                                          instance_member_port_member;
    joined_instance_ports               : OPTIONAL SET [1:?] OF -- reference
                                          instance_port; 
    joined_master_ports                 : OPTIONAL SET [1:?] OF -- reference
                                          master_port;
    joined_master_port_members          : OPTIONAL SET [1:?] OF
                                          master_port_member;
    instance_port_expressions           : OPTIONAL SET [1:?] OF 
                                          instance_port_expression; 
    name                                : OPTIONAL name_information;  
    properties                          : OPTIONAL SET [1:?] OF property;
    width                               : integer_expression;
  DERIVE
    containing_cluster : cluster                                -- reference
                         := containing_view.containing_cluster;
    containing_edif    : edif                                   -- reference
      := containing_cluster.containing_cell.containing_library.containing_edif;
    containing_view    : cell_representation                    -- reference
      := usedin_any_one_role(SELF,
         ['connectivity_view_model.internal_connectivity_view.signals', 
          'schematic_view_model.internal_schematic_view.signals']);
  WHERE
    containment_constraint :
      (* A signal belongs to either one internal_connectivity_view or one
         internal_schematic_view. *) 
      either_belongs_to_one(SELF, 
       ['connectivity_view_model.internal_connectivity_view.signals',
        'schematic_view_model.internal_schematic_view.signals']);

    valid_joined_global_ports :
      (* All joined global_ports are defined in the containing edif of the
         signal. *) 
      joined_global_ports <= containing_edif.global_ports;

    valid_joined_instance_member_port_members :
      (* All joined instance_member_port_members refer to the instances in the
         containing view of the signal.  *)
      not_exists(QUERY(port <* joined_instance_member_port_members |
        NOT (port.referenced_instance IN containing_view.instances)));

    valid_joined_instance_ports :
      (* All joined instance_ports refer to the instances in the containing view
         of the signal.  No joined instance_port is unused externally. *)
      not_exists(QUERY(port <* joined_instance_ports |
        NOT (port.referenced_instance IN containing_view.instances)));

    valid_joined_master_ports :
      (* All joined master_ports are defined in the interface of the cluster
         containing the signal.  No joined master_port is unused internally. *)
      (joined_master_ports <= containing_cluster.interface.ports)
        AND
      not_exists(QUERY(port <* joined_master_ports | port.unused_internally));

    valid_joined_master_port_members :
      (* All joined master_port_members refer to the master_ports defined in
         the interface of the cluster containing the signal.  No joined
         master_port_member is unused internally. *)
      not_exists(QUERY(port <* joined_master_port_members |
        NOT (port.referenced_master_port 
             IN containing_cluster.interface.ports)));

    valid_joined_wide_instance_ports :
      (* The same instance_member_port_member cannot be referenced more than
         once within a signal.  Therefore if a wide instance_port has been
         referenced, it is illegal to reference members of that wide
         instance_port. *)
      not_exists(QUERY(joinedWidePort <* joined_instance_ports |
        there_exists(QUERY(joinedMemberPort 
                           <* joined_instance_member_port_members |
          joinedWidePort :=: joinedMemberPort.referenced_instance_port))));

    valid_joined_wide_master_ports :
      (* The same master_port_member cannot be referenced more than once within
         a signal.  Therefore if a wide master_port has been referenced, it is
         illegal to reference members of that wide master_port. *)
      not_exists(QUERY(joinedWidePort <* joined_master_ports |
        there_exists(QUERY(joinedMemberPort <* joined_master_port_members |
          joinedWidePort :=: joinedMemberPort.referenced_master_port))));

    valid_width :
      (* The width expression may reference the parameters defined in the
         interface of the containing_view. *) 
      not_defined;
  END_ENTITY;

Description:

A signal is defined as a named object which lists all the global_ports, instance_ports, instance_member_port_members, master_ports and master_port_members which are electrically common at a given level of hierarchy. Its width is determined by an integer_expression.

There is no constraint to force distinct instance_ports to be part of the same signal, even when their corresponding master_ports are defined in the same cluster_interface and are shorted together. Hence, on an instance of a cluster containing master_ports which are interface joined, it is legal for connections to be made to the corresponding instance_ports by either a single signal or by distinct signals.

After design expansion, if the width of a signal is greater than 1, then all joined master_ports must have the same width as the signal. Each member of the expanded signal is connected to the corresponding member of the expanded master_port. On the other hand, if a signal joins to an instance_port or an instance_port_bundle, the connectivity may be determined by the connected_signal_index_generator specified on the instance_port_expressions. In the case where the connected_signal_index_generator is not present on an instance_port or an instance_port_bundle, the pattern of connectivity is limited in the following two cases.

If the signal width equals the port width, each member of the signal is connected to the corresponding member port of all the member instances in parallel.

If the signal width equals the product of the instance width and the port width X, then the first X members of the signal connect to the port on the 0th member of the instance, the next X members connect to the corresponding port on the 1st member of the instance, and so on.

mergeable_signal

  ENTITY mergeable_signal
      SUBTYPE OF (signal);
    connectivity_tag_generator : string_expression;
  UNIQUE
    unique_connectivity_tag_generator :
      (* All mergeable_signals defined in the same containing_view must have
         unique connectivity_tag_generator. *)
      connectivity_tag_generator, SELF\signal.containing_view;
  WHERE
    valid_connectivity_tag_generator :
      (* The connectivity_tag_generator expression may reference the
         signal_index of the mergeable_signal or the parameters defined in the
         cluster_interface of the containing view. *)
      not_defined;
  END_ENTITY;

Description:

 LEVEL 1
 =======
A mergeable_signal is a signal which can be merged with other mergeable_signals. It has a connectivity_tag_generator which is vital for the merging process in the expansion of a design. After the expansion, the connectivity_tag_generator expression will be evaluated to a tag and all mergeable_signals with the same tag are merged together. Within a view, all mergeable_signals must have unique connectivity_tag_generator. The connectivity_tag_generator expression may reference the index of the mergeable_signal or any parameter defined in the cluster_interface of the containing view.

non_mergeable_signal

  ENTITY non_mergeable_signal
      SUBTYPE OF (signal);
  END_ENTITY;

Description:

 LEVEL 1
 =======
A non_mergeable_signal is a signal which is not subject to merging.

instance_port_expression

  ENTITY instance_port_expression;
    connected_wide_port              : instance_port; -- reference
    connected_signal_index_generator : integer_expression;
  UNIQUE
    uniqueness_constraint :
      (* An instance_port is allowed to be associated with at most one
         instance_port_expression. *) 
      connected_wide_port;
  WHERE
    containment_constraint :
      (* An instance_port_expression belongs to one signal. *)
      belongs_to_one(SELF,
        'logical_connectivity_model.signal.joined_instance_port_expressions');

    valid_connected_signal_index_generator :
      (* The connected_signal_index_generator expression may reference the
         port_index of the referenced master_port, the instance_index of the
         referenced instance or the parameters defined in the containing
         cluster_interface. *) 
      not_defined;
  END_ENTITY;

Description:

 LEVEL 1
 =======
An instance_port_expression defines how a wide port on an instance is to be connected to a wide signal. The connected_signal_index_generator specifies the connectivity between the individual bits of a wide port and the individual bits of a signal after the expansion.

signal_group

  ENTITY signal_group;
    members                     : LIST [1:?] OF                  -- reference
                                  signal_or_signal_group;
    name                        : OPTIONAL name_information;  
    properties                  : OPTIONAL SET [1:?] OF private_property;
  DERIVE
    containing_view : cell_representation                        -- reference
      := usedin_any_one_role(SELF, 
         ['connectivity_view_model.internal_connectivity_view.signal_groups',
          'schematic_view_model.internal_schematic_view.signal_groups']);
    flattened_signal_list : LIST [1:?] OF signal                 -- reference
                            := flatten_signal_group(members);
  UNIQUE
    unique_members :
      (* No two signal_groups have the same structure of members. *)
      members;
  WHERE
    containment_constraint :
      (* A signal_group belongs to either one internal_connectivity_view or one
         internal_schematic_view. *) 
      either_belongs_to_one(SELF, 
       ['connectivity_view_model.internal_connectivity_view.signal_groups',
        'schematic_view_model.internal_schematic_view.signal_groups']);

    valid_members :
      (* All member signals or signal_groups are defined in the containing view 
         of the signal_group. *)
      not_exists(QUERY(member <* members |
        member.containing_view :<>: containing_view));

    non_recursive_constraint :
      (* A signal_group cannot contain itself either directly or indirectly. *)
      not_recursive_signal_group([SELF], [SELF]);
  END_ENTITY;

Description:

A signal_group is defined as a named object which provides a grouping mechanism for signals. This provides a basis for the structured connectivity.

flatten_signal_group

  FUNCTION flatten_signal_group
    (signal_group_members : LIST OF signal_or_signal_group) : LIST OF signal;
    LOCAL
      i, j        : INTEGER;
      position    : INTEGER := 1;
      signal_list : LIST OF signal := [ ];
      member_list : LIST OF signal := [ ];
    END_LOCAL;

    REPEAT i := 1 TO SIZEOF(signal_group_members);
      IF 'logical_connectivity_model.signal' 
        IN TYPEOF(signal_group_members[i]) THEN
        INSERT(signal_list, signal_group_members[i], position);
        position := position + 1;
      ELSE
        member_list := flatten_signal_group(signal_group_members[i].members);
        REPEAT j := 1 TO SIZEOF(member_list);
          INSERT(signal_list, member_list[j], position);
          position := position + 1;
        END_REPEAT;
      END_IF;
    END_REPEAT;
    RETURN(signal_list);
  END_FUNCTION;

Description:

The flatten_signal_group function returns the flattened list of signals of a signal_group.

Used by:

not_recursive_signal_group

  FUNCTION not_recursive_signal_group 
    (parents, invalid_ancestors : SET OF signal_group) : BOOLEAN;
    LOCAL
      i, j        : INTEGER;
      descendants : SET OF signal_group := [ ];
    END_LOCAL;
    REPEAT i := 1 TO HIINDEX(parents);
      REPEAT j := 1 TO HIINDEX(parents[i].members);
        IF 'signal_group' IN TYPEOF(parents[i].members[j]) THEN
         descendants := descendants + parents[i].members[j];
        END_IF;
      END_REPEAT;
    END_REPEAT;
    RETURN
     (not_exists(descendants) OR
       (not_exists(descendants * invalid_ancestors) AND
         not_recursive_signal_group(descendants, parents + invalid_ancestors)));
  END_FUNCTION;

Description:

The not_recursive_signal_group function returns true if a signal_group does not contain members which reference itself. It prevents cyclic definition of a signal_group.

Used by:

signal_group
